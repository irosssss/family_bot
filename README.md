# 🏠 Family Chores RPG (Telegram Mini App 32-bit Edition)

**Семейный геймифицированный трекер домашних обязанностей, реализованный как полноценная 32-bit RPG игра с тремя игровыми сценами внутри Telegram Mini App.**

Мы полностью отказываемся от концепции скучных табличных дашбордов. Наше приложение выглядит и ощущается как ретро-игра, превращая рутинный быт в увлекательное совместное приключение.

---

## 1. 🏗️ Технологический Стек и Архитектура

Проект использует современный веб-стек для доставки игрового опыта прямо в мессенджере:

- **Frontend**: React 18, Vite, Tailwind CSS.
- **Рендеринг**: PixiJS (или чистый HTML5 Canvas / 32-bit CSS-layers) для отрисовки сцен и спрайтов.
- **Backend & API**: Node.js (Express), Socket.IO для real-time синхронизации.
- **База Данных**: PostgreSQL + Drizzle ORM.
- **Ассеты**: Хранение 32-bit графики (спрайт-шиты, иконки, тайлсеты от GandalfHardcore) в облачном S3-хранилище.
- **Интеграция**: `node-telegram-bot-api` для работы с экосистемой Telegram.

---

## 2. 🎮 Три Игровые Сцены (Single Source of Truth)

Приложение разделено на три ключевых экрана (сцены), между которыми происходит навигация.

### Сцена 1: Главный Хаб — «Семейный Дом» (Family Shared Hub)
- **Визуал:** Единая общая комната/дом в изометрии или виде сбоку (32-bit стиль). На сцене одновременно стоят анимированные спрайты персонажей всех членов семьи (Родители и Дети), а рядом с ними — их купленные питомцы (из архива `Pet companion.zip`).
- **Динамика прогресса:** Внешний вид дома меняется в зависимости от уровня семьи. Чем больше задач выполнено, тем чище и богаче выглядит комната (добавляется мебель из паков Cainos).
- **Интерактив:** Над головой персонажа ребенка появляется анимированный квестовый маркер `!` (из архива `Emojis and Icons.zip`), если родитель назначил ему новое домашнее дело. Клик по персонажу открывает баббл с его текущей задачей.

### Сцена 2: Боевая Арена — «Битва с Боссом» (Boss Raid Room)
- **Визуал:** Отдельная темная локация (данж). Слева стоят персонажи членов семьи в боевых позах, справа — анимированный Король Слизней (из архива `Slime Enemy.zip`) с большой полосой здоровья (HP).
- **Механика:** Каждое выполнение реального домашнего дела (например, «Уборка в комнате») конвертируется API в «Мощный удар» по боссу во фронтенде Mini App. Бот в Telegram присылает пуш: «Миша помыл посуду и нанес Слизню 150 ед. урона!». Здоровье босса общее на всю семью. При победе в конце недели — все получают золото.

### Сцена 3: Приватная Зона — «Гардероб и Кастомизация» (Character Customization & Inventory)
- **Визуал:** Персональная комната игрока с зеркалом. Крупный план персонажа по центру.
- **Интерфейс:** Вкладочное меню инвентаря (Оружие, Одежда, Шляпы, Питомцы).
- **Логика рендеринга (32-bit Layered System):** Динамическая сборка персонажа из S3-ассетов на основе Z-index слоев. Когда ребенок покупает в Лавке и надевает новую вещь (например, `female_clothing_12.png`), она аппаратно перекрывает базовое тело персонажа в правильном порядке.

## 3. ⚙️ Технические Требования для Разработки

1. **Маршрутизация (Scene Router):** 
   Переключение между тремя сценами должно происходить мгновенно через React State (или легковесный in-memory роутер) без перезагрузки страницы WebApp. Это критично для сохранения сессии Telegram и бесшовного игрового опыта (без `<a href>` или браузерных рефрешей).

2. **Оптимизация рендеринга (Sprite Sheets):** 
   Обязательно использовать технику Sprite Sheets (атласы анимаций) для 32-bit графики. Анимации `Idle` и `Walk` всех членов семьи на одном экране не должны нагружать процессор телефона. Рендер должен быть максимально оптимизирован для мобильных устройств.

3. **Синхронизация через API (Real-Time):** 
   При изменении состояния через бота (например, ребенок сдал квест -> родитель подтвердил) сцена «Семейный Дом» должна мгновенно обновиться по WebSocket/Polling. У ребенка должен пропасть маркер `!`, а его персонаж — проиграть анимацию радости/успеха без перезагрузки сцены.

## 4. 🗄️ Схема Базы Данных (PostgreSQL)

Вместо локального in-memory стейта используется полноценная реляционная база данных.

**Ключевые таблицы:**
- `users`: Пользователи (id, telegram_id, роль, класс, золото, опыт, здоровье, мана, кастомизация).
- `tasks`: Задачи (code, title, description, points, assignee, task_type).
- `families`: Семейные группы (family_code, name) для разделения пользователей.
- `items`, `pets`: Магазин и доступные питомцы.
- `character_inventory`, `character_pets`: Связь пользователей с купленными предметами и активированными питомцами.
