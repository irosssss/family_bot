# Family Chores RPG (Telegram Mini App 32-bit Edition)

**Семейный геймифицированный трекер домашних обязанностей, реализованный как полноценная 32-bit RPG игра с тремя игровыми сценами внутри Telegram Mini App.**

Мы полностью отказываемся от концепции скучных табличных дашбордов. Наше приложение выглядит и ощущается как ретро-игра, превращая рутинный быт в увлекательное совместное приключение.

---

## Ролевая модель семьи

Вместо жёстких демо-имён — гибкие роли:

- **Родители (папа/мама)** — администраторы семьи:
  - ставят задачи, управляют составом семьи, видят прогресс детей;
  - **не играют**: у родителей нет своих задач (генерация возвращает 0), нет золота и XP за выполнение, streak = paused;
  - родителям не генерируются детские задачи (и наоборот, дети не получают родительских).
- **Дети (сын/дочка)** — игроки без ограничений по количеству: выполняют задачи, копят золото, растят питомцев, бьют босса.

### Первый пользователь — родитель-админ
Первый зарегистрированный пользователь автоматически становится **родителем-админом** (`family_role: 'parent'`, `is_admin: true`). Все последующие — дети (`family_role: 'child'`).

### Настройка состава семьи
- Кнопка **«Семья»** в Navbar (видна **только родителям** — проверка `is_admin || family_role === 'parent'`).
- Модалка `FamilyManagementModal`: добавить ребёнка (имя, роль, возраст, класс), редактировать, удалить; настройки Telegram push и приложений.

### API управления пользователями (admin-guard)

Все операции требуют `actorId` в теле запроса — ID пользователя, выполняющего операцию. Если он не родитель/админ — ответ `403`.

| Метод | Endpoint | Описание |
|---|---|---|
| `POST` | `/api/users` | Добавить ребёнка (только админ) |
| `PUT` | `/api/users/:id` | Редактировать имя/возраст/пол (только админ) |
| `DELETE` | `/api/users/:id` | Удалить ребёнка (нельзя удалить родителя) |
| `GET` | `/api/users` | Все пользователи семьи |
| `POST` | `/api/users/register` | Регистрация (первый пользователь = родитель-админ) |

Пример запроса:
```json
POST /api/users
{
  "actorId": 1,
  "display_name": "Саша",
  "age": 8,
  "gender": "male"
}
```

## Быстрый старт (локально)

### Требования
- **Node.js** 18+ (npm)
- **PostgreSQL** 18 (локально или через Docker)
- **Telegram Bot Token** (от [@BotFather](https://t.me/BotFather))
- **ID семейного чата** (числовой, начинается с `-100`)

### Шаг 1: Настройка
```bash
# Клонировать репозиторий
cd family_bot

# Скопировать .env.example → .env и заполнить токены
cp .env.example .env
```

### Шаг 2: Запуск (автоматический)
```bash
# Windows
start.bat

# Linux / macOS / Git Bash
chmod +x start.sh && ./start.sh
```

Скрипт сам проверит PostgreSQL, применит миграции и запустит dev-сервер.

### Шаг 3: Запуск (вручную)
```bash
# 1. Убедиться, что PostgreSQL работает на 5432
# 2. Установить зависимости
npm ci

# 3. Применить миграции
npm run db:push

# 4. Запустить dev-сервер
npm run dev
```

Сервер будет доступен на **http://localhost:3000**.

### Шаг 4: Настроить Telegram Webhook
```bash
curl -X POST "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<ваш-домен>.up.railway.app/api/webhook/telegram"
```

## Технологический стек

- **Frontend**: React 18, Vite 6, Tailwind CSS 4, Motion (framer-motion), Recharts
- **Backend**: Node.js 20, Express, Socket.IO
- **Database**: PostgreSQL 18, Drizzle ORM + postgres.js
- **Telegram Bot**: node-telegram-bot-api (вебхуки, коллбэки, пуш-уведомления)

- **PWA**: Vite PWA plugin (автообновление, offline-кеширование ассетов)
- **Инфраструктура**: Docker Compose, Railway-ready
- **Design System**: `src/components/ui` — PixelButton, PixelCard, PixelBadge, PixelCoin (WCAG 2.1 AA)
- **Графика**: LPC / Kenney pixel-арт (CC0 / CC-BY-SA), canvas-рендер персонажей, иконки lucide-react (без эмодзи)

## Три игровые сцены

### Сцена 1: Главный Хаб — «Семейный Дом» (Family Shared Hub)
- **Визуал:** Единая общая комната/дом в изометрии или виде сбоку (32-bit стиль). На сцене одновременно стоят анимированные спрайты персонажей всех членов семьи (Родители и Дети), а рядом с ними — их купленные питомцы.
- **Динамика прогресса:** Внешний вид дома меняется в зависимости от уровня семьи. Чем больше задач выполнено, тем чище и богаче выглядит комната.
- **Интерактив:** Над головой персонажа ребенка появляется анимированный квестовый маркер `!`, если родитель назначил ему новое домашнее дело. Клик по персонажу открывает баббл с его текущей задачей.

### Сцена 2: Боевая Арена — «Битва с Боссом» (Boss Raid Room)
- **Визуал:** Отдельная темная локация (данж). Слева стоят персонажи членов семьи в боевых позах, справа — анимированный Король Слизней с большой полосой здоровья (HP).
- **Механика:** Каждое выполнение реального домашнего дела конвертируется API в «Мощный удар» по боссу. Бот в Telegram присылает пуш: «Миша помыл посуду и нанес Слизню 150 ед. урона!». Здоровье босса общее на всю семью. При победе в конце недели — все получают золото.

### Сцена 3: Приватная Зона — «Гардероб и Кастомизация» (Character Customization & Inventory)
- **Визуал:** Персональная комната игрока с зеркалом. Крупный план персонажа по центру.
- **Интерфейс:** Вкладочное меню инвентаря (Оружие, Одежда, Шляпы, Питомцы).
- **Логика рендеринга (32-bit Layered System):** Динамическая сборка персонажа из ассетов на основе Z-index слоёв. Когда ребенок покупает в Лавке и надевает новую вещь, она перекрывает базовое тело персонажа в правильном порядке.

## Игровые механики

### Ежедневные задачи (Streak)
- **Система серий:** Каждый день без пропуска обязательных задач увеличивает streak (серию).
- **Бонус:** **+5% к наградам за каждый день**, максимум **+50%** (10 дней). Milestones: **3 дня → +15%**, **7 дней → +35%**, **10 дней → +50%**.
- **Только обязательные:** Streak считается ТОЛЬКО по обязательным задачам (`personal` + `is_required`). Задачи «на выбор» (core) и квесты (quest) на streak не влияют.
- **Защита серии:** Раз в неделю можно использовать «заморозку» — пропустить день без потери streak.
- **Сброс:** Если пропустить день без заморозки — streak сбрасывается.
- **Родители не участвуют:** streak = paused, для детей.

### Задачи (Tasks)

**Три типа (core / personal / quest):**
- **ОБЯЗАТЕЛЬНЫЕ (required)** — красная секция: личные задачи с флагом `is_required`. Единственный тип, который влияет на streak.
- **НА ВЫБОР (choice)** — зелёная секция: `core` (классические ежедневные) + необязательные `personal`. Ребёнок выбирает, какие выполнять.
- **КВЕСТЫ (quests)** — золотая секция: длинные задания (60–100 очков), единственный источник кристаллов.

**Возрастные группы и лимиты задач в день:**

| Возраст | Макс. задач в день | Обязательных |
|---|---|---|
| 4–5 лет | до 3 (1 обяз + 1–2 на выбор) | 1 |
| 6–8 лет | до 5 (~40% обязательных) | 2 |
| 9–11 лет | до 7 | 2 |
| 12–13 лет | до 8 | 3 |

- **Детерминированная генерация:** список задач на день генерируется seeded-random'ом от `(дата + user_id)` (mulberry32) — при перезагрузке страницы список не меняется.
- **Награды:** база по типу (personal 15–25, core 20–30, quest 60–100) × возрастной множитель (0.7 / 1.0 / 1.3 / 1.6) × вариативность ×(0.8–1.2).
- **Сундук сюрпризов:** ~15% шанс бонуса (10–50 золота, редко кристалл).
- **Кристаллы:** только за квесты (3–5 за квест).
- **Создание:** родитель создаёт задачу через Telegram-бота или Mini App.
- **Одобрение:** ребёнок выполняет — родитель одобряет через бота — начисляются монеты и опыт.

### Telegram-уведомления (cron)

| Время | Событие |
|---|---|
| 08:00 | Утренняя сводка задач (обязательные / на выбор / квесты + текущий streak) |
| 19:00 | Вечернее напоминание — только если не все обязательные выполнены |
| 20:00 | Streak-alert: серия под угрозой, остались невыполненные задачи |

Расписание работает по таймзоне семьи (`CRON_TIMEZONE` или таймзона первого пользователя). Родителям сводки задач не отправляются.

### Битвы с Боссами
- **Общий босс:** HP босса общее на всю семью, обновляется еженедельно.
- **Урон:** Каждая выполненная задача наносит урон пропорционально сложности.
- **Награда:** При победе все члены семьи получают золото и опыт.

### Магазин и Инвентарь
- **Покупки:** Золото тратится на предметы (оружие, одежда, шляпы, питомцы).
- **Кастомизация:** Купленные предметы надеваются и отображаются на персонаже.
- **Layered система:** Сборка внешности персонажа из слоёв (тело → одежда → аксессуары → оружие).

## Персонажи (LPC layered sprites)

- **Нарезка спрайтшитов:** LPC-листы 576×256 нарезаются на кадры 64×64 (детект сетки автоматический: 576×256 = 9×4 кадра).
- **Z-структура слоёв** (`rpg32bitCatalog.ts`): тень → back/плащ → ноги → тело → одежда → лицо-эмоции → задние волосы → передние волосы → шлем/головной убор → щит → оружие (задней/передней руки) → эффекты/аура.
- **Программные эмоции:** happy / sad / excited / tired рисуются на canvas поверх лица (`LayeredAvatar`).
- **Питомец:** отдельный слой-компаньон (`pet`), рендерится рядом с персонажем.
- **Лицензии:** LPC / Kenney (CC0 / CC-BY-SA) — пиксельные спрайты, без эмодзи.

---

## Без эмодзи

- Весь **UI, API и Telegram-бот** (команды, утренняя сводка задач, уведомления о streak) — **без эмодзи** (0 вхождений в `src/bot/`, `src/components/ui/` и в API-ответах).
- Вместо эмодзи — пиксельные спрайты (LPC / Kenney CC0 / CC-BY-SA) и иконки lucide-react: `PixelCoin` вместо монеты-эмодзи, спрайтовые иконки задач, `PixelBadge` вместо эмодзи-статусов.
- **Известное исключение:** пуш-уведомления при выполнении задачи и победе над боссом (`src/services/taskService.ts`) используют несколько эмодзи — остаток старой демо-модели, планируется к удалению.

## Для родителей (как настроить)

### 1. Создать бота в Telegram
1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → выберите имя → получите токен.
2. Вставьте токен в `.env` в переменную `BOT_TOKEN`.

### 2. Настроить семейный чат
1. Создайте групповой чат для семьи.
2. Добавьте туда бота (администратором).
3. Чтобы узнать ID чата: напишите в чат любое сообщение, откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` — найдите `chat.id`.
4. Вставьте ID в `.env` → `TELEGRAM_CHAT_ID`.

### 3. Первый запуск
```bash
start.bat  # или ./start.sh
# Сервер сам создаст таблицы в БД и засеет начальные данные (семья + пользователи)
```

### 4. Использование
- **Бот**: Команды `/menu`, `/task`, `/stats`, `/shop` в семейном чате.
- **Mini App**: Кнопка «Открыть игру» в сообщении бота — открывает приложение со сценами.
- **Создание задачи**: `/task "Убрать в комнате" 150` — создаёт задачу на 150 монет.
- **Одобрение**: После выполнения ребёнок нажимает «Сделано» — вы проверяете и одобряете.
- **Управление семьёй**: кнопка «Семья» в Navbar (видна только родителям) — добавить/редактировать/удалить ребёнка, настроить push-уведомления.
- **Регистрация**: первый зарегистрированный пользователь становится родителем-админом.

## Схема базы данных (PostgreSQL)

**Ключевые таблицы:**
- `users`: Пользователи (id, telegram_id, display_name, family_role — parent/child, is_admin, возраст, класс, золото, опыт, здоровье, мана, кастомизация, streak-поля).
- `tasks`: Задачи (code, title, description, points, task_type — core/personal/quest, is_required, age_min/age_max, assignee, done).
- `families`: Семейные группы (family_code, name) для разделения пользователей.
- `items`, `pets`: Магазин и доступные питомцы.
- `character_inventory`, `character_pets`: Связь пользователей с купленными предметами и активированными питомцами.

Миграции применяются автоматически через `drizzle-kit push` — схема описана в `src/db/schema.ts`.

## Технические требования для разработки

1. **Маршрутизация (Scene Router):** Переключение между тремя сценами должно происходить мгновенно через React State (или легковесный in-memory роутер) без перезагрузки страницы WebApp. Это критично для сохранения сессии Telegram и бесшовного игрового опыта (без `<a href>` или браузерных рефрешей).
2. **Оптимизация рендеринга (Sprite Sheets):** Обязательно использовать технику Sprite Sheets (атласы анимаций) для 32-bit графики. Анимации `Idle` и `Walk` всех членов семьи на одном экране не должны нагружать процессор телефона.
3. **Синхронизация через API (Real-Time):** При изменении состояния через бота (например, ребенок сдал квест -> родитель подтвердил) сцена «Семейный Дом» должна мгновенно обновиться по WebSocket/Polling. У ребенка должен пропасть маркер `!`, а его персонаж — проиграть анимацию радости/успеха без перезагрузки сцены.
