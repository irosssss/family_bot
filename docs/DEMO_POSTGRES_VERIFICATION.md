# Проверка сохранения локального DEMO

Дата: 2026-09-05. Проверено на настоящем локальном PostgreSQL, используемом приложением.

## Подтверждённый результат

`tests/demoPostgres.test.ts`: **9/9 тестов прошли**. После исправления `GET http://localhost:3000/api/demo/state` вернул **HTTP 200**.

Проверены отдельные тестовые записи `integration-<UUID>` в `demo_worlds`. Каждый тест создаёт свою запись. После прогона все девять записей удалены по точным идентификаторам; дополнительный SELECT подтвердил отсутствие остатка. Запись приложения `local-family-v1` и существующие таблицы реальных семей тесты не изменяют.

Проверены:

- Запись и последующее чтение состояния новым экземпляром хранилища.
- 12 одновременных заявок на ежедневный подарок: семья получает ровно 2 монеты.
- 16 параллельных отправок одного доверенного задания: одно выполнение, одна награда, одно известное яйцо.
- 8 одновременных родительских подтверждений: одна награда по снимку, сохранённому до редактирования задания.
- Две разные покупки, превышающие вместе доступный баланс: одна проходит, вторая отклоняется, отрицательного баланса нет.
- 12 повторов одного удара с одинаковым requestId: одно списание энергии и один удар.
- Одновременные завершающие удары: одна награда за победу.
- Ошибка при изменении внешности откатывает всю транзакцию, включая промежуточную выдачу стартовой одежды.
- Новый отдельный процесс Node читает сохранённое состояние и повторяет уже проведённую демонстрационную покупку: остаются 120 декоративных кристаллов и одна покупка.

## Найденная и исправленная runtime-проблема

В `src/db/index.ts` один клиент postgres.js используется также Drizzle. Установленная версия Drizzle заменяет сериализаторы JSON/JSONB клиента на пропускающие значение без преобразования (`node_modules/drizzle-orm/postgres-js/driver.js`, типы 114/3802). Поэтому передача объекта через `client.json(object)` приводила к TypeError при первой вставке и HTTP 503.

`src/demo/store.ts` теперь передаёт JSON как параметризованный `JSON.stringify(state)` с явным `::jsonb`. Общие настройки клиента не меняются. Все проверки и запись по-прежнему выполняются внутри транзакции после `SELECT … FOR UPDATE`.

## Повторный запуск

По умолчанию тесты реальной БД пропущены, чтобы обычный `npm test` не требовал базы и доступа к переменным окружения. Для явного запуска:

```bash
envskill run --only SQL_HOST,SQL_USER,SQL_PASSWORD,SQL_DB_NAME -- env DOTENV_CONFIG_PATH=/dev/null DEMO_REAL_PG=1 npx vitest run tests/demoPostgres.test.ts
```

Передаются только четыре именованные переменные. Их значения не читаются и не печатаются. `DOTENV_CONFIG_PATH=/dev/null` исключает дополнительное чтение проектного `.env`. Для подключения к localhost среда Codex может потребовать разрешение на выполнение за пределами сетевой песочницы.

## Границы проверки

Это проверка реальных транзакций, конкурентного доступа и сохранения между процессами. Визуальные сценарии и рабочее браузерное демо проверяются отдельно в основном плане. Идентификация через выбранный профиль допустима только в локальном демо: маршруты ограничены loopback и локальным Host/Origin. Основное приложение (`src/server/apiApp.ts`) вообще не подключает `/api/demo` при `NODE_ENV=production`, в том числе при `DEMO_MODE=true`. Внутренний флаг роутера не отменяет эту production-границу основного приложения.
