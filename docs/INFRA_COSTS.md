# Затраты на развёртывание в Telegram: детальный анализ + минимизация

Дата: 2 сентября 2026. Проверено по актуальным тарифам Supabase, Cloudflare,
VPS-провайдеров РФ, требованиям Telegram Bot API и ЮKassa.

---

## 1. Что вообще нужно для работы family_bot в Telegram

| Компонент | Требование | Комментарий |
|---|---|---|
| **База данных** | PostgreSQL | users, tasks, inventory, completions, pets, referrals |
| **API-сервер** | Node.js + Express + HTTPS | роутеры /api/*, auth TMA |
| **Бот** | node-telegram-bot-api | long polling ИЛИ webhook |

| **Мониторинг** | uptime-пинг | Telegram-пользователи не прощают даунов |

## 2. Вариант 1 — МАКСИМАЛЬНО БЕСПЛАТНО (0₽ хостинг)

### Состав
- **БД**: Supabase Free — Postgres 500MB, **50,000 MAU**, API без лимитов, 5GB egress
- **API**: Cloudflare Workers Free — **100k запросов/день**, 10ms CPU/запрос, SSL включён
- **MiniApp**: Cloudflare Pages Free — безлимитная статика + SSL
- **Бот**: webhook-режим (setWebhook указывает на Worker), long polling отключить
- **Realtime**: Supabase Realtime (free) вместо socket.io
- **Мониторинг**: UptimeRobot Free (50 мониторов, пинг каждые 5 мин — заодно
  решает проблему паузы Supabase после 7 дней неактивности)
- **Бэкапы**: CF Cron Triggers (free) → pg_dump в R2/репозиторий (free-tier R2 = 10GB)

### Ёмкостная проверка (что реально влезает)
- **БД**: ~50KB на семью → 500MB вмещает **~10 000 семей / 40 000 юзеров**
- **Workers 100k req/день** = ~**2 500 DAU** (по 40 запросов/день на активного)
- **Egress 5GB** = 1000 DAU × 5 refresh/день × 30KB = 150MB/мес — запас 30×

### Что придётся переделать (честно, это главное)
1. **Workers — это не Node.js.** Экспресс-сервер не запускается as-is:
   - `node-telegram-bot-api` (long polling) → переписать на raw webhook-хендлер (fetch → sendMessage)
   - `socket.io` → убрать; урон босса через Supabase Realtime или простой polling
   - `drizzle + postgres-js` → работает на Workers (проверено CF), pooling через Supabase pooler
   - `appState` in-memory зеркало → читать из БД (мы уже БД-first после Phase 6 — полдела сделано)
2. **10ms CPU/запрос**: тяжёлое (генерация превью) — вынести/кэшировать. Наши API лёгкие, ок
3. **Нет бэкапов в free** — критично для детских данных: cron-скрипт обязателен
4. **Supabase паузит проект** после 7 дней неактивности → UptimeRobot решает

## 3. Вариант 2 — ГИБРИД: бесплатное + мини-VPS (рекомендую)

Идея: **весь код остаётся как есть** — Node-процесс живёт на дешёвом VPS,
зато фронт/ассеты — на Cloudflare Pages, БД — Supabase Free (или прямо на VPS).

### Состав
- **API+бот**: VPS 1 vCPU / 1GB RAM — наш сервер ест ~200MB, хватает с запасом
  - SprintHost от 91₽/мес, VDSina от 150₽/мес, Beget 210₽/мес (бэкапы включены, SLA 99.98%)
- **БД**: Postgres прямо на VPS (0 внешних зависимостей) ИЛИ Supabase Free
- **Фронт/ассеты**: Cloudflare Pages Free (CDN по миру, SSL) — Telegram MiniApp грузится быстро
- **Бот**: long polling как сейчас — **ноль миграций**
- **Домен**: .ru ~200–390₽/год — нужен для HTTPS MiniApp
- **Мониторинг**: UptimeRobot Free

### Плюсы/минусы
- ✅ **Ноль миграций** — деплой как на локале (pm2 + git pull)
- ✅ WebSocket работает, полный контроль, бэкапы по cron
- ❌ ~170–240₽/мес вместо 0

## 4. Что НЕ покупаем (экономия)

| Статья | Почему 0₽ |
|---|---|
| SSL | Let's Encrypt / Cloudflare — бесплатно навсегда |
| CDN | Cloudflare Free — бесплатный |
| Telegram-хостинг | Бот API бесплатен, лимиты Telegram щедрые (~30 messages/sec) |
| App Store / Google Play | НЕ нужны — MiniApp внутри Telegram, 0₽ + нет их 30% комиссии! |
| Мониторинг | UptimeRobot Free |
| Реестры/лицензии | Минцифры реестр — только если рекламироваться в РФ-сторах; мы в Telegram |
| Supabase Pro | Только при >5k MAU (данные крошечные: 500MB = 10k семей) |

**Ключевая экономия всей схемы**: не публикуем в сторы → нет 30% комиссии Apple/Google,
нет $99/год Apple Developer, нет ревью. Telegram = дистрибуция за 0₽.

в сторону CF Workers + Supabase Pro (на тот момент доход позволит).
