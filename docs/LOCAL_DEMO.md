# Семейный дом на этом Mac

## Запуск

Docker Desktop уже установлен. PostgreSQL 18 работает в контейнере `family_chores_db`, данные находятся в постоянном томе `family_bot_pgdata`. Контейнер можно останавливать без потери базы. Не выполняйте `docker compose down -v`: ключ `-v` удаляет том с данными.

На этом Mac процессор Intel (`x86_64`). Команда `brew install docker/tap/sbx` относится к Docker Sandboxes для AI-агентов, а не к PostgreSQL. `sbx` не установлен: по [официальным требованиям Docker](https://docs.docker.com/ai/sandboxes/install/) на macOS нужен Apple silicon. Для этого проекта достаточно установленного Docker Desktop; отсутствие sbx не мешает запуску.

1. Откройте Docker Desktop и дождитесь запуска.
2. В каталоге проекта выполните `docker compose up -d postgres`.
3. Выполните `npm run dev:demo` и оставьте терминал открытым.
4. Откройте [семейный дом](http://localhost:3000/).

`dev:demo` использует установленный envskill и передаёт только параметры PostgreSQL. Значения не выводятся; дополнительная загрузка `.env` отключена. Telegram, S3 и Sentry этому запуску не передаются. Настройки существующего проектного `.env` были импортированы через envskill без отображения значений. Для перенастройки используйте `envskill set ИМЯ_ПЕРЕМЕННОЙ`, не вставляйте секреты в чат.

Остановка сервера: Ctrl+C. Остановка PostgreSQL: `docker compose stop postgres`. Повторный запуск читает сохранённое состояние.

## Где что находится

- Новый интерфейс: `src/demo/`; локальная семья хранится отдельной записью `demo_worlds/local-family-v1` в PostgreSQL.
- Прежнее приложение доступно по [localhost:3000/?legacy=1](http://localhost:3000/?legacy=1). Его таблицы и ассеты сохранены.
- Production-сборка продолжает открывать прежнее приложение; локальный API не монтируется при `NODE_ENV=production`.
- Переключатель профиля — удобство локальной демонстрации. Он не является настоящей авторизацией и не должен переноситься в production.
- API демо принимает только loopback-подключения с локальными Host/Origin. Демо не публиковалась в интернете.

## Короткая прогулка

1. В доме нажмите на близкого: откроются его дела, ваш профиль не сменится.
2. Во вкладке «Дела» выполните доверенное дело ребёнка. Получите первый опыт, энергию, вклад в копилку и известное яйцо.
3. Дело с подтверждением сначала ждёт взрослого. Выберите взрослый профиль сверху, подтвердите или оставьте подсказку. Повторная отправка не создаёт двойную награду.
4. «Гардероб» → «Образ»: кожа, причёски, цвета, класс; борода только у папы. «Отменить примерку» ничего не записывает.
5. «Одежда»: примерка → получение в коллекцию → сохранение образа. Покупка не надевает вещь автоматически.
6. «Дом»: примеряйте три комнаты, выбирайте декор для полки, стены и пола. Предыдущая вещь остаётся в коллекции.
7. «Питомцы»: вылупите полученное яйцо бесплатно и явно выберите спутника. До этого животных в доме нет.
8. «Поход»: ребёнок тратит заработанную энергию. В книге представлены все 49 позиций боссов, взрослый выбирает следующий поход. Повторная победа — тренировка без награды.
9. Взрослый → «Семья»: редактор участников, дел, боссов, питомцев, вещей и комнат. Скрытие обратимо; используемое защищено.
10. Взрослый → «Особый декор»: симуляция с явной отменой и надписью об отсутствии списаний. Это не Stars и не реальный платёж.

## Старые данные с рабочего компьютера

Клонирование GitHub переносит код, но обычно не содержимое PostgreSQL. Здесь создана отдельная локальная база с начальными данными; прежние семейные записи не были восстановлены.

Для переноса нужен дамп со старого компьютера, например созданный `pg_dump -Fc`. Не отправляйте его в публичный репозиторий или чат: внутри могут быть персональные данные. Сначала сохраните дамп локально, затем восстановите в **отдельную новую базу** и проверьте состав таблиц/пользователей. Перезаписывать нынешнюю базу или применять `--clean` без отдельного согласования нельзя. PostgreSQL 18 здесь подходит для дальнейшего переноса; фактическую совместимость нужно сверить с версией исходной базы и дампом.
