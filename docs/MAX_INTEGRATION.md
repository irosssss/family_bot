# MAX-мессенджер: проработка интеграции family_bot

Дата: 2 сентября 2026. Источники: официальная документация dev.max.ru, разборы
Bot API, кейсы платёжных интеграций (СБП), статистика аудитории VK/Сферум.

---

## 1. Что такое MAX и почему это наш второй канал (стратегически идеальный)

MAX — мессенджер от VK Tech (2024), к 2026: **~30 млн MAU**, 1 млрд сообщений,
8 млн звонков/день. Но главное — **не общий MAU, а структура аудитории**:

| Факт | Что это значит для нас |
|---|---|
| **Сферум (образовательное пространство) в MAX: 26 млн зарегистрированных — 23,9 млн учащиеся и их родители, 2,1 млн педагогов. Еженедельная аудитория 20 млн** | Наша ЦА (семьи со школьниками) УЖЕ массово сидит в MAX — школы переводят родительские чаты туда с мая 2026 |
| Школы обязаны использовать нац. сервис обмена информацией для дистанционного обучения | Семьям с учениками MAX фактически навязан — установка у целевой семьи почти гарантирована |
| Интеграция с ЕСИА/Госуслугами | Верификация «родитель/ребёнок» через Госуслуги = честные роли без выдумок |
| Данные на серверах в РФ (152-ФЗ) | Для детского продукта это плюс к доверию родителей |
| Конкуренция в мини-приложениях минимальная | «Золотое окно» захвата ниши 6-12 месяцев |

**Вывод**: MAX — это не «ещё один мессенджер», а канал, куда наша ЦА заведена
административно. Для семейного chore-приложения это дистрибуция мечты.

## 2. Техническая платформа MAX Bot API (детально)

### Базовые параметры
- **Домен**: `platform-api2.max.ru` (v2; старые `botapi.max.ru` / `platform-api.max.ru`
  отключались в течение 2026 — идти сразу на v2)
- **REST + JSON**, авторизация `Authorization: <token>` (query-параметры НЕ поддерживаются)
- **Rate limit: 30 запросов/сек** (как у Telegram), 429 при превышении
- **Webhook или Long Polling** (взаимоисключаемо; Long Polling — для дева,
  webhook — прод; JS SDK `@maxhub/max-bot-api` поддерживает long polling «из коробки»)
- **Медиа до 4 ГБ**, форматирование Markdown/HTML
- **SDK**: JS официальная `@maxhub/max-bot-api` (npm), Python: maxapi/maxgram/aiomax, Go

### Кто может создать бота (КРИТИЧНО — отличаются от Telegram!)
| Кто | Право публикации | Лимит ботов |
|---|---|---|
| **Юрлицо РФ** | Да | до 5 ботов |
| ИП | Да (через business.max.ru/self) | до 5 |
| **Самозанятый** | Да | **до 2 ботов** |
| Физлицо | Нет | — |

Верификация: Госуслуги / Alfa ID / Т-Business ID / СберБизнес ID, до 48 часов.
Платформа для бизнеса **бесплатна** (2025-2026).

**Для нас**: самозанятость (уже планировали для ЮKassa) даёт 2 слота ботов —
достаточно (1 бот + 1 запасной). ИП даёт 5.

### Модерация (до 48 часов) — причины отказов
- Ник 11–60 символов, оканчивается на `_bot`/`bot`
- Без эмодзи в названии
- **Обязательны: пользовательское соглашение, политика конфиденциальности,
  сведения о правообладателе, контакты поддержки** (у нас ПДн/оферта уже
  планировались для ЮKassa — переиспользуем)
- HTTPS-сайт организации
- Новый домен API (не botapi.max.ru)

### Ограничение ботов: **не могут писать первыми**
Пользователь должен сам нажать «Старт». Холодный охват — через канал в MAX
(каналы бесплатны, автопостинг из Telegram конверсия 3-7%) и кнопку open_app.

## 3. Мини-приложения в MAX (наш главный сценарий)

Mini App SDK MAX ≈ Telegram Web Apps, но со своей спецификой:

- **HTML/JS/CSS приложение**, открывается кнопкой типа `open_app` в боте
- **HTTPS обязателен** (наш Cloudflare Pages — подходит как есть)
- **Обязательная HMAC-SHA256 валидация initData** — без неё модерацию не пройти
  (у нас уже есть TMA-валидация Telegram — добавляем вторую схему проверки,
  структура почти та же)
- Кнопка запуска: «Открыть» / «Играть» / «Начать»
- В чат-бот встраивается через настройку ссылки на приложении в карточке

**План интеграции фронтенда**: наш Vite-билд работает как есть (это веб-приложение).
Разница только в bootstrap-скрипте: определяем хост (Telegram vs MAX) по
User-Agent/query, валидируем initData соответствующей схемой, адаптируем тему.
Ещё нюанс: MAX требует сертификат Минцифры в trust-list для API-запросов бота
(серверная часть), на фронт-пользователя не влияет.

## 4. Платежи в MAX (критический вопрос монетизации)

**Встроенного аналога Telegram Stars в MAX НЕТ** (на середину 2026). Как платят
в MAX-мини-приложениях (подтверждено кейсами):

1. **СБП прямо в чате/мини-приложении** — через ЮKassa/Prodamus: генерируем
   платёжную ссылку/QR, пользователь платит, вебхук подтверждает. Комиссия ~0.4-3%,
   деньги на следующий день. Это ЛУЧШИЙ рельс — те самые «СБП #1» кнопки из VPN-ботов.
2. **Банковские карты** через того же агрегатора.
3. **Платная подписка на канал MAX** (комиссия платформы 15%, мин. 99₽/мес) —
   не наш формат (у нас не контент-канал), но есть как запасной путь.

**Схема для Family Pro в MAX**: кнопка «Купить Pro» → генерация платёжной ссылки
ЮKassa (СБП) → оплата в 2 тапа → вебхук → активация `family_pro_until`.
Тот же код, что для Telegram-СБП-рельса — переиспользуем 100%.

**Экономика в MAX даже лучше Telegram**: нет 55% звёздного налога, чистая маржа
~97% при СБП.

## 5. Архитектура мульти-мессенджера (как строим)

```
                    ┌────────────────────────┐
   Telegram Bot ────┤                        │
   (node-telegram)  │   Ядро: Express API    │
                    │   + Drizzle + Postgres │──── Supabase/VPS Postgres
   MAX Bot ─────────┤   (общее ядро игры)    │
   (@maxhub SDK)    │                        │
                    └───────────┬────────────┘
                                │
              MiniApp-фронт (Vite build, Cloudflare Pages)
              bootstrap определяет хост: Telegram TMA | MAX WebApp
              → валидация initData по схеме хоста
              → платежи: Stars (TG) | СБП-ЮKassa (оба)
```

**Ключевое: игровое ядро одно.** Боты — тонкие адаптеры (получить апдейт →
вызвать ядро → отправить ответ). MiniApp-фронт один, с двумя bootstrap-адаптерами.

### Объём работ по MAX-адаптеру (оценка)
1. **MAX-бот-адаптер** (уведомления: задача выдана, стрик, босс атакован):
   1 день — JS SDK, long polling для дева, webhook в прод
2. **initData-валидация MAX** (HMAC-SHA256): полдня — аналог apiAuth.ts
3. **Платёжный вебхук ЮKassa** (общий для обеих платформ): 1-2 дня + договор
4. **Bootstrap-детект хоста во фронте**: полдня
5. **Карточка бота + юр. страницы + модерация**: полдня (тексты уже есть)

**Итого: ~3-4 дня** на полноценный второй канал.

## 10. MAX Bridge — фронтенд-API мини-приложения (детали)

Подключение одной строкой в index.html (аналог telegram-web-app.js):
```html
<script src="https://st.max.ru/js/max-web-app.js"></script>
```
После этого доступен глобальный `window.WebApp`:

**Идентификация:**
- `WebApp.initData` — строка для серверной валидации (как TMA)
- `WebApp.initDataUnsafe` — `{ query_id, ip?, auth_date, hash, user{id,first_name,...}, chat{id,type}, start_param }`
- `WebApp.platform` — `ios|android|desktop|web`
- `WebApp.version`, `WebApp.deviceName`

**Навигация и UX:**
- `BackButton.show()/hide()/onClick()` — кнопка «Назад» в шапке (наш таб-бар не конфликтует)
- `openLink(url)` — внешний браузер, `openMaxLink(url)` — диплинк внутри MAX
- `enableClosingConfirmation()` — предупреждение о потере данных (для форм оплаты!)
- `getViewportSize()` — размер viewport (Promise)

**Виральные механики (готовые из коробки!):**
- Диплинк `https://max.ru/:share?text=<текст>` — системный экран «Поделиться в MAX»
- `shareMaxContent({ mid, chatType })` — шеринг медиа: бот отправляет контент,
  мини-апп пересылает его в любой чат (реферальный движок — «позвать семью» одной кнопкой)
- Диплинк приложения: `https://max.ru/<botName>?startapp=<payload>` (payload до 512 симв.,
  `[A-Za-z0-9_-]`) — как t.me/bot?start= у нас; `initDataUnsafe.start_param` читается во фронте

**Устройство:**
- `requestContact()` — номер телефона с HMAC-проверкой (для верификации родителя!)
- `SecureStorage.setItem/getItem` — защищённое хранилище устройства
- `BiometricManager` — биометрия (FaceID/пин) — можно защитить кошелёк/покупки ребёнка
- `requestScreenMaxBrightness()` — яркость на 30 сек (квест-режимы/QR-показ)
- `ScreenCapture.enable/disable` — блокировка скриншотов (приватность детей!)

**MAX UI** — официальная React-библиотека (`@maxhub/max-ui`, github.com/max-messenger/max-ui)
+ Figma-гайдлайн: наш пиксель-стиль остаётся, но системные компоненты (модалки, тосты)
можно взять нативные для «ощущения родного приложения».

## 11. Валидация initData MAX — схема ИДЕНТИЧНА Telegram

Сверил с dev.max.ru/docs/webapps/validation: алгоритм 1-в-1 как TMA:
1. Пары key=value, hash ровно один раз, исключить hash
2. URL-декод значений, сортировка a→z
3. `launch_params` = пары через `\n`
4. `secret_key = HMAC_SHA256(key="WebAppData", data=BOT_TOKEN)`
5. `hash = hex(HMAC_SHA256(secret_key, launch_params))`
6. Сравнить с присвоенным hash

**Отличия от Telegram — только 3:**
1. Параметры приходят в URL-фрагменте `#WebAppData=...` (TG — в query `tgWebAppData=`)
2. Есть доп. поля: `ip`, `chat{...}` (в TG нет), `start_param` вместо `start_param` (совпадает)
3. `chat` бывает в initData (если открыли из группы) — учесть в схеме БД: max_chat_id

**Следствие для кода**: наш `telegramAuth.ts` переиспользуется почти 1:1 —
выносим общую функцию `validateWebAppData(token, params)`, два тонких адаптера.
auth_date freshness-проверка такая же (24ч окно).

## 12. Платежи в MAX — практика (проверено по кейсам)

Встроенного Stars в MAX нет. Два проверенных пути:

**A. ЮKassa (для самозанятых — официально поддерживается)**
- СБП: комиссия от 0.4% (не более 1500₽/платёж), «рассчитывается индивидуально»
- Карты РФ/зарубежные: 3.5%; ЮMoney 3.5%; SberPay/T-Pay 3.5%
- **Автоплатежи поддерживаются** («подойдёт тем, кто продаёт по подписке» — прямая
  цитата ЮKassa) → рекуррентный Family Pro возможен
- Лимит самозанятого: 500k₽/мес с карт, годовой доход до 2.4M₽ (НПД)
- Чеки 54-ФЗ: автоматом
- Интеграция: платёжная ссылка из ЛК даже без сайта; API-модуль для webhook

**B. Prodamus (альтернатива, готовое мини-приложение в MAX)**
- Подключение 10 000₽ разово (или 8000₽ промо), комиссия 3.5% (до 500k оборота),
  дальше 3.2-2.7%
- Готовое мини-приложение приёма платежей в MAX, 54-ФЗ автоматом
- Минус: платное подключение; плюс: ноль интеграции

**Выбор для нас**: ЮKassa — нет платы за подключение, СБП от 0.4%, автоплатежи.
Prodamus — fallback, если ЮKassa затянет верификацию.

**Сценарий оплаты Family Pro в MAX:**
1. Витрина Pro в MiniApp → кнопка «Оплатить»
2. Наш API → ЮKassa API: создание платежа с `confirmation: { type: 'redirect' }`
   и `save_payment_method: true` (для рекуррентности)
3. `openLink(paymentUrl)` (MAX Bridge) → платёжная форма/СБП-подтверждение в banking app
4. ЮKassa webhook `payment.succeeded` → наш сервер → активация family_pro_until
5. Возврат в MiniApp по return_url
