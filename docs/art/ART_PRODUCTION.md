# Family Chores RPG — производство, покрытие и приёмка графики

Версия 1.0, 2026-09-07. **ART07–ART08 приняты как спецификация; визуальная проверка впереди.** База: [Asset Bible](ASSET_BIBLE.md), [компоненты](ASSET_COMPONENTS.md), [UX](UX_CONTRACT.md), [roadmap](../PRODUCT_ROADMAP.md). Сейчас подготовлена только документация; ни один шаг генерации/публикации этой таблицей не запущен.

## 1. Предлагаемый вертикальный пилот

Пилот проверяет одну завершённую цепочку: дом → дело → личное приобретение → герой/питомец → сохранённый уголок. Он не является финальным количеством персонажей/питомцев игры и не разрешает импорт старых изображений как основных.

| Единица пилота | Предлагаемый объём | Что доказывает |
|---|---|---|
| Дом | 1 основная комната, 1 совместимое улучшение | Camera/light, свободное место, anchors, изменение без полного перерисовывания семьи. |
| Семья | 2 взрослых + 2 ребёнка как тестовая композиция | Совместность, пропорции, разные роли; это fixture, не ограничение состава семьи. |
| Базовые образы | Минимальные body/pose families для этих четырёх фигур; точное число после concept | Повторное использование слоёв; не четыре уникальных склеенных портрета. |
| Одежда | Бесплатный базовый комплект + 1 сменный верх + 1 сменный головной убор | Совместимость, покупка/примерка, волосы/головной убор. Сидячие варианты включаются, если выбран seated profile. |
| Причёски/цвет | 2 различимых стиля + проверяемые варианты цвета в пилоте | Неодинаковость героев без зависимости роли от цвета. Не финальный ассортимент редактора. |
| Питомцы/яйца | 2 известные коллекционные позиции; один экземпляр с полностью собранным уголком для глубокой проверки | Осмысленный стартовый выбор и коллекция без дубликатов; 2 не становится лимитом каталога. |
| Уголок | 1 бесплатная база, совместимые rest+toy, 1 сменный rest и 1 сменный фон | Независимые сохранения двух pet и переиспользование одного декора. |
| Иконки | Только фактически используемые первыми экранами | Стиль, target, контраст; список ниже, количество PNG определяется реализацией. |
| UI | Дом, дело, товар/примерка, коллекция, уголок, взрослая проверка; shared components | Реальные состояния действий и мобильная читабельность. |
| Локализация | Русский черновик + псевдолокализация тестового набора | Длинные имена/цены/описания не ломают рамки. Финальные языки остаются O13. |

Начальный реестр назначений иконок: home, tasks, profile, shop, pets, wardrobe, family_reward, review, settings, back, close, previous, next, coins, xp, family_contribution, pending, accepted, returned, locked, selected, error, retry, egg, rest, toy. Это semantic roles; arrow/close/focus могут быть кодовыми primitives, а не отдельными PNG. Никаких emoji как временной замены в runtime.

## 2. Производственные этапы

| Этап | Результат | Критерий перехода |
|---|---|---|
| A0 — спецификация, сейчас | ART01–ART08, декомпозиция, UX, профиль-кандидаты | Приёмка направления и явных зависимостей. |
| A1 — художественный образец | Один согласуемый concept дома с тестовой семьёй, pet и оболочкой | Отдельное разрешение на создание образца; проверка композиции/стиля/масштаба до нарезки. Не выдавать flattened concept за модульные слои. |
| A2 — профиль модульности | Body/pose/layer/anchor contract, палитра и exact размеры | Образцы выдерживают 1×/2×, совместимые сборки и прозрачность. При изменении профиля пересчитать производственную матрицу. |
| A3 — пилотный пакет | Проверенные отдельные assets + metadata + localization + credits | Нет дыр/двойных кистей/ошибок occlusion; все зависимости разрешимы; demo reference отдельно. |
| A4 — изолированный UI-прототип | Экранные состояния на синтетической семье | Отдельное разрешение на реализацию, визуальные доказательства на 375/390 и web; нет мутаций реальных семей. |
| A5 — согласование ассортимента | Число баз/вариантов/предметов/видов, покрытие release | Стоимость рассчитана по пилотной скорости и реальным доработкам, не по числу строк в Bible. |
| A6 — серийное производство | Пакеты поддерживаемых вариантов, thumbnails, review sheets | Графика проходит тот же контракт и visual QA; повторное использование не нарушает происхождение/совместимость. |
| A7 — выпуск / поддержка | Immutable manifest, проверенная активация, план сохранения старых ревизий | Отдельная приёмка/разрешение выпуска; новые файлы внесены в ASSET_MANIFEST. |

## 4. Метрики производства и бюджеты

Количество финальных PNG нельзя достоверно определить до выбора body/pose/view-матрицы. В ведомости считаются отдельно: логические определения, варианты сборки, уникальные бинарные файлы, производные превью, локализуемые сообщения и проверяемые комбинации. Два слоя одной шляпы — два ресурса, но одна вещь; один общий PNG может обслуживать несколько definitions без копирования файла.

| Метрика | Как получить | Граница решения |
|---|---|---|
| Время на принятый вариант | Время concept/cleanup/export/QA плюс доля переделок пилота | До оценки команды/календарных дат. |
| Стоимость нового body/pose | Число затронутых вещей × новые варианты + QA комбинаций | До обещания нового семейства тел/поз игрокам. |
| Размер первой загрузки | Реальные bytes manifest, критических сцен/иконок, отдельно JS/fonts | O13: цель согласуется на целевых устройствах; общий размер репозитория не метрика загрузки. |
| Память изображений | Сумма декодированных размеров и одновременно живых layers/cache | Для грубой RGBA-оценки width×height×4, затем измерение WebView; формат сжатия не равен decoded memory. |
| Переключение уголков | Время появления текущего pet, число запросов и высвобождение прежних сцен | Не загружать все полные уголки; превью коллекции отдельно. |
| Полнота совместимости | Поддержанные tuple и проверенные overlap cases | Не объявлять unsupported/untested комбинацию доступной к покупке. |
| Доступность / тексты | Контраст фактического экрана, focus, reader flow, длинная локализация | Не равна одному контрастному hex-набору. |

Начальный runtime static PNG RGBA/opaque по профилю; lossless-альтернатива рассматривается только после проверки одинаковых пикселей, alpha, decoding и размера на целевых клиентах. Сжатие не должно добавлять цветовой шум/потерю контура. Атласизация — оптимизация сборки после измерений, а не способ потерять отдельные AssetRef/credits.

## 6. Карточка принятого ассета

Для каждого ресурса перед включением: стабильный asset_id/revision, definition bindings, роль, profile revision, canvas/bounds/anchors, checksum/bytes/media type/alpha, exact variant tuple, источник и права, результат совместимости, ссылка на visual proof, статус draft/reviewed/approved/released и принимающая сторона. Стадии art review и публикации различаются; сгенерированный файл не становится approved автоматически.

Производственный manifest и [ASSET_MANIFEST](../ASSET_MANIFEST.md) имеют разные роли: первый обеспечивает сборку/зависимости, второй фиксирует реальные runtime-файлы и точки использования по правилам проекта. Нельзя обещать наличие новых ассетов, добавив только строку в манифест.

ART01–ART08 приняты как спецификация. Принят как проект [детальный контентный конвейер PIPE01–PIPE08](../content/CONTENT_PIPELINE.md): закрытые authoring-схемы, манифест, нейминг, validation/preview, сборка, совместимость, активация и откат. Разрешение создавать художественный образец A1 или реализовывать прототип A4 запрашивается для конкретного результата отдельно в согласованном пользователем порядке.
