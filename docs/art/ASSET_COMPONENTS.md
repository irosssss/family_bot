# Family Chores RPG — декомпозиция ассетов и зависимости

Версия 1.0, 2026-09-07. **ART02–ART05 приняты как спецификация; визуальная проверка впереди.** Основа: [Asset Bible](ASSET_BIBLE.md). Каждая строка — самостоятельная единица сборки/контента или явно объединённый элемент. Это таксономия для производства; она не означает отдельную покупку каждого слоя и не утверждает выпуск всей матрицы в MVP.

## 1. Герои: взрослые и дети

| Код | Элемент | Минимальная единица / зависимость | Варианты и этап |
|---|---|---|---|
| CH01 | Базовый силуэт | Body с шеей/головой либо согласованный body+head profile; единая система координат | По утверждённым пропорциям/позе. Не тело на каждого пользователя. MVP. |
| CH02 | Лицо | Глаза/брови/нос/рот одним face overlay, пока они не меняются независимо | Разделить глаза только если принята их независимая настройка; без неподтверждённого редактора каждой черты. |
| CH03 | Цвет кожи | Заданный вариант тела/палитры с сохранением shading | Маска/палитра или проверенные экспорты; цвет не определяет роль. |
| CH04 | Волосы сзади | hair_back overlay | Только у причёсок, пересекающих плечи/одежду. Остальные не получают пустой обязательный PNG. |
| CH05 | Основные волосы | hair_main overlay | Стиль + цвет + pose/view; не ссылка на старые ULPC каталоги. |
| CH06 | Передние пряди | hair_front overlay | Опционально, если нужны независимые перекрытия лица/головного убора. |
| CH07 | Борода/усы | facial_hair overlay | Опциональная косметика базового образа; конкретный ассортимент позднее. |
| CH08 | Нижняя одежда базы | Бесплатный непрозрачный underlayer, при необходимости объединён с body | Снятие экипировки не создаёт голого/некорректного персонажа; базовый комплект согласуется визуально. |
| CH09 | Кисти | hand_back/hand_front по необходимости крепления предмета | Не дублировать кисть поверх нарисованной в body; конкретная поза захвата в профиле. |
| CH10 | Контактная тень | Маленький отдельный ресурс/зарегистрированный shape | Привязка floor/seat, может повторно использоваться для нескольких героев. |
| CH11 | Портрет | Derived crop той же принятой сборки | Источник образа единый; отдельная иллюстрация не выдаёт другой цвет волос/одежду. |
| CH12 | Рамка/выбор героя | UI-компонент поверх сборки | Не часть тела или купленной одежды; active/focus/selected различаются. |

Взрослые имеют отображаемый образ для дома, но не получают игровые кошельки/уровни ради рендера. Наличие внешнего вида не добавляет неподтверждённые административные игровые действия. Детские варианты рисуются в собственной пропорции, с совместимостью declared body_family.

## 2. Экипировка и личные вещи

| Код | Элемент | Зависимости и разбиение | Ограничение |
|---|---|---|---|
| EQ01 | Верх | torso overlay, при необходимости отдельные рукава/часть за рукой | Один предмет/право, несколько visual bindings. |
| EQ02 | Низ | legs overlay | Совместимые pose/body; сидячий низ не растягивается из стоячего. |
| EQ03 | Обувь | feet overlay; пара одним слоем при общей смене | Не две покупки за левый/правый ботинок. |
| EQ04 | Головной убор | headwear_main, при необходимости back/front | Hair occlusion profile; лысая «дыра»/волосы сквозь шляпу — дефект. |
| EQ05 | Полный костюм | Набор upper/lower/feet bindings по slots | Occupied_slots запрещает одновременный конфликтующий низ/верх; один ownership_key. |
| EQ06 | Плащ/накидка | cape_back и, если нужен, cape_front | Пересечение волос/рук описано профилем. Поздний ассортимент, не обязательный MVP. |
| EQ07 | Предмет в руке | held_back/held_front + grip anchor | Игровое оружие не включает автоматически боевые свойства в MVP. |
| EQ08 | Щит/вторая рука | offhand overlay с допустимой позой | Не продавать для позы без соответствующей геометрии. |
| EQ09 | Малый аксессуар | Один overlay на объявленный слот | Не вводить произвольные координаты drag/drop в первой версии. |
| EQ10 | Иконка товара | icon + при необходимости item_preview | Проверяется соответствие конкретной форме/цвету предмета. |
| EQ11 | Цветовой вариант | Content variant или material palette mapping | Не автоматически новая покупка/редкость; правила владения вариацией задаёт каталог. |
| EQ12 | Упаковка/подарок | Превью отдельного поддерживаемого типа | Подарки между детьми, торговля/крафт не приняты только из-за наличия изображения. |

Комплект связывается данными `set_key` лишь для группировки, если этот контракт будет принят; сам набор не обязан иметь игровые бонусы. Статы из старого stats_modifier не переносятся вместе с новой картинкой.

## 3. Питомцы, яйца, косметика, уход

| Код | Элемент | Минимальная единица / связь | Этап |
|---|---|---|---|
| PT01 | Вид/коллекционная позиция | Pet ContentDefinition + collection_key | MVP; самостоятельная позиция отличается от косметической расцветки. |
| PT02 | Тело питомца | Один полный статичный sprite; хвост/уши не разделять без необходимости перекрытия | MVP; совместимый camera/light/profile. |
| PT03 | Контактная тень | Отдельная общая или видовая тень | MVP; сцена не рисует вторую тень поверх запечённой. |
| PT04 | Яйцо | Статичная icon/preview + ссылка на известный pet_result | MVP; описание/предпросмотр результата доступны до покупки. |
| PT05 | Получение/вылупление | Статичная композиция: яйцо либо питомец + UI-сообщение | MVP; не нужен spritesheet трескающегося яйца или анимация. |
| PT06 | Превью коллекции | Derived render body+выбранная косметика либо явно базовое превью с подписью | MVP; просмотр не меняет active companion. |
| PT07 | Головная косметика | pet_head overlay + anchor | 1.1; подходящие профили видов, уши/рога не перекрываются случайно. |
| PT08 | Ошейник/шарф | pet_neck overlay | 1.1; та же косметика в доме/уголке. |
| PT09 | Косметика корпуса | pet_body overlay | 1.1; не создаёт второго OwnedPet. |
| PT10 | Еда | item icon/preview + consumable definition/use contract | 1.1; не нужна отдельная сцена склада еды. |
| PT11 | Дружба | UI-символ/полоса/текст из данных | 1.1; значение не запекается в тело, не уменьшается за пропуск. |
| PT12 | Реакция на заботу | По отдельному решению статичный вариант позы/выражения | Не обязательная анимация; стоимость дополнительных вариантов учитывается отдельно. |

Экран питомца содержит его пользовательское имя отдельным текстом. Никаких уникальных PNG с именем ребёнка/питомца. Маунты, бой питомцев, разведение, торговля и случайные результаты не добавляются этим перечнем.

## 4. Уголок каждого питомца

| Код | Элемент | Владение / зависимости | MVP и расширение |
|---|---|---|---|
| PC01 | Базовый фон | Бесплатный corner_base, общий ресурс для экземпляров | MVP, обязательный. |
| PC02 | Пол / поверхность | Часть фона, если не меняется независимо; иначе отдельный слой | Не продавать как новый обязательный элемент базы. |
| PC03 | Место отдыха | Один логический rest slot: лежанка ИЛИ домик | MVP. Полностью подходящий бесплатный вариант при получении pet. |
| PC04 | Задняя часть домика | rest_back binding того же rest-item | Только если питомец действительно размещается в проёме. |
| PC05 | Передняя часть домика | rest_front binding с occlusion mask/областью | Не скрывать лицо/весь pet; принадлежит тому же предмету, не отдельная покупка. |
| PC06 | Игрушка | Один toy slot, одна постоянная вещь | MVP: фиксированное место, бесплатная базовая композиция. |
| PC07 | Питомец | OwnedPet appearance + floor/rest anchor | Одна сборка, не копия pet state в уголке. |
| PC08 | Тени вещей | В составе вещи либо отдельные bindings при смене позиции | Единый свет, не оба варианта одновременно. |
| PC09 | Дополнительное оформление | Новые совместимые слоты только после расширения профиля | 1.1/пакеты, без обязательного нового экрана на вещь. |
| PC10 | Миска/предмет ухода | Декор или часть отдельного use contract | Не вводить голодный таймер и обязательную миску в MVP. |

Фон, rest и toy — данные PetCorner. Один entitlement постоянного декора можно выбрать в разных совместимых уголках одного ребёнка. На общем доме показывается питомец возле владельца; вся его спальня рядом с владельцем не дублируется. Это сохраняет читаемость сцены.

## 6. Порядок слоёв и якоря

Предлагаемый герой: contact_shadow → hair_back/cape_back → base_body/underlayer → legs → feet → torso → rear_held → face → hair_main → headwear → hair_front по occlusion rule → hands/held_front → foreground_accessory. Это кандидат нового профиля, не изменение legacy ULPC-порядка. Для headwear/оружия нельзя обещать универсальный порядок: конкретные back/front bindings и hidden_layers указываются в данных и проверяются на сочетаниях.

Дом: shell → rear_furniture → rear_people_group → middle_props → front_people_group → permitted foreground. Участник и его pet имеют согласованный floor_contact/depth; сортировка только по произвольному zIndex предмета запрещена. Уголок: background/floor → rest_back → pet/shadow → rest_front по профилю → toy/foreground. Если toy должен быть сзади, профиль задаёт это явно.

| Якорь | Владелец | Проверка |
|---|---|---|
| floor_contact | Герой, питомец, prop | Сборка стоит на поверхности; прозрачный padding не определяет точку контакта. |
| seat_contact | Герой и сиденье | Совпадающая поза/пропорции; персонаж не висит и не проваливается. |
| hand_grip | Поза героя + предмет | Предмет удерживается нужной рукой, ориентация не получена запрещённым зеркалированием текста/асимметрии. |
| head_top / neck / back | Hero/pet + косметика | Ограниченные допустимые offsets, а не свободный transform автора каждой вещи. |
| companion_contact | Layout slot владельца | Pet не закрывает лицо/чужого участника; точка относится к раскладке, не к кошельку. |
| label_anchor | Сцена | Подпись вынесена в DOM и может менять положение при длинном имени; имя не часть hit-box спрайта. |

## 7. Матрица совместимости и контроль полноты

| Связка | Что нужно проверить |
|---|---|
| Body × pose × clothing | Совпадение canvas/контактов, силуэт, непрозрачная база, отсутствие двойных рук/ног. |
| Hair × headwear | Задняя/передняя прядь, visible/hidden layers, лицо читается. |
| Pose × held item | Захват, локоть/кисть, передняя/задняя часть, safe bounds. |
| Pet × cosmetic × corner | Та же revision внешности, уши/хвост, отверстие домика, незакрытая узнаваемая часть pet. |
| Owner × active pet × family layout | Независимые сборки, общий свет/пол, нет чужого pet, доступные controls не перекрываются. |
| House profile × upgrade | Сохранены anchors, видимость участников и допустимые interactive regions. |
| Season × базовая коллекция | Не требуется заново рисовать купленные вещи; dependencies сохраняют pinned revisions. |

Реестр допустимых комбинаций содержит explicit supported/unsupported с причиной. «Не тестировали» не равно supported. До первого массового выпуска проверяются все пары перекрывающихся слоёв и целевые полные комплекты; для растущего каталога можно применять pairwise-отбор плюс обязательные конфликтные случаи, но полноту объявленной поддержки обеспечивает валидатор матрицы и ручной просмотр новых комбинаций.
