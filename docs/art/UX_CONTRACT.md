## 1. Визуальная иерархия и токены-кандидаты

Одна выразительная сцена дома или выбранного питомца, понятная задача экрана, одно основное действие в текущем контексте. Списки дел/покупок не превращаются в набор одинаковых декоративных игровых рамок. Имя, состояние и цена важнее орнамента; текст выравнивается влево, центрирование используется для короткого результата/персонажа.

| Токен | Кандидат | Роль |
|---|---|---|
| ink | `#202C3A` | Основной тёмный текст/контур оболочки. |
| paper | `#F3EBDD` | Светлая нейтральная поверхность рядом с интерьером; без шумной текстуры под буквами. |
| wood | `#6B523D` | Вторичный материал/выделенная тёмная поверхность. |
| leaf | `#48715B` | Основное положительное действие/успех с обязательной подписью. |
| danger | `#A33A38` | Ошибка/опасное действие с текстом, не единственный признак состояния. |
| reward | `#C99745` | Акцент прогресса/монет; не мелкий золотой текст на paper. |

Расчёт непрозрачных sRGB-пар выполнен при подготовке документа: ink/paper 11.96:1, paper/leaf 4.68:1, paper/danger 5.51:1, ink/reward 5.39:1, paper/wood 6.12:1. Reward/paper 2.22:1 — не подходит для обычного текста. Эти цифры проверяют только указанные плоские пары, а не готовый экран с тенями, opacity, disabled-состояниями и темами. Палитра остаётся кандидатом художественного пилота.

Шрифт-кандидат — Noto Sans для основного текста/контролов; один набор начертаний 400/600 достаточно для пилота. Проверить точный файл, кириллицу, лицензию, размер и загрузку перед включением. [Официальный проект Noto Latin/Greek/Cyrillic](https://github.com/notofonts/latin-greek-cyrillic) содержит исходники и лицензию; в проект файлы не загружены. Pixel-font допустим только как дополнительное художественное решение коротких заголовков после проверки чтения, не для обязательных инструкций/ошибок.

| Размер / интервал | Кандидат CSS | Правило |
|---|---|---|
| Основной текст | 16px, line-height 1.5 | Масштабируемый DOM-текст; пользовательское увеличение не блокируется. |
| Вторичный текст | 14px, line-height 1.45 | Не единственное место цены/состояния/важного условия. |
| Заголовок экрана | 24px/1.25, 600 | Sentence case, без декоративного межбуквенного разрежения. |
| Заголовок блока | 18px/1.35, 600 | Иерархия по смыслу, не каждый ряд отдельный заголовок. |
| Отступы | 4/8/12/16/24px | Обычный горизонтальный padding16; у сцены отдельные правила integer scale. |
| Hit target | ≥44×44 CSS px; основные кнопки кандидат min-height48 | Высота увеличивается для многострочного текста; пиксельная иконка может быть меньше target. |
| Фокус | Видимый контур с отступом | На обеих поверхностях, не только смена цвета/hover. |

Светлая/тёмная оболочки имеют отдельные semantic token mappings. Один набор шестнадцатеричных значений не объявляется готовой тёмной темой. Нарисованный тёплый дом сохраняет художественные цвета, а текстовые поверхности/контролы адаптируются к теме и доступности.

## 2. Предлагаемая навигация MVP

| Режим | Основные разделы | Вложенный доступ |
|---|---|---|
| Собственный детский вход | Дом, Дела, Моё, Магазин | Моё → герой/гардероб, питомцы/уголок, мои семейные награды. Магазин → вещи / доступные семейные награды. |
| Управляемый детский режим | Те же детские разделы и действия того же профиля | Переход к другому ребёнку/взрослому — явный защищённый переход; взрослые полномочия не наследуются. |
| Взрослый режим | Дом, Проверка, Управление | Проверка → дела/запросы/выдача; Управление → семья, задания, цели, каталог реальных наград, доступ и данные. |

Это предложение информационной архитектуры, не уже принятые четыре пункта меню. Питомцы имеют прямую заметную ссылку из «Моё» и карточки своего героя; маленький pet в доме не единственный вход. Взрослому не показывается пустой личный кошелёк/боевой уровень. Боссы/уход не занимают неработающие пункты MVP.

Тап по персонажу в доме открывает допустимую карточку/его дела; он не переключает действующего пользователя. Переключение режима/профиля происходит только через явный селектор. Бейдж «Режим ребёнка: {name}» остаётся видимым в управляемом входе. Публичная карточка другого участника не раскрывает его кошелёк/личные заметки.

## 3. Структура двух основных экранов

Текстовые схемы ниже показывают иерархию, а не пиксельный макет и не изображение основных ассетов.

```text
Дом ребёнка
  Заголовок семьи                 Профиль/режим
  Общая статичная сцена
  Состав семьи / доступный список участников
  Семейная цель: что открываем, состояние, вклад
  Ближайшее доступное дело / переход к делам
  Нижняя навигация в безопасной области

Уголок выбранного питомца
  Назад к коллекции              Имя питомца
  Статичная сцена текущего уголка
  Статус «Со мной в доме» / кнопка «Взять с собой»
  Оформление: Фон / Место отдыха / Игрушка
  При изменении: «Сохранить» и «Отменить»
```

При большой семье не уменьшать всех до нечитаемых точек. Предлагаемый стартовый layout рассчитан на 4 видимых участников; для большего состава — явные страницы/группы сцены и полный доступный список с именами. Это ограничение видимого кадра, не размера семьи; число/раскладка групп проверяются на пилоте. Перелистывание не меняет actor, спутников, принадлежность вещей или очередность наград. Другие участники не должны исчезать без индикатора группы/списка.

Если несколько родителей не помещаются в кадр, применяются те же правила групп; первые два не становятся единственными администраторами. В ландшафтном/desktop режиме допускается больше места для сцены и соседняя колонка информации, но контролы и тексты сохраняют свой масштаб.

## 5. Компоненты UI до повторно используемых элементов

| Код | Компонент | Из чего состоит | Состояния / правила |
|---|---|---|---|
| UI01 | Button | Native button, label, optional icon, focus ring, поверхность | default/pressed/focus/disabled/busy; loading не меняет ширину и не допускает повтор эффекта. |
| UI02 | IconButton | Иконка + ≥44px target + accessible name | Не использовать без подписи для незнакомого/опасного действия. |
| UI03 | NavigationItem | Иконка, текст, active indicator, optional count | Выбранный раздел отличается не только цветом; счётчик не мигает. |
| UI04 | Surface / Card | Оболочка, optional header, content/actions slots | Рамка только для смысловой группы; без обязательного отдельного PNG на состояние. |
| UI05 | StatusBadge | Symbol + localized label | Pending/returned/accepted различаются словами, цвет вспомогателен. |
| UI06 | Amount | Icon currency, formatted exact amount, label | Available/reserved отдельно; XP/вклад не выглядит расходуемыми монетами. |
| UI07 | Progress | Label, progress value, bar, optional remaining text | Семейный вклад может превышать порог; визуальная полоса ограничивается, фактическая сумма не теряется. |
| UI08 | TaskRow | Текст/условия/статус + одно явное действие | Тап по строке открывает детали, кнопка отмечает; вложенные targets не пересекаются. |
| UI09 | CatalogTile | Preview, name, price/status, accessible product link | Не делать мелкую наклейку цены единственным target покупки. |
| UI10 | Avatar / PetView | Контейнер сборки и отдельная подпись/контроль | Decorative layers скрыты от screen reader; семантическая подпись у сборки/действия. |
| UI11 | SlotPicker | Label, варианты, compatibility/ownership state | Selection в preview отдельно от сохранённого значения; clear только если слот optional. |
| UI12 | ProfileSelector | Текущий контекст, доступные переходы, защищённый выбор | Нет смены actor через сцену/URL/query alone. |
| UI13 | Input / Textarea | Label, input, help, error, optional counter | Placeholder не заменяет label; UGC длиннее строки переносится. |
| UI14 | Checkbox / Switch / Radio | Native control + label + description | Radio для выбора одного pet/item, Switch для реальной бинарной настройки; не имитация div без semantics. |
| UI15 | Tabs / Filter | Короткие подписанные группы, selected indicator | Keyboard/focus, сохранение фильтра без изменения владения; скрытые будущие вкладки не показаны. |
| UI16 | Dialog / Sheet | Title, description, body, actions, close | Focus trap/return; на телефоне длинная форма полноэкранная; destructive action не стоит рядом с близким target без ясной границы. |
| UI17 | Feedback | Inline status/error, optional live region, retry | Важное состояние сохраняется на экране, не только исчезающий toast. Ошибка не сообщает ложного успеха. |
| UI18 | Empty / Loading / Offline | Текст, необязательная статичная иллюстрация, допустимое действие | Нет неработающей кнопки; статичный skeleton без shimmer, не обязательный spinner. |
| UI19 | Pagination / GroupSelector | Подписанные previous/next/номер, доступный список | Не требует swipe/drag; все участники достижимы. |
| UI20 | Timeline / OrderHistory | Список событий с исходными условиями и датами | Покупка/выдача/возврат различаются; скрытые технические ID не пользовательский текст. |

Иконки контентных сущностей — отдельные статичные ресурсы. Геометрические стрелки, focus ring, native controls и простые рамки допустимо реализовать кодом/вектором: запрет контента в коде не требует PNG для каждой границы кнопки. Иконки одного назначения используют единый принятый стиль; существующие lucide/Kenney — демо/технический материал до визуальной приёмки системы.

## 6. Состояния операций и тексты

| Состояние | Что видит пользователь | Что не происходит |
|---|---|---|
| Готово к действию | Реальная цена/условия, понятная кнопка | UI не назначает себе цену или actor. |
| Отправляется | «Сохраняем…» / «Проверяем покупку…», повторная кнопка временно недоступна | Баланс не выдаётся оптимистически как подтверждённый. |
| Подтверждено | Сохранённое состояние и понятный результат | Нет второй награды при повторном открытии экрана. |
| Известный отказ | Причина рядом с действием; обновлённые условия или допустимый следующий шаг | Не показывается общий «Что-то пошло не так» вместо недостатка средств/несовместимости. |
| Неизвестный результат сети | «Проверяем, сохранилось ли действие»; восстановление по тому же ключу | Не объявлять покупку отменённой и не отправлять новую независимую покупку. |
| Конфликт revision | «Данные изменились. Обновите условия» | Не перезаписывать чужое решение молча. |
| Нет связи до отправки | Явное состояние offline, просмотр кеша с пометкой при допустимости | Не обещать offline-покупки/одобрения; неизвестные операции не накапливать скрытой очередью. |
| Доступ отозван | Выход из недействующего режима, объяснение разрешённого следующего шага | Чужие приватные данные не остаются активным экраном после смены контекста. |

Примеры ключей и текста — черновик русской локализации, не строки в коде: `task.submit_review` → «Отправить на проверку»; `shop.buy` → «Купить за {amount}»; `reward.request` → «Запросить за {amount}»; `reward.reserved` → «Ожидает решения: {amount} монет зарезервировано»; `pet.take_with_me` → «Взять с собой»; `pet.hatch_free` → «Вылупить бесплатно»; `corner.save` → «Сохранить уголок». Формы чисел и аргументы реализуются через принятую систему сообщений, без склейки строк.

Нельзя показывать ребёнку технические термины entitlement, allocation, FK, revision, migration, UUID. Взрослому при BEN объясняются конкретные суммы и последствия, а не SQL-дельты. «Прощено» не выводится как долг к оплате.

## 7. Telegram и доступность

| Область | Обязательная проверка |
|---|---|
| Viewport / safe area | Контролы не попадают под панели Telegram/вырез устройства/нижний индикатор. Обрабатывать изменения viewport/theme/safe area при поддержке API, иметь fallback для старых клиентов. |
| Клавиатура | Активное поле и ошибки доступны при экранной клавиатуре; нижняя панель не закрывает кнопку сохранения, длинная форма прокручивается. |
| Back | Вложенный экран/примерка возвращает назад; при несохранённых изменениях спрашивает только о потере изменений, без постоянного подтверждения обычной навигации. |
| Native BottomButton | Одна стратегия основной кнопки; не дублировать одновременно web и native CTA в разных местах. Выбор делается на prototype-проверке совместимости. |
| Touch / keyboard | Target≥44×44 по правилу проекта; независимые targets не перекрываются. Keyboard/focus и screen-reader путь доступны вне Telegram на web. |
| Контраст | Для обычного текста минимум 4.5:1, крупного 3:1; состояния не только цветом. Artwork не используется как неконтролируемый фон для важного текста. |
| Reflow | Проверить viewport320 CSS px и увеличение текста; сцена может иметь альтернативный список, формы/контролы не требуют горизонтального скролла страницы. |
| Подписи | У иконок действий accessible name; декоративные части сборки скрыты; доступная карточка объясняет роль сцены без перечисления каждого слоя. |
| Модальности | Нет обязательного hover/long press/drag; haptics не единственное подтверждение. Не создавать motion как обязательную часть feedback. |

Telegram документирует viewport/theme/safe-area и Back/BottomButton API: [Mini Apps](https://core.telegram.org/bots/webapps). Поддержка зависит от клиента/версии и должна проверяться capability detection; сам факт существования API не доказывает корректность нашего макета.

Порог 44px — требование проекта. WCAG 2.2 AA для target size minimum описывает 24 CSS px с оговорёнными исключениями, поэтому не называем наше правило «обязательные 44px по AA»: [Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Контраст и reflow сверены по [Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) и [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html). Приёмка документа не равна сертификации доступности приложения.

## 8. Проверка направления перед прототипом

Принцип frontend-design применён к продукту: главным акцентом служит семейная сцена; оболочка помогает сделать дело/покупку, а не демонстрирует набор декоративных панелей. В первом проходе исключены отдельные комнаты верхней навигации на каждого питомца и общий боевой HUD с валютами. В спецификации оставлены один переключаемый уголок, явные available/reserved и разные режимы взрослого/ребёнка.

Пока не доказаны художественная привлекательность сцены, удобство предложенной навигации, выбранные размеры, темы и поведение WebView. Следующий пилот должен показать эти вещи на разрешённом прототипе. Код, аккаунты и реальные семейные данные для текущего документа не менялись.
