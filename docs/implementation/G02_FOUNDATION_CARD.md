# G02-A — изолированная техническая основа

Версия 1.1, 2026-09-07. **G02-A реализован, проверен и принят пользователем.** [Первоначальный отчёт](G02_FOUNDATION_RESULT.md) сохраняет доказательства F01–F08. Затем отдельно разрешён и выполнен [G02-B](G02_DOMAIN_SCHEMA_RESULT.md); базовый G02 готов к приёмке целиком.

## 1. Результат

Новый target-каркас можно импортировать, проверить и запустить локально с собственной disposable PostgreSQL, не вызывая старые migrations/seed, не подключая Telegram/cron и не меняя действующий интерфейс. Есть проверяемые ID/refs/точные числа, отдельный миграционный журнал и тесты изоляции. Это инженерная основа; пользовательские вход, дела и покупки ещё не работают в ней.

## 2. Состав изменения

## 3. Изоляция и операции с окружением

| Область | Разрешаемое в G02-A | Условия |
|---|---|---|
| Код | Новые target/contracts/db/app/scripts/tests; точечное дополнение package scripts/config. | Без переключения main.tsx/production routing; чужие незавершённые изменения сохраняются. |
| PostgreSQL | Один task-owned disposable PostgreSQL 18 для synthetic fixture/служебных схем. | Отдельный instance, никакой доверенной ссылки на текущие SQL_*; фактический образ/версия фиксируются перед запуском. |
| Контейнер/volume | Создание и удаление только объектов, созданных этим запуском. | Exact IDs, run label и запись владельца; cleanup не использует wildcard, prune, старый compose down или удаление неизвестной БД. |
| Параметры доступа | Только локальные временные test credentials. | Не читать существующие секреты; не писать их в Git/логи. Если нужны секреты, применять доступный envskill в его разрешённой области. |
| Внешние зависимости | Использовать существующие библиотеки, где достаточно. Минимальная новая зависимость — только при доказанной необходимости для контракта. | Проверить официальный API/совместимость/лицензию и зафиксировать lock. Платные сервисы, загрузка референсов и реальные аккаунты не входят. |
| Запуск | Новый loopback HTTP и выделенный тестовый PostgreSQL. | Старые server.ts, dev:demo, db:push, db:migrate и verify-clean-migration не использовать для этого этапа. |

Если Docker или загрузка требуемого образа недоступны, независимые unit/contracts-работы продолжаются. Интеграционная часть остаётся blocked/not_run; успешный fake adapter не заменяет PostgreSQL evidence. Нельзя обойти блокировку окружения использованием реальной БД.

## 4. Обязательные проверки

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| FT01 | Импорт config/contracts/app при запрещённом network/DB creation | Никаких соединений, bot/cron/seed/migrations. |
| FT02 | Нет target config или переданы только legacy SQL_* | Ясный отказ до соединения, без выбора БД по умолчанию. |
| FT03 | Неверное имя/маркер/назначение временной БД | Запрещены миграции и cleanup; контейнер принадлежит известному run. |
| FT04 | Максимальные/нулевые/отрицательные/дробные/слишком большие суммы | Только разрешённые UInt/Int; никаких округлений через Number. |
| FT05 | Invalid UUID/ContentId/revision/лишние поля/неизвестный TypedPayload | Явный отказ, стабильный ключ ошибки и путь поля. |
| FT06 | Две миграции одного manifest одновременно | Один сериализованный результат, журнал без ложного повторного применения. |
| FT07 | Повтор завершённых миграций | Без новых эффектов и записей applied. |
| FT08 | Файл применённой миграции изменился | Checksum mismatch; выполнение остановлено до последующих миграций. |
| FT09 | SQL падает посередине тестовой миграции | Её эффекты и запись applied откатились; ранее завершённые миграции сохранены. |
| FT10 | Закрытие ресурсов и cleanup | Удалены только точные task-owned объекты; нет открытых клиентов после теста. |
| FT11 | HTTP health/readiness и неизвестный игровой маршрут | Никаких family данных; недоступная БД не даёт ложный ready, игровые методы не обслуживаются. |
| FT12 | Локальные типы и границы импортов | Проверены src/target/scripts/tests; нет транзитивного подключения старых глобальных сервисов. |

FT01–FT12 выполнены в границах [итогового отчёта](G02_FOUNDATION_RESULT.md); браузерный preview заблокирован инструментом, автоматические HTTP-проверки прошли. Они не заменяют DBT01–DBT20. В G02-B будут семейные composite FK/CHECK и соответствующая DBT14-проверка; в G07 — эффекты/кошельки, в G04 — полные схемы authoring/пакеты.

## 5. Обратимость и границы завершения

Новый target-каркас пока не обслуживает семьи. Откат — удалить/отменить только собственный diff, восстановить только внесённые строки конфигов и закрыть собственную disposable-среду. Не использовать reset/clean/stash всей рабочей копии. Legacy/demo данные и графика не входят в изменение.

После прохождения FT и typecheck результат предъявляется пользователю. Следующая карточка G02-B описывает конкретные базовые таблицы по PDB/DAT и generated DDL до исполнения на разрешённой среде. G03 не начинается от одного наличия HTTP health; оба доступа требуют собственного протокола O09.

Оценка по составу: 8 ограниченных подзадач, 12 проверочных сценариев, без UI/art/domain-команд/реального переноса. Уверенность в границах высокая; трудозатраты зависят от доступности среды и выбора проверенного UUIDv7-инструмента. Календарное обещание до этих проверок не даётся.

## 6. Статус разрешения

Пользователь разрешил **G02-A в объёме F01–F08**, принял результат и отдельно разрешил G02-B. Оба подэтапа выполнены в своих границах; следующий [G03-A](G03_ACCESS_PROTOCOL_CARD.md) пока не разрешён. Старый сервер, реальные семейные данные и графика не затрагивались.
