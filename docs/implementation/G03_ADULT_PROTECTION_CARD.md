# G03-E — PIN-защита взрослого и передача устройства ребёнку

Версия 0.1, 2026-09-07. **Разрешён сообщением «делай» и выполнен; [результат](G03_ADULT_PROTECTION_RESULT.md) на приёмку.** Вход — приёмка [G03-D](G03_FAMILY_ACCESS_RESULT.md). Цель: заменить default-deny hooks проверяемой взрослой защитой и реализовать adult/managed issuance на синтетических данных, сохранив оба детских доступа в MVP.

## 2. Числовые кандидаты для синтетических проверок

| Область | Кандидат из принятой последовательности проектирования |
|---|---|
| PIN | 6 ASCII-цифр как строка, включая начальные нули. |
| KDF | Argon2id, минимум-кандидат 19456 KiB / t=2 / p=1; параметры уточняются только после измерений и проверки первичных источников. Индивидуальный salt и отдельный pepper key ID; при отсутствии ключа отказ. |
| Adult grant / fresh proof | 5 минут бездействия, максимум 30 минут; свежесть чувствительного подтверждения 2 минуты, с привязкой к операции/цели/revision. |
| Family session / setup | 8 часов абсолютного срока; setup 10 минут. Managed не длиннее родительского контекста. |
| Recovery setup | 160 случайных бит, Base32, отдельный checksum/locator; значение показывается однократно. Полное применение recovery для утраченного доступа — следующий блок. |
| Попытки и отзыв | SP10/SP15/SP16 из [ACCESS_VALIDATION](../security/ACCESS_VALIDATION.md), атомарное состояние между процессами; общие сообщения без раскрытия существования чужой защиты. |

Эти числа не становятся политикой реального запуска по факту написания тестов. Изменения модели/стоимость сопровождения фиксируются до зависимого кода. Если конкретный KDF не поддерживается или измерения неприемлемы, завершается независимая часть и предъявляется проверенный выбор, без выдуманного fallback.

## 3. Разрешаемая среда и границы

Исходники/схемы/синтетические тесты — только target. Используются текущий disposable PostgreSQL harness и искусственный тестовый pepper; настоящий bot key не нужен. Разрешение карточки включает проверенный выбор и фиксацию необходимой криптографической зависимости после G3E01, но не подключение к настоящим семейным данным.

Создание настоящих семей, приглашения, изменение Telegram-привязки через recovery, согласованное исключение/last-adult, публичные endpoints, UI, сообщения ботом, публикация и production-настройки не входят. Сервисы setup работают с существующей test binding. Настоящий adult/managed доступ останется недоступен пользователю до реализации transport, полного lifecycle и необходимых условий запуска.
