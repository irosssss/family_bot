# G03-D — семейные привязки и серверные контексты

Версия 1.0, 2026-09-07. **Разрешён ответом «да». G3D01–G3D06 выполнены; результат на приёмку.** Вход — принятый [G03-C](G03_IDENTITY_EXCHANGE_RESULT.md). [Результат и границы проверки](G03_FAMILY_ACCESS_RESULT.md). Оба детских доступа остаются в MVP.

| ID | Конкретная работа | Приёмка |
|---|---|---|
| G3D01 | Закрытые записи/Drizzle access_bindings, session_contexts, session_token_verifiers; следующая append-only миграция | Composite FK удерживают family/profile/account/role; managed manager в той же семье и Account; один активный own_child. |
| G3D02 | Resolver семейного bearer и guard целей | Account/binding/profile/family активны; actor выводится из серверного контекста. Чужие familyId/profileId/actorId не расширяют права. |
| G3D03 | Выдача own_child session из действующего launch и уже существующей own_child-привязки | Атомарное потребление launch, один результат при гонке, один player/profile без стартовых подарков; не создаётся привязка по просьбе клиента. |
| G3D04 | Отдельная запись происхождения и verifier; отзыв сессии/привязки и потомков | Погашение старого bearer не равно отзыву parent lineage; явный отзыв закрывает производные контексты. Сохранённые покупки/прогресс не меняются. |
| G3D05 | Семейная транзакционная проверка и доказательства | Сериализация мутации с отзывом, отрицательные проверки чтения/команд, expiry, чужая роль, разные семьи, CAS/конкуренция. |
| G3D06 | Результат и следующая карточка взрослой защиты | Конкретный PIN/recovery setup, benchmark KDF и managed issuance до реализации, без «временно доверенного» PIN=true от клиента. |

Реализованные файлы: src/target/access/{familySession,familyAuthorization}.ts, отдельные db/schema/familyAccess.ts и contracts/familyAccess.ts, migrations/target/0004_family_access.sql, tests/target/family-access{,-postgres}.test.ts. Разделение схем сохраняет проверяемую базовую модель миграции 0003. Тесты — на собственной временной PG18.6 через существующий harness; никаких настоящих аккаунтов/семей.

Для проверки own_child используется явный кандидат SP05: 8 часов абсолютного срока. Adult grant5/30 минут, fresh PIN2 минуты и другие SP не становятся production-настройками этого блока. Сессии взрослого/managed допускаются только как явно вставленные тестовые fixtures для проверки отказов, границ и отзыва; их реальная выдача остаётся закрытой до взрослой защиты. Никакого публичного endpoint с подставляемым доказательством PIN.

Создание настоящих семей/привязок, приглашения, собственный/общий UI входа, бот, публичный API и запуск с реальным BOT_TOKEN не входят. Приложение на localhost:3000 остаётся демо; доступность проверяется отдельно. Весь G03 этим блоком не закрывается. Следующее разрешение — [G03-E](G03_ADULT_PROTECTION_CARD.md).
