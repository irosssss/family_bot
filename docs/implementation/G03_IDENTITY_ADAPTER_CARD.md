# G03-B — проверяемый адаптер Telegram identity

Версия 1.0, 2026-09-07. **Разрешена сообщением «хорошо, тогда продолжим». G3B01–G3B06 реализованы и проверены; [результат на приёмку](G03_IDENTITY_ADAPTER_RESULT.md).** Основа: [протокол G03-A](../security/ACCESS_PROTOCOL.md), [параметры и тесты](../security/ACCESS_VALIDATION.md). Это первый технический блок G03, не вся авторизация и не выпуск входа. Следующий этап — [G03-C](G03_IDENTITY_EXCHANGE_CARD.md).

## 1. Конкретный результат

Чистый target-адаптер принимает initData и явно переданные expected bot/key/clock/policy. Возвращает закрытую проверенную identity либо ошибку по ключу. Не читает process.env сам, не создаёт Account/сессию и не выдаёт семейных прав. Срок свежести не выдаётся за защиту от повторного обмена.

| ID | Изменение | Доказательство |
|---|---|---|
| G3B01 | Строгий query parser в src/target/access/telegram | Лимиты, дубли после декодирования, malformed UTF-8/percent, CR/LF, единственный hash; GAT02/GAT03/GAT05. |
| G3B02 | Канонизация и HMAC verifier | Независимые RFC и golden vectors; корректная работа с JSON escaping/Unicode/signature; GAT01/GAT02/GAT04. |
| G3B03 | Проверка auth_date/user и закрытая identity projection | Внедряемые clock/policy, положительный безопасный integer user.id → строка subject; no role/семья из Telegram. |
| G3B04 | Изоляция и ошибки | Нет bot/DB/env side effects, утечки raw input/key; неподдержанная конфигурация отклонена. |
| G3B05 | Тесты и регрессия | Target typecheck/build, релевантные тесты и существующая регрессия; негативные случаи и фиксированные ожидаемые байты. |
| G3B06 | Отчёт и следующая карточка | Предел доказательства, открытый replay-exchange/session этап, конкретный состав его schema/handlers/tests до исполнения. |

Местоположение новых файлов: src/target/access/telegram, tests/target/telegram-identity.test.ts, документ результата. Точечные дополнения общих закрытых контрактов допустимы, если нужны адаптеру. Новые зависимости не устанавливаются без необходимости и проверки; ожидается использование имеющейся Node crypto.

## 2. Что не входит

Дефект src/utils/telegramAuth.ts исправлен по отдельному прямому поручению пользователя; [результат и HTTP/socket проверки](../security/TELEGRAM_AUTH_FIX.md). Это не реализация target-адаптера. Нельзя незаметно направить старый UI на новое ядро.

Ни реальные bot tokens, ни собственные Telegram-аккаунты, ни отправка сообщений, ни публичные auth endpoints, ни новая БД/миграция доступа не нужны G03-B. Работа проводится на синтетических примерах с тестовым ключевым материалом, создаваемым в памяти, без сохранения секретов или обращения к внешнему боту.
