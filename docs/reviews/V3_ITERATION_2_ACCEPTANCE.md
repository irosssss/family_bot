# V3 — сценарии приёмки второй итерации

> Исторический отчёт этапа. Актуальная основная версия и правила — [V3](../V3_BASELINE.md). Прежние номера страниц и промежуточные решения не использовать как текущие указания.

Скриншот подтверждает внешний вид. Read-back реакций подтверждает наличие перехода, но не исполнение выражения в Present. Ручной проход в браузере не подтверждает серверную безопасность. В итоговом отчёте эти уровни перечисляются отдельно.

Цены приняты для прототипа. Пример8монет и демонстрационный начальный баланс не являются новым тарифом/стартовым подарком.

## Результаты приёмки

| Критерии | Результат и доказательство |
|---|---|
| S01–S10 | PASS в объёме прототипа: личные Present-проходы главного агента, дополнительно read-back симуляция агента. S06 проверен лично повторным открытием; защита старой кнопки подтверждения — симуляцией. |
| S11 | PASS: цены и7 маршрутов проверены агентом в симуляции; главный лично проверил базовый02 и зимний, прочитал все7 ветвей применения. |
| A01, A03 | PASS: личный Present и граф. Реальные начисления не тестировались. |
| A02 | PASS по read-back: исполнитель и проверяющий разделены, из принятия только пустая очередь. Положительная ветка Алексея отдельно в Present главным не проходилась. |
| A04 | PASS для разделения контекстов по графу/текстам. Полная детская проверка остаётся в итерации1. |
| E01, E03, E04 | PASS для макетов и графа. PIN/права/серверные ответы не валидируются Figma. |
| E02 | PASS: личный Present claim→pending, закрытый граф ожидания; собственный вход — структурная проверка. |
| A05 — возврат | PASS: главный лично прошёл пояснение/возврат Алексея и отдельную повторную отправку Марины. |

Первоначальный FAIL магазина сохранён в истории итогового отчёта; повторная проверка выполнена после исправлений. Перечисленные PASS не распространяются на backend, сохранение после перезапуска или весь продукт.
