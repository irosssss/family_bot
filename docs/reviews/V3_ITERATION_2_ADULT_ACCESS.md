### Соответствие HTTP

| UI | Протокол |
|---|---|
| Кнопка «Отправить заявку» | invitation/claim с launch credential; зафиксированный кандидат |
| Экран ожидания | lifecycle/read с candidate credential; только статус |
| Марина сверяет человека и вводит PIN | lifecycle/inspect + invitation/approve; request/revision/candidate фиксированы |
| «Подключить мой вход» / «Подключиться и настроить PIN» | invitation/consume; approved само по себе не даёт чтение семьи |
| PIN и повтор PIN | setup/prepare |
| Код + ввод из сохранённой копии | setup/acknowledge с recovery_code; не один checkbox |
| Обычный взрослый вход | session/login |
| Личный вход ребёнка | session/own-child |
| Передача устройства/возврат | session/switch с PIN; старый контекст погашается в реальном протоколе |

PIN, приглашение, recovery-код и Telegram handles являются демонстрационными примерами. DEMO-RECOVERY-NOT-VALID заведомо не настоящий секрет. Кнопки воспроизводят заранее выбранный успешный ответ, не проверяют подпись, PIN, сохранение кода или членство. Об этом явно написано на внешнем пульте; технические пояснения убраны из пользовательских экранов.
