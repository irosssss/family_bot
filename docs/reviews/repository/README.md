# Разбор файлов относительно V3 — 22.09.2026

V3 — единственная принятая основа дальнейшей разработки. Категория файла не определяет
новую версию продукта. Проверка выполнялась по текущему рабочему дереву, включая незакоммиченные изменения.

## Что проверено

- Статические import/export, буквальные import() и require через TypeScript resolver.
- Деревья `src/v3/V3App.tsx`, `src/main.tsx`, `server.ts`, scripts/target и примерочной.
- Потребители общих модулей, публичные URL и настройки сборки.
- Байтовое SHA256-сравнение копий public в двух существующих сборках.
- Основание архивирования визуального V2: фиксация V3 и последующий выбор яркого оформления.

## Важная обнаруженная зависимость запуска

В src/main.tsx V3 выбрана при import.meta.env.DEV без legacy=1. Production всё ещё
рендерит App; demo=legacy включает прежнее демо. server.ts отдаёт dist в production.
Это долг переключения реализации, а не основание считать прежний продукт целевым.
В этом аудите поведение входа/авторизации не менялось. Для переключения production на V3
сначала нужны реальный вход и серверное сохранение; локальную тестовую семью нельзя
случайно выдать за готовый публичный сервис.

## Сборки и дубликаты

SHA256 подтверждено: dist содержит16971 копию public, dist-wardrobe-pilot —17002.
Среди сравнимых файлов отличий нет. Остальные11 и3 файлов — сборочный/служебный вывод,
не объявляются дубликатами. Детали: build-copies.json. Логический объём двух деревьев

Воспроизведение: `npm run build`; примерочная: `npx vite build --config vite.wardrobe.config.ts`.
Перед очисткой проверить, что соответствующая сборка не обслуживает запущенный preview/server.
Пока обе сборки сохранены. dist-wardrobe-pilot добавлена в gitignore, как основной dist.

## Реестр и границы вывода

- source-files.csv — конкретные исходники, документы, настройки и прямые потребители.
- summary.json — числа по категориям и полное статическое дерево V3.
- work/repository-audit/files.csv — полный реестр, включая десятки тысяч ассетов/копий.
- Повторить: `node scripts/maintenance/inventory.mjs`.

`review_required=true` означает «не доказано, что безопасно архивировать/удалить».
Для public категория active означает включение в публичное дерево сборки, а не доказательство
показа каждого изображения. Динамические пути ULPC/питомцев нельзя оценить одним поиском импортов.
Для не достигнутых графом исходников категория prepared означает консервативное сохранение
до адресной проверки, не обещание включить их в V3. Реестр не является списком на удаление.
Наличие файла в work/output также не доказывает его бесполезность.

Никакие исходники приложения, исходные изображения, сохранения, БД и планы не удалены.
