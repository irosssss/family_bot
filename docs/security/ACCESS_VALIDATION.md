# G03-A — параметры, тесты и нерешённые вопросы доступа

Версия 0.2, 2026-09-07. **Параметры остаются кандидатами; не production-настройки. Статусы проверок обновлены по G03-D.** Дополняет [ACCESS_PROTOCOL](ACCESS_PROTOCOL.md). Рекомендации OWASP задают принципы, но не утверждают выбранные ниже сроки именно для семейной игры.

## 1. Параметры-кандидаты

| ID / параметр | Предложение для первого прототипа | Основание и последствия |
|---|---|---|
| SP01 / telegram_init_max_age | 300 секунд; допустимое опережение серверных часов 30 секунд | Сокращает окно предъявления украденного материала. Не срок игровой сессии. Старый 24-часовой лимит не переносится автоматически. |
| SP02 / init_data_limits | 16 KiB UTF-8, до 64 уникальных полей | Ограничение до разбора/криптографии; проверка на поддерживаемых клиентах до пилота. Дубликаты и неверное кодирование отклоняются. |
| SP03 / identity_exchange_receipt | Уникален по bot/environment/hash; хранить как минимум до auth_date + SP01 + допуск часов | Фиксация в той же транзакции, что AccessLaunch. Перестановка query не создаёт новый обмен. Исходный initData не сохраняется. Cleanup позже безопасен, раньше — нет. |
| SP04 / access_launch_ttl | 10 минут, без семейных данных и без автоматического adult grant | Хватает на выбор входа/настройку; длинное восстановление создаёт свой ограниченный challenge. |
| SP05 / family_session_absolute_ttl | 8 часов; для managed — не позже expires_at записи родительского источника | Ограниченный период игры без постоянного повторного входа; нет бесконечного скользящего продления. После истечения новый вход. |
| SP06 / adult_grant | Неактивность 5 минут, абсолютный срок 30 минут | Уменьшает окно оставленного устройства. Проверяется сервером. Обычная детская игра не продлевает взрослый grant. |
| SP07 / sensitive_confirmation_age | Не старше 2 минут; привязка к конкретному действию/цели и ожидаемой revision | Приглашение/recovery/архив/чувствительный отзыв требуют отдельного актуального намерения. Подтверждение одноразово для команды; идемпотентный повтор возвращает прежний несекретный результат. |
| SP08 / session_entropy | 32 криптографически случайных байта, opaque bearer в памяти вкладки | UUID сессии не bearer. Сервер хранит verifier с типом/версией и защищает token store. Ротация при смене режима/защиты. |
| SP09 / PIN | Ровно 6 ASCII-цифр, начальные нули сохраняются | Уже принято A04. Проверка только после identity, для своего adult membership; не самостоятельный публичный вход. |
| SP10 / PIN attempts | 5 неверных проверок за скользящие 15 минут → пауза 15 минут; максимум 20 за 24 часа → запрет новых PIN-попыток до освобождения окна | Счётчик по protection_id, не сбрасывается новой вкладкой/сессией/IP. Успех не удаляет суточную историю попыток. Recovery остаётся отдельным путём. Нельзя отзывать действующие детские сессии за чужие попытки. UX/DoS подлежит пилоту. |
| SP11 / KDF | Argon2id: 19456 KiB, t=2, p=1; индивидуальный случайный salt; отдельный pepper | Минимальный кандидат; измерить нагрузку и конкурентность до выбора пакета/запуска. Версия KDF и pepper key ID хранятся с verifier; значения ключей не в БД. |
| SP12 / invitation | 24 часа от выдачи, claim не продлевает; secret 32 случайных байта | Взрослый может пересоздать истёкшее приглашение. Secret не заменяет финальное одобрение кандидата. |
| SP13 / recovery request | 30 минут; authorized completion grant — 5 минут и не позже expires_at запроса | Нельзя держать одобрение бессрочно; чувствительная смена проверяет candidate/protection revision при commit. |
| SP14 / recovery code | 160 случайных бит, 32 Base32-символа с группировкой и отдельным checksum | Одноразовый при recovery; показывается один раз, хранится вне доступного ребёнку устройства. Планового календарного срока пока нет: это не отменяет отзыв при выходе/ротации/удалении и обязательную retention-политику. |
| SP15 / recovery attempts | 5 неверных кодов за 30 минут на credential locator + verified candidate; дополнительный лимит по locator независимо от кандидата | Смена аккаунта не обнуляет защиту. Общие ответы, отдельный путь второго взрослого. Установить окончательные сетевые/общесервисные лимиты по нагрузочному тесту. |
| SP16 / revoke-other-sessions | Не чаще одного успешного отзыва пары инициатор/цель за 5 минут; повторы той же operation идемпотентны | Снижает злоупотребление A15, не превращает временный отзыв в исключение человека. Остальные действия взрослого не блокируются этой квотой. |
| SP17 / pending setup | 10 минут для завершения PIN/recovery-кода; по истечении — новый проверенный запуск/setup | После recovery потеря ответа не возвращает старые секреты. До завершения настройки нет adult/managed полномочий. |

SP01–SP17 хранятся в версионированном SecurityPolicy, а не разбросанными литералами по handlers. Способ KDF/transport — зарегистрированная реализация, не произвольный исполняемый код из policy. Изменение policy определяет, какие действующие сессии/подтверждения немедленно инвалидируются; старый policy_id не гарантирует сохранение ослабленных прав.

Предлагаемые меры управления сессиями — случайные идентификаторы, серверные сроки, ротация и отзыв — согласуются с [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Выбор хранения bearer в памяти и конкретные значения выше — наши проектные решения. Потеря bearer при reload означает новый вход; это осознанный компромисс MVP до отдельного протокола безопасного возобновления.

## 2. Сроки security-состояния и retention — разные задачи

| Данные | Что можно определить технически сейчас | Что пока открыто |
|---|---|---|
| InitData/PIN/bearer/recovery plaintext | Не писать в логи, БД игр или аналитику; держать только в нужной краткой операции/памяти | Контроль внешних SDK и observability до выпуска. |
| Replay receipt / попытки / короткие grants | Не удалять до конца окна защиты; cleanup после expiry; атомарность между процессами | Окончательная политика security-логов, основание/минимизация IP-данных. |
| Account/семейная привязка/участие | Явные retention_policy_id/revision, без неявного «вечно» | O01/O09: страны, возраста, основания, сроки, удаление и backup suppression. |
| Audit решений/восстановления | Минимальные внутренние ссылки и outcome keys, без секретов | Срок хранения, доступ персонала, экспорт/удаление и поддержка. |
| Recovery verifier | Действует до потребления/ротации/отзыва; не в публичных проекциях | Retention после прекращения участия; календарная ротация только отдельным решением. |

Короткие TTL безопасности не являются юридически достаточной политикой персональных данных. Здесь не делается юридический вывод о допустимости запуска. Реальные сроки хранения не выбираются по языку интерфейса или региону разработчика.

## 3. Матрица будущих тестов

Исходно все GAT были специфицированы без исполнения. После [G03-B](../implementation/G03_IDENTITY_ADAPTER_RESULT.md): GAT01–GAT03/GAT05 проверены в границах чистого адаптера; GAT04 частично (deployment/реальные среды ещё не проверены). После [G03-C](../implementation/G03_IDENTITY_EXCHANGE_RESULT.md) GAT06 проверен на уровне service/БД. После [G03-D](../implementation/G03_FAMILY_ACCESS_RESULT.md) GAT07/GAT08/GAT09 проверены на уровне отказов issuer/resolver/guard, без onboarding HTTP, home-проекции и настоящих игровых начислений. GAT10/GAT11/GAT14 частично проверены на контекстах/fixtures: токен отдельно от lineage, parent grant/expiry/revoke, public ID, CAS. Настоящий PIN, переключение UI, recovery и остальная матрица остаются будущими. Тесты G02 не подменяют эту матрицу.

| ID | Сценарий | Ожидаемое доказательство |
|---|---|---|
| GAT01 | Независимый HMAC-vector + Telegram golden bytes | Принимается ожидаемая подпись; signed fixture не формируется тестируемым signer. |
| GAT02 | Unicode, %, +, &, percent casing, экранирование JSON, signature | Разбор один раз, строки JSON не пересериализуются; кодирование транспортного query не меняет каноническое значение. |
| GAT03 | Duplicate hash/auth_date/user/декодированные ключи, malformed UTF-8, CR/LF | Отказ до identity; нет first/last-value обхода. |
| GAT04 | Чужой ключ/бот/среда, бит подписи, неизвестный алгоритм | Отказ; отсутствие ключа не включает demo; нет HMAC→Ed25519 fallback. |
| GAT05 | Границы auth_date/входных лимитов и неверный user.id | Fake clock; включение/исключение границ определено; дробь/строка/unsafe integer не становится subject. |
| GAT06 | Конкурентные обмены, переставленные пары, повтор после expiry | Один receipt/launch; отказ replay не зависит от сериализации query или экземпляра сервера. |
| GAT07 | Verified identity без binding | Семья/детские записи недоступны; только ограниченный onboarding/challenge. |
| GAT08 | Свой child binding и чужой profileId/familyId/actorId | Нет чтения/действий другого ребёнка; дома возвращается минимальная проекция. |
| GAT09 | Parent profile в игровых командах | Нет личного начисления/покупки как ребёнку; административные команды отдельно. |
| GAT10 | Adult→managed→другой ребёнок/adult | Старый bearer погашен, новое взрослое подтверждение обязательно; старые вкладки/очереди не действуют от нового ребёнка. |
| GAT11 | Parent grant истёк, managed session ещё действительна | Детская игра продолжается до своего срока; взрослые действия запрещены. Явный revoke источника прекращает managed. |
| GAT12 | Reload/закрытие/фон/возврат, отсутствие событий закрытия | UI не восстанавливает adult grant; серверные сроки работают без доверия к клиентскому таймеру. |
| GAT13 | PIN с начальным нулём, неизвестный PIN, параллельный перебор/рестарт | Строковый формат, общий атомарный лимит, отсутствие сброса сменой сессии/IP; recovery не блокируется чужой атакой PIN. |
| GAT14 | Кража session ID, истёкший bearer, rotation | Public ID не аутентифицирует; прежний bearer не проходит после переключения/ротации. |
| GAT15 | Два кандидата/два одобряющих одного приглашения | Один неизменный кандидат/consumption/binding; второй не получает семейные данные. |
| GAT16 | Истёк/отозван invite, вышел issuer, архивирован target | Нельзя потребить; profile/player/gifts не создаются заново. |
| GAT17 | Recovery-код использован дважды/одновременно | Один completion, старый код/сеансы недействительны; новая настройка обязательна. |
| GAT18 | Подмена recovery candidate/другая семья/устаревшее одобрение | Отказ; identity по чужому Telegram не переназначает глобально права всех семей. |
| GAT19 | Потеря ответа после recovery commit | Старые credentials не возвращаются; повтор ограниченного setup не открывает полноценный adult access. |
| GAT20 | Нет кода/второго взрослого | Нет обхода по имени/балансу/скриншоту или открытой Telegram-сессии. |
| GAT21 | Revoke own_child / revoke adult descendants / independent access | Отзывается нужная ветвь; другой взрослый, собственный вход ребёнка и покупки сохраняются. |
| GAT22 | Команда одновременно с revoke/выходом последнего взрослого | Семейная блокировка задаёт порядок; нельзя оставить семью без допустимого управления или провести команду после отзыва. |
| GAT23 | Чужой origin/redirect/CORS, XSS в имени, секрет в telemetry | Credential не уходит на другой origin; UGC не исполняется; логи проходят redaction-проверку. |
| GAT24 | Оба входа iOS/Android/Telegram Web на целевых устройствах | Реальные разрешённые клиенты, background/reload, отсутствие обязательной зависимости от third-party cookies. До O13/тестового бота — не PASS. |

## 4. Что нужно подтвердить, и что это блокирует

| Вопрос | Чьё решение / требуемое доказательство | Блокирует | Можно делать независимо |
|---|---|---|---|
| Принять SP01–SP17 и технические уточнения session/launch | Пользователь после просмотра последствий; параметры остаются кандидатами | Код зависимых session/PIN/invite/recovery flows | Pure verifier с явно внедряемыми тестовыми параметрами. |
| Страны и возрастные группы O01 | Владелец продукта; затем отдельная проверка условий платформы/правил запуска | Реальная регистрация и запуск для этих групп | Синтетические контрактные тесты. |
| Retention/согласия/оператор O09 | Условия запуска и ответственное решение; при необходимости профильная проверка | Production identity/audit и обработка настоящих семей | Временные тестовые записи с очисткой всей БД. |
| Домены, тестовый бот, secret-store, deployment | Проверяемая среда и явное разрешение её использования | Живой Telegram end-to-end, TLS/CORS/secret rotation | Локальные примеры и tests без реального токена. |
| Поддерживаемые клиенты/устройства O13 | Список и фактические проверки GAT24 | Обещание общей совместимости | Основной протокол и серверные unit/DB tests. |
| Выбор Argon2id-пакета и бюджет KDF | Проверка поддержки runtime, лицензии/обновлений, benchmark | Реальный PIN verifier | Интерфейс ProtectionVerifier/лимитер без secret material. |

## 5. Результат G03-A

G3A01–G3A08 из карточки покрыты протоколом, параметрами и GAT01–GAT24. Проверены локальные исходники и первичные технические источники; выполнен один синтетический диагностический пример канонизации. Изменения runtime, настоящих БД, секретов, графики и запуска браузера отсутствуют. Lint/игровые тесты не перезапускались: в этом этапе менялись документы, а не код приложения. Проверены 87 локальных ссылок в восьми документах, отсутствующих целей нет; git diff --check прошёл.

После этого G03-B разрешён и [реализован](../implementation/G03_IDENTITY_ADAPTER_RESULT.md). G03-C затем [выполнен](../implementation/G03_IDENTITY_EXCHANGE_RESULT.md); следующий блок на разрешение — [G03-D](../implementation/G03_FAMILY_ACCESS_CARD.md). Последующие session/access/invite/recovery blocks выделены отдельно; оба способа входа остаются в MVP, а спецификация G03-A не объявляется всей выполненной авторизацией.
