# ARTEMIS: пилот Telegram Mini App

Статус: по выбору владельца 21.09.2026 сейчас только сценарии и инструкция;
установка и запуск отложены. Ни один сценарий ниже не выполнен через ARTEMIS.
Это спецификация проверки, не готовый исполняемый тест и не отчёт PASS.

## Условия старта

- Выбран отдельный Android-эмулятор или тестовый телефон и точный serial.
- Установлены Python >=3.12, uv, ADB и изолированное окружение ARTEMIS по
  `371aa6df56880643da57b30da936e9812fb0ec66` либо заново проверенной версии.
- Выбран провайдер, доступ и бюджет; ключи инжектируются через envskill, не в Git.
- `artemis doctor` и наблюдение устройства успешны; проверена конфигурация внешних
  уведомлений. Автоматическую установку helper учитывать до первого запуска.
- Установлен тестовый Telegram, выбран тестовый бот и доступный устройству URL.
  Адрес localhost на Mac не является автоматически адресом Mac с телефона.
- Используется синтетическая семья; перед записью отсутствуют личные уведомления.

Предпочитать целевую конфигурацию MCP только для выбранного клиента. Не запускать
`mcp --install all` и не добавлять Android rules глобально всем проектам по умолчанию.
Использовать официальный `mcp --generate-config codex` после установки, проверить
абсолютные пути к venv и cwd. Настройка MCP сама по себе не доказывает доступ к телефону.

## Набор проверок

| ID | Сценарий | Критерий | Доступность |
|---|---|---|---|
| A01 | Открытие и навигация | Экран загружен; CTA доступны; нет горизонтального обрезания | После настройки URL/Telegram |
| A02 | Дело с проверкой | Выполнение → pending; награды до одобрения нет | Локальный V3; отдельно подтвердить в WebView |
| A03 | Дело без проверки | Однократная награда; повторный тап не удваивает её | Локальный V3; проверить ledger |
| A04 | Reload и возврат из фона | Состояние согласовано, команда не повторяется | Local persistence не считать server persistence |
| A05 | Длинная форма и клавиатура | Поля/CTA доступны; modal scroll и Back предсказуемы | Нужен реальный Android/WebView |
| A06 | Гардероб | Выбранный образ сохранён и согласован на связанных экранах | Только реализованные образы; волосы-пилот отдельно |
| A07 | Недостаточно монет | Покупка невозможна; баланс не меняется; причина понятна | Синтетический баланс |
| A08 | Семейные роли | Нет исполнения чужих дел; собственное дело взрослого по V3 | UI-проверка не доказывает server authorization |
| A09 | Реальный вход/приглашение | Доверенная сессия и корректные границы семьи | BLOCKED до подключения onboarding/backend |

Для каждого: записать исходный fixture, шаги, ожидаемые значения, фактические
значения и trace/screenshots. Не брать предположительные coordinates из макета.
При неудаче выяснить: ошибка теста, недоступная среда или дефект приложения.

## Первый пробный запрос после готовности стенда

```text
На выбранном тестовом Android открой заранее заданный тестовый Mini App.
Исследуй экран и навигацию без покупок и изменения реальных данных.
Проверь видимость основного действия, нижней навигации и отсутствие обрезания.
Сохрани начальное и конечное наблюдение, trace ID и фактический результат.
Если URL, авторизация или экран недоступны, сообщи точный блокер.
```

После smoke выбрать один сценарий с мутацией синтетических данных и явными
проверками. Flash подходит для короткой разведки; Pro — для checkpoint-проверок
и диагностики. Ограничить длительность пилота; режим unlimited не считать бюджетом.

## Приёмка интеграции

MCP доступен в клиенте; doctor готов; A01 и минимум один сценарий состояния
выполнены с проверяемыми артефактами. Остальные сценарии отмечены отдельно.
Android-пилот не закрывает iOS, production-допуск, серверную авторизацию или весь QA.
