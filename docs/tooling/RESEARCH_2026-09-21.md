# SoL-Pi, Inspo, ARTEMIS и AI Studio: исследование и внедрение

Дата проверки: 21.09.2026. Область: инструменты разработки и проверки проектов;
продуктовые правила Family Chores RPG не меняются.

## Решение

| Ресурс | Назначение | Применение | Фактический статус |
|---|---|---|---|
| SoL-Pi | Экономия работы агентного harness Pi | Заимствовать дисциплину работы с доказательствами; сам движок — отдельный эксперимент | Изучен, не установлен |
| Inspo | Поиск визуальных референсов через MCP | Новые направления и неизвестные паттерны; существующая дизайн-система важнее | Добавлен в Codex; HTTP handshake, tools/list и recommend проверены |
| ARTEMIS | Управление Android и диагностика | Проверки Telegram/WebView на отдельном тестовом устройстве | Изучен; сценарии подготовлены, устройство и runtime не настроены |
| AI Studio guide | Методика улучшения UI и инструменты визуального редактирования | Референсы → дизайн-контракт → точечная итерация → проверка | Методика перенесена в рабочий процесс; проект в AI Studio не импортирован |

Это не четыре зависимости приложения. Они относятся к разным этапам работы и не
должны попадать в production bundle или package.json игры.

## 1. NVIDIA SoL-Pi

[README](https://github.com/NVlabs/SoL-Pi),
[configuration](https://github.com/NVlabs/SoL-Pi/blob/main/docs/configuration.md),
[compatibility](https://github.com/NVlabs/SoL-Pi/blob/main/docs/compatibility.md),
[security](https://github.com/NVlabs/SoL-Pi/blob/main/SECURITY.md).
Дерево исходников зафиксировано на `bd005888b9b8a3fcdb511feb91fc27d3dfa8f2b1`.

Это расширение независимого coding agent Pi, а не MCP-сервер и не расширение Codex.
Текущая документация требует Node >=22.19 и рекомендует Pi 0.85.1. На машине
Node 24.16.0; команда `pi` не найдена в PATH. MIT-лицензия относится к коду.

Четыре механизма:

- **Action Fusion:** редактирование и последующая проверка в одном вызове инструмента.
- **ObservationPack:** большие повторяющиеся наблюдения заменяются ссылками с точным
  постраничным восстановлением исходника.
- **Evidence-Preserving Reducer:** длинный диагностический вывод сокращается с проверкой
  цитат по архиву; при неудаче сохраняется исходный результат.
- **Online Context Compact:** сжатие на границах завершённых этапов с оценкой окупаемости
  и давления на контекст, затем продолжение задачи.

По умолчанию механизмы выключены. Настройки доверенного проекта заменяют глобальные,
а не объединяются с ними. Поэтому файл в проекте способен неожиданно изменить набор
включённых функций. Официальная процедура all-enabled — отдельный режим установки,
а не обязательное условие обычного использования.

В compatibility описаны ограничения: очередь Action Fusion не блокирует сторонние
процессы; между изменением и командой проверяется хеш файла. Transformer другого
расширения, загруженный позже, может выйти за пределы оценки контекста. Число тестов
upstream подтверждает их собственную проверку совместимости, но не экономию у нас.

Дополнительно прочитан `online-context-compact/economics.ts`: решение учитывает
горизонт оставшихся запросов, стоимость записи/чтения кэша и долг предыдущего сжатия.
Поэтому «чаще сжимать» не равно «дешевле». Коэффициент в конфигурации не является
измеренным процентом экономии и не обновляется автоматически при смене модели.

Reducer может передавать логи выбранному внешнему провайдеру. Детектор вероятных
секретов не гарантирует очистку данных. Архивы остаются на диске после завершения
сессии; расширение использует полномочия Pi и не создаёт sandbox.

**Наше применение:** сохранять исходные логи, сообщать краткий результат с путём и
exit code, читать нужные диапазоны вместо повторения всего вывода. Это рабочая
дисциплина, не реализация ObservationPack внутри Codex. Внутреннее сжатие Codex этим
исследованием не изменено.

**Условие отдельного пилота Pi:** одинаковые задачи на изолированных checkout,
одинаковая модель и критерии приёмки; сравнивать стоимость, время, повторные проверки
и долю завершённых задач. Начать с Action Fusion и ObservationPack. Включение reducer
требует выбранного провайдера и подходящих для передачи логов. Не подключать Pi к
текущему грязному working tree как второго одновременного редактора.

## 2. Inspo MCP

[Репозиторий](https://github.com/Nutlope/inspo),
[инструменты и установка](https://github.com/Nutlope/inspo/blob/main/apps/mcp/README.md),
[исходник installer](https://github.com/Nutlope/inspo/blob/main/apps/mcp/src/install.ts).

Архив сайтов содержит скриншоты, палитры, шрифты, структуру страниц и примеры
компонентов. Он помогает формулировать дизайн-направление, но не проверяет удобство
нашего интерфейса и не знает продуктовых правил.

`npx inspo-mcp install` — установщик конфигурации клиентов. Поддерживает dry-run и
выбор клиента; без ограничения способен предложить настройку нескольких IDE.
Для Codex исходник installer использует `codex mcp add`. Выполнен тот же штатный
путь напрямую:

```bash
codex mcp add inspo --url https://inspomcp.dev/api/mcp
codex mcp get inspo
```

Результат: глобальный сервер `inspo`, enabled=true, Streamable HTTP, без токена.
Это настройка текущего пользователя Codex, доступная проектам этого профиля;
не настройка других компьютеров или IDE. В текущем каталоге инструментов сессии
Inspo ещё не появился: MCP нужно перезапустить/переподключить в приложении.
Проверка протокола выполнена отдельно HTTP-запросами, не нативным tool call Codex.

Фактическая проверка: `initialize` вернул `hosted-85acb10`; `tools/list` — 15
инструментов; `recommend` успешно обработал общий brief мобильного планировщика.
Код, логи, имена участников и данные семьи не передавались.

Для практики достаточно `recommend`, `search_screens`, `get_screen`,
`get_design_system`, иногда `compare`. Параметр `device: mobile` ограничивает поиск
записями с мобильным снимком; `maxTokens` сокращает выдачу. Реальные схемы сохранены
в `work/tooling-research-2026-09-21/inspo-tools.json`.

**Обнаруженное ограничение:** тестовый brief про семейные дела вернул Marquee Hero
и сайт дизайн-студии General Condition. Это свидетельство смещения подборки в сторону
маркетинговых сайтов, а не подходящий шаблон TodayPanel. Ответ также предлагает
крупные межсекционные интервалы: переносить их на экран 375px без адаптации нельзя.
Пилот подтвердил работоспособность поиска, но не качество готового игрового UI.

Hosted endpoint не требует ключа по текущей документации и фактическому handshake.
Заявленная бесплатность не гарантирует будущий SLA. MIT-лицензия кода не означает
свободное присвоение чужих скриншотов, брендов и изображений. Источник референса
сохраняем, используем принципы композиции и собственные ассеты.

Откат подключения: `codex mcp remove inspo`. Само приложение игры не затронуто.

## 3. Google ARTEMIS

[README](https://github.com/google/artemis),
[MCP](https://github.com/google/artemis/blob/main/mcp_server/README.md),
[testing rules](https://github.com/google/artemis/blob/main/mcp_server/rules.md),
[зависимости](https://github.com/google/artemis/blob/main/pyproject.toml).
Дерево исходников: `371aa6df56880643da57b30da936e9812fb0ec66`.

ARTEMIS выполняет действия на Android по текстовому заданию, использует дерево
доступности и визуальное наблюдение, сохраняет диагностические материалы. Для нас
ценен именно настоящий Telegram WebView: клавиатура, Back, сворачивание и возврат,
safe area и реальные размеры экрана. Это дополнение к TypeScript/domain/DB тестам.

Flash — простой цикл наблюдения и действия. Pro добавляет планирование и проверку
контрольных точек, диагностику; он дороже по времени. README заявляет 99%+ на
AndroidWorld, но это результат авторов на отдельном benchmark, не прогноз для
Family Chores RPG. iOS указан в roadmap; Android-проверка не покрывает iPhone.

Требования: Python >=3.12, окружение зависимостей, ADB, авторизованный Android или
эмулятор, настроенный модельный backend. В текущем PATH нет `adb` и `uv`; наличие
готового Android-стенда не подтверждено. Исходник `start.sh` автоматически ставит
системные инструменты, синхронизирует Python-зависимости и предлагает глобальные MCP
и правила для IDE. Его не запускали. В pyproject есть много транзитивных зависимостей,
включая posthog; само наличие пакета не доказывает активную отправку телеметрии.

Первое задание может установить Accessibility Helper на устройство. Модельный
контур обработки скриншотов нужно отличать от локального helper: локальность helper
не означает локальность всей системы. Для пилота нужен тестовый аккаунт и синтетическая
семья, без личных чатов и уведомлений на экране.

Из правил заимствуем наблюдение до действия, явные проверки результата, устойчивые
локаторы и свежий скриншот перед координатным fallback. Не переносим весь rules.md
в глобальные инструкции: его Android-специфичные требования не подходят каждой
задаче. Тайминги проверяем реальными часами/условиями; среднюю задержку LLM нельзя
считать доказательством истечения таймера.

**Внедрение:** подготовлены [сценарии пилота](ANDROID_PILOT.md). Владелец выбрал
на этом этапе только сценарии и инструкцию; установка отложена. После выбора стенда:
изолированная установка по pinned revision, настройка провайдера через envskill,
doctor, подключение MCP, один smoke, затем критические сценарии. Без выбранного
устройства и провайдера установка не считается законченной. Авторизация и настоящее
серверное сохранение V3 ещё не подключены; тест не должен выдавать local demo за них.

## 4. Google AI Studio: восемь приёмов UI

[Статья Geneviève Huskens от 16.09.2026](https://aistudio.google.com/learn/ai-ui-design-google-ai-studio)
прочитана целиком через браузер; web extractor сначала вернул пустое содержимое.

Приёмы автора: извлечение стиля из референсов; согласованные изображения; локальное
редактирование изображений; проверка шрифтов; варианты оформления; настройка
конкретного элемента; удаление визуального шума по аннотациям; изучение Gallery Remix.
В статье генерация изображений связана с платным API-ключом. Никакая генерация или
платный вызов в AI Studio в этой работе не запускались.

**Наша адаптация:** сначала цель экрана и выбранный стиль, затем собственные ассеты,
сравнение 2–3 направлений только при открытом выборе, точечные правки и визуальная
проверка. Для кириллицы отдельно проверяем шрифтовое покрытие и длинные строки.
Заявление design engine о сохранении логики не заменяет наши regression tests.

AI Studio — опциональная среда прототипирования, не новая обязательная IDE.
Для текущего проекта сохраняем React/Vite, существующие Figma-экраны и принятое яркое
направление. Не начинаем очередной редизайн TodayPanel только ради новых инструментов.

## Проверка результата и границы

Проверено: источники, выбранные исходники, требования окружения, конфигурация Inspo
и реальный запрос рекомендаций. Внешние test suites SoL-Pi/ARTEMIS не запускались;
полный аудит безопасности их кода не проводился. Проценты экономии и качество Android
автоматизации на нашем проекте пока не измерены.

Рабочий процесс закреплён в [DEVELOPMENT_WORKFLOW.md](DEVELOPMENT_WORKFLOW.md),
ссылка добавлена в AGENTS.md. Его можно переносить в другие проекты с заменой
дизайн-контракта, команд проверки и платформы. Автоматического распространения
правил по всем репозиториям не было.
