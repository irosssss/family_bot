# Запросы изображений для Family Life V3

Добавлено 2026-09-09 по ссылке пользователя. Это рабочие инструкции и заготовки для будущего этапа графики; изображения этим изменением не создавались. Геометрия из [реестра](../../src/v3/assets/registry.ts) остаётся кандидатом до арт-проверки.

## Что берём из OpenAI Image Prompting

Запрос описывает назначение изображения, объект, композицию, материал/стиль и ограничения. Референсы имеют номера и явные роли. При редактировании отдельно перечисляются изменение и сохраняемые детали; за итерацию меняется один пункт. Результат проверяется, включая реальные прозрачные пиксели. Для сравнения моделей сохраняются одинаковые входы и настройки. Сначала достигается требуемое качество, затем оценивается скорость; точное сохранение пикселей одним запросом не гарантируется. [Официальное руководство](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5)

- **Flare** (`gpt-image-2.5-flare`) — кандидат для быстрых концептов; опубликованный snapshot `gpt-image-2.5-flare-2026-09-08`. [Модель Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)
- **Sunburst** (`gpt-image-2.5-sunburst`) — кандидат для сложного сохранения персонажа и точных правок; snapshot `gpt-image-2.5-sunburst-2026-09-08`. Обе модели допускают `auto/low/medium/high/xhigh/max`; уровень качества сам по себе не доказывает пригодность слоя. [Модель Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)

Для API размер/качество/формат задаются параметрами, отдельно от текста. Прозрачность: `background: transparent` и PNG/WebP. Пользовательский размер: стороны кратны 16, до 3840, отношение≤3:1, площадь 655360…8294400; свыше 3686400 пикселей — экспериментально. Поэтому 64×80 или 48×48 — будущий экспорт, не размер прямого запроса. [Параметры](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5#model-parameters)

## Как выполнять в этом рабочем пространстве

Обычная генерация/правка выполняется доступным инструментом `image_gen` по скиллу imagegen. Его текущий интерфейс не предоставляет аргумент выбора модели: название в тексте запроса не переключает движок. Добавление этого документа не означает подключение API или подтверждённый запуск GPT Image 2.5. Точный API/model-путь используется при соответствующем поручении, с проверкой доступного клиента и named-secret инъекцией через envskill. Не переносить устаревшие параметры bundled CLI автоматически на новую модель.

Для локальной правки сначала просмотреть исходное изображение. Передать известные локальные пути референсов; если нужного изображения нет по локальному пути — использовать поддерживаемую ссылку на недавние изображения разговора. Встроенному инструменту не приписывать отсутствующие параметры `size`, `quality`, `output_format` или выходного пути. Формат и прозрачность результата проверять в файле, выбранный вариант затем сохранять в проект.

## Применение к нашим ассетам

1. Выбрать один slot ID и одну задачу: художественный концепт, ресурс-кандидат, носимый слой или локальная правка. Полная картинка героя не считается комплектом отдельных слоёв.
2. Взять холст, anchor, safe bounds и layer order из конкретной ревизии профиля. Пока профиль не принят, оставить явные поля-кандидаты. Пропорции взрослого и ребёнка проверяются отдельно, без автоматического уменьшения взрослого.
3. Заполнить [заготовку](templates/ASSET_PROMPT.md). Style reference определяет художественный язык; geometry reference — размер тела, позу и контакты. Конфликт этих требований выявляется до партии изображений.
4. В вариантах одежды оставить персонажа/позу/контакты неизменными. Предмет в руке отделить на задний/передний слой по принятому профилю; превью покупки хранить отдельно от носимого ресурса.
5. Дом и уголок делать отдельными от героя/питомца. Уголок не запекает котёнка в фон. Игровой текст, HP, монеты, цены, кнопки и состояния фокуса остаются в DOM. В изображениях нет эмодзи.
6. Проверить читаемость в настоящем слоте на 375/390 px, не только увеличенный концепт. Выбранное направление V3 — мягкий детальный cartoon/chibi; не требовать pixel-art и не наследовать автоматически маленькие экспорты старой игры. Совпадение названного размера в prompt не доказывает правильность файла.

## Художественное направление после аудита референсов

Три референса от 09.09.2026 задают объёмную рисованную семейную fantasy-графику: крупные выразительные глаза, мягкое освещение, тёплое дерево, золото, листва и холодная даль. Первая заставка — предпочтительный ориентир композиции. Это не утверждение её пригодности как готового runtime-файла: полоса и подписи загрузки в ней запечены.

До партии принять style sheet и геометрический профиль на небольшом комплекте: одна взрослая и одна детская внешность, сменный костюм, предмет в руке, питомец и комната. Отдельно определить, какие части действительно заменяются слоями, а какие поставляются готовой сборкой. Список из 16 hero-ролей не требует генерировать 16 независимых изображений: без доказанной совместимости это создаёт лишние швы.

Идентичность героя описывается отдельным паспортом внешности: лицо, волосы, пропорции и обязательные признаки. Слова «мама», «папа» или роль администратора не заменяют выбранную внешность. Реестр `appearancePresetId`, SceneLayout и UI-тема предложены в [аудите](ASSET_ARCHITECTURE_AUDIT.md); они ещё не реализованы. Генерация PNG сама их не добавит.

## Заготовки конкретных заданий

Эти дополнения вставляются в основной шаблон после определения художественного профиля:

| Slot / задача | Содержание запроса | Проверка приёмки |
|---|---|---|
| `hero.adult` / `hero.child` | Один герой целиком, голова и ступни в кадре. Референс принятого тела и паспорт внешности; никакой мебели или питомца. Поза и точка опоры из профиля. | Силуэт читается в реальном слоте; 64×80 — прежний кандидат, HD-экспорт принимает пилот; портрет получается из той же внешности |
| `item.outfit` | Для превью — только одежда. Для носимого слоя — только нужная часть на полном холсте профиля, с прозрачным остальным полем. Референс тела задаёт форму | Превью не выдаётся за носимый слой; overlay совпадает с anchor, нет чужого тела в одежде |
| `pet.companion` | Один известный котёнок или щенок указанной стадии. Вид/стадия названы явно, без случайных альтернатив и деталей уголка | Силуэт в реальном слоте и принятом HD-экспорте; контакт с полом; тот же экземпляр на главной и в разделе героя |
| `home.room` / `pet.corner` | Отдельная сценическая основа 4:3. Зоны размещения и перекрытия по схеме; персонажи и питомцы отдельными слоями | Кандидат 320×240; фон не мешает будущим фигурам и кнопкам; проверены foreground и место контакта |

Пример узкой правки одежды: «В референсе 1 изменить только цвет куртки на цвет из утверждённой палитры. Сохранить тело, лицо, причёску, позу, контур куртки и все точки привязки. Куртка остаётся на полном холсте того же размера. Остальная область прозрачна». Это текст задачи, а не обещание точности экспорта.

## Конкретные задания для следующего художественного этапа

Ниже авторские проектные заготовки. Поля в угловых скобках требуют принятого значения; они не отправляются буквально. Для каждого задания указать отдельную запись попытки из шаблона. Чистая заставка и UI-рамка — новые предлагаемые ресурсы, которых пока нет в 14 runtime-местах.

### Чистая заставка из первого референса

```text
Задача: подготовить художественную основу загрузочного экрана Family Life.
Референс 1 — целевое изображение и источник композиции.
Сохранить верхнюю вывеску Family Life RPG, лица и внешность четырёх героев,
двух питомцев, дома, перспективу, освещение и общий характер рисунка.
Изменить только нижнюю область загрузочного интерфейса:
убрать нарисованную полосу, статус загрузки, совет, нижний ряд значков
и служебную подпись. Продолжить на их месте окружающий пейзаж.
Нижняя область должна оставаться спокойной для будущего живого текста
и индикатора. Не рисовать новую полосу, кнопки, проценты или подписи.
Сохранить полный исходный кадр и пропорции. Не добавлять персонажей.
```

Сначала проверить именно эту правку без одновременного изменения композиции. Затем отдельной итерацией подготовить адаптивный crop или расширение фона, если это нужно по макету 375/390. Сравнить лица и бренд с исходником: просьба сохранить их не гарантирует отсутствия дрейфа. Для заставки допустима цельная иллюстрация; для живого дома — отдельные сущности.

### Комната для независимой расстановки

```text
Назначение: основа домашней сцены Family Life, профиль <room-profile-r1>.
Референс 1 задаёт художественный язык тёплого рисованного fantasy-дома.
Референс 2 — утверждённая схема камеры и свободных зон пола.
Создать только <shell или конкретная задняя часть> на полном холсте профиля.
Оставить свободными точки <список anchors> для членов семьи и питомца.
Сохранить перспективу пола, направление света и масштаб дверей из схемы.
Не включать героев, питомцев, покупаемую лампу, текст или интерфейс.
Передний декор и размещаемая мебель будут отдельными ресурсами.
```

Передние части мебели ставить отдельным заданием. Само наличие пустого места на рисунке не создаёт anchor в коде: значения записываются в профиль и проверяются сборкой.

### Одна исходная внешность героя

```text
Назначение: базовая внешность <appearance-id> для профиля <body-profile-r1>.
Референс 1 определяет стиль. Референс 2 определяет принятую геометрию.
Паспорт внешности: <форма лица, волосы, кожа, отличительные признаки>.
Один персонаж в полный рост, <принятая поза и угол камеры>.
Голова, волосы, кисти и ступни целиком внутри safe bounds.
Опора ног и свободная кисть совпадают с отмеченными точками схемы.
Нейтральная базовая одежда <описание>. Настоящий прозрачный фон.
Не добавлять второго героя, питомца, предмет в руке, комнату и текст.
```

Результат сначала принимается как цельный кандидат. Разделять его на внутренние слои можно только по выбранной схеме совместимости, с проверкой собранного результата.

### Носимый костюм на принятой базе

```text
Назначение: <outfit-id>, носимая часть для <body-profile-r1>.
Референс 1 — неизменяемая геометрия утверждённого героя.
Референс 2 — художественный дизайн костюма, только его материалы и крой.
Создать только <конкретная роль одежды> на полном холсте референса 1.
Совместить плечи, талию и рукава с указанными точками профиля.
Сохранить позу, камеру и направление света.
Вне одежды — настоящая прозрачность; не добавлять чужое тело,
лицо, кисти, фон или предметы. Не обрезать прозрачные поля автоматически.
```

Если костюм требует иной позы, скрытых частей тела или сложной маски, пометить несовместимость. Не исправлять это случайным масштабированием runtime-слоя; принять новый профиль либо подготовленную сборку. Превью костюма для магазина выполняется отдельным заданием.

### Питомец отдельно от уголка

```text
Назначение: <species-id>, стадия <stage>, профиль <pet-profile-r1>.
Референс 1 задаёт внешность этого питомца; референс 2 — геометрию позы.
Один питомец целиком, включая уши и хвост; <принятая поза>.
Сохранить окрас, форму мордочки и направление света.
Опора совпадает с anchor профиля. Настоящая прозрачность вокруг фигуры.
Не включать лежанку, миску, игрушки, второго питомца, текст и интерфейс.
Контактная тень <отдельный ресурс или принятое правило профиля>.
```

### Деревянная растягиваемая рамка

```text
Назначение: декоративная рамка DOM-кнопки Family Life, <ui-profile-r1>.
Референс 1 задаёт тёплое дерево и золотистую кромку.
Референс 2 — схема nine-slice с границами углов и краёв.
Создать одну рамку, вид строго спереди, без перспективного наклона.
Угловые детали целиком в защищённых областях схемы.
Вдоль растягиваемых краёв — спокойная совместимая текстура.
Не рисовать текст, цену, иконку, тень букв, стрелку или состояние прогресса.
Центр <прозрачный либо принятая поверхность>. Полный холст по профилю.
```

Проверить рамку на короткой и длинной русской подписи, в разных размерах кнопки. Сгенерированное изображение не определяет автоматически границы nine-slice, padding, hit area и focus. Эти параметры принадлежат UI-контракту.

## Сохранение и проверка

Для каждой попытки записать slot/profile/revision, точный prompt, роли и digest референсов, реально использованный инструмент/модель (или unknown), фактические параметры, выходной digest и результат проверки. Для сравнения моделей добавить время, число попыток и стоимость принятого варианта, если доступна; не заявлять ускорение по рекламному описанию.

Рабочие исходники и варианты находятся вне `public/assets/game/`; будущие пути описаны в [инструкции вставки](ASSET_INSERTION_GUIDE.md#порядок-будущей-вставки). В runtime попадает выбранный проверенный экспорт, с отдельной строкой ASSET_MANIFEST. Этот документ не создаёт renderer, не меняет 14 мест и не запускает генерацию. Пробелы и порядок реализации: [ASSET_ARCHITECTURE_AUDIT](ASSET_ARCHITECTURE_AUDIT.md); загрузчик: [LOADING_SCREEN_SPEC](LOADING_SCREEN_SPEC.md).
