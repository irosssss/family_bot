# Техническая спецификация загрузчика Family Life V3

Спецификация описывает будущий старт изолированного V3 на React 18 + Vite в браузере и Telegram Mini App. Контракт от 09.09.2026 **не реализован и не принят по результатам браузерной проверки**. Готового загрузочного арт-экспорта пока нет; полное состояние графического контура описано в [аудите](ASSET_ARCHITECTURE_AUDIT.md).

## 1. Результат для пользователя

После получения HTML приложение показывает понятную оболочку, затем открывает вход или семейный дом. Пользователь видит, что происходит, и может повторить неудавшееся подключение. Необязательная иллюстрация не препятствует входу. Быстрое подключение не задерживается ради демонстрации заставки.

Загрузчик остаётся частью React DOM. Для его реализации не требуются PixiJS, Phaser, canvas или новая система состояния игры. Из игровых загрузчиков используется принцип: небольшой стартовый набор, готовность первого экрана, последующие ресурсы по потребности. Это соответствует разделению Boot/Preloader в официальном [Phaser React TypeScript template — Boot](https://raw.githubusercontent.com/phaserjs/template-react-ts/main/src/game/scenes/Boot.ts) и [Preloader](https://raw.githubusercontent.com/phaserjs/template-react-ts/main/src/game/scenes/Preloader.ts), а также примеру [PixiJS background loading](https://pixijs.com/8.x/guides/components/assets/background-loader).

## 2. Исходное состояние и ограничения

На дату спецификации:

- `family-life-v3.html` и `family-life-v3-telegram.html` содержат пустой `#root`; HTML-оболочки и `noscript` нет.
- `src/v3/main.tsx` статически импортирует `LiveApp`; `src/v3/live/App.tsx` импортирует все пять разделов.
- Первый React-экран сообщает «Открываем наш дом». Запросы идут последовательно: `/v3/api/meta`, затем `/v3/api/bootstrap`.
- В `src/v3/live/transport.ts` уже есть `AbortController` и таймаут 20 секунд. В `LiveApp` уже есть защита чтений поколением, последовательностью и ревизией проекции. Эти механизмы необходимо сохранить.
- Неопределённый результат POST уже сохраняется для повтора с тем же телом и ключом. Загрузчик не меняет этот контракт.
- `src/v3/assets/release.json` имеет `entries: []`. Сейчас нет реального набора игровых изображений для процентной загрузки.
- `GameAsset` уже резервирует пропорции, ждёт `onLoad` всех слоёв и показывает заглушку при `onError`. Это не заменяет таймаут зависшего ресурса и явный барьер декодирования для цельного раскрытия иллюстрации.

Пути выше — ориентиры для будущей реализации; строковые номера следует проверять по актуальному коду перед изменением.

## 3. Состояния и переходы

Состояния старта отделяются от фонового обновления данных и исполнения игровых команд.

| Состояние | Условие входа | Видимый результат | Условие выхода |
|---|---|---|---|
| `html-shell` | HTML получен, основной модуль ещё не готов | Название, спокойный фон, «Открываем Family Life» | Смонтирована React-оболочка либо обнаружена ошибка запуска |
| `connecting` | Код оболочки готов; обязательные чтения выполняются | «Подключаемся к семейному дому», неопределённый индикатор | Режим и сессия определены либо произошла ошибка |
| `preparing-art` | Есть выпущенный набор ресурсов первого экрана, который действительно требуется подготовить | Подписанный прогресс этого набора или статус подготовки | Набор подготовлен либо выбран доступный fallback |
| `login-ready` | Режим известен, действующей сессии нет | Форма входа | Пользователь отправил форму; далее существующий контракт авторизации |
| `home-ready` | Получены действующие session и projection, первый экран может быть показан | Семейный дом с доступными изображениями или заглушками | Последующая навигация и обновления относятся к приложению |
| `retryable-error` | Не удалось прочитать режим/семью или загрузить необходимый код | Понятная ошибка и «Попробовать снова» | Новая попытка старта или перезагрузка документа |
| `js-unavailable` | JavaScript отключён/не поддерживается | Статическая инструкция через `noscript` | Пользователь изменил условия и перезагрузил страницу |

`art-degraded` — дополнительный признак результата ресурсов, а не обязательный полноэкранный шаг. Он совместим с `login-ready` и `home-ready`: отсутствие декоративной графики не превращает работающую игру в ошибку подключения.

При пустом release состояние `preparing-art` пропускается. Переход к входу не должен ждать персональных ассетов семьи. На горячем кэше промежуточные состояния могут быть краткими; минимальная обязательная длительность заставки не устанавливается.

## 4. HTML и передача управления React

1. Минимальный фон, название и текст состояния доступны из HTML до выполнения главного приложения. Они не зависят от игрового CSS, веб-шрифта или загрузки большого изображения.
2. HTML-оболочка имеет собственный жизненный цикл, например как сосед `#root`. React не должен очистить единственный видимый экран до готовности его замены.
3. Владелец видимого статуса в каждый момент один. После первого commit React-оболочки статическая версия скрывается или удаляется. При переходе к форме/дому/ошибке не остаётся двух доступных скринридеру загрузчиков.
4. Сбой главного module-script должен оставлять рабочий HTML-fallback. Перехват ошибки импорта и ограниченное ожидание запуска принадлежат маленькому bootstrap-слою, а не модулю, который сам может не загрузиться. Реализация обязана учитывать применяемую CSP; нельзя предполагать, что произвольный inline-script всегда разрешён.
5. `noscript` объясняет, что для игры нужен JavaScript. Он не заменяет обработку ошибки module-script: JavaScript может быть включён, но отдельный файл недоступен.
6. Необходимо проверить обе точки входа. В Telegram-entry сейчас внешний синхронный SDK стоит в `head` перед `body` и способен задерживать разбор оболочки. Перед реализацией выбрать и проверить не блокирующую показ оболочки схему с явным ожиданием SDK, его ошибкой и сохранённым порядком инициализации. Простое добавление React-компонента не закрывает этот интервал.

Основания: браузерные правила [script](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script) и [noscript](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/noscript). Проверка отсутствия пустого кадра проводится по filmstrip/видео и скриншотам; вызов callback сам по себе не доказывает, что пользователь увидел новый экран.

## 5. Готовность API, сессии и повтор

`meta` определяет разрешённый режим запуска; `bootstrap` возвращает сессию и семейную проекцию. Эти GET не зависят от результата друг друга и могут выполняться параллельно. Реализация должна независимо классифицировать их результаты, не превращая ожидаемое отсутствие сессии в общую ошибку `Promise.all`.

Контракт результатов:

- Успешные meta и bootstrap: открыть семью после минимальной подготовки первого экрана.
- Успешный meta и подтверждённое отсутствие/истечение сессии: открыть вход. Не писать «Сервис недоступен».
- Ошибка определения режима, запрет адреса/источника, неправильный ответ сервера или невозможность связаться с ним: показать ошибку запуска. Нельзя считать любой `403/FORBIDDEN` доказательством отсутствия сессии: текущий сервер использует этот код также для boundary-отказов. При уточнении API добавить различимый результат; до него не делать новых выводов по одному HTTP-статусу.
- Ошибка чтения: «Не удалось подключиться. Попробуйте ещё раз». Текст о возможном сохранении действия применяется только к соответствующему POST.
- Подсказка локального запуска и ссылка `127.0.0.1` допустимы только в достоверно определённом local-режиме. Не показывать их в Telegram и при неизвестном режиме.
- Вход и восстановление PIN используют существующие правила отправки формы. Загрузчик не запускает их автоматически.

Начальная политика ожидания для реализации: после 6 секунд видимого ожидания добавить «Подключение занимает больше времени»; сохранить существующий сетевой deadline 20 секунд на обязательный GET, включая чтение тела. Это продуктовые настройки, а не заявленная скорость сервиса. Для фоновой вкладки таймеры могут приостанавливаться; при возвращении на экран состояние необходимо согласовать с фактическим результатом запроса.

Повтор чтения создаёт новое поколение boot-попытки, очищает её ошибку, отменяет прежние GET и таймеры. Отменённая из-за cleanup операция не показывает пользователю сетевую ошибку. Ответ старого поколения не может открыть дом или скрыть ошибку новой попытки. Существующие epoch/sequence/revision-проверки сохраняются; caller-signal добавляется к transport без потери его deadline. При необходимости использовать совместимый `AbortController + setTimeout`, а не требовать новый API во всех WebView. [React Effect cleanup](https://react.dev/reference/react/useEffect), [AbortSignal timeout и совместимость](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/timeout_static).

Для недоступного главного JS или несовместимого устаревшего чанка кнопка может перезагрузить документ. Не создавать бесконечный автоматический reload. Действие с неопределённым результатом повторяется только по существующему механизму с тем же ключом и телом; восстановление старта не должно создавать новый экземпляр такой команды.

## 6. Наборы ресурсов и честный прогресс

| Класс | Примеры | Может блокировать показ первого экрана | При сбое |
|---|---|---|---|
| Оболочка | Минимальный HTML/CSS, системный шрифт, статус и повтор | Только необходимый код управления | Статическая ошибка и перезагрузка |
| Обязательные данные | Режим, результат проверки сессии, проекция для авторизованного дома | Да | Ошибка подключения или вход по смыслу ответа |
| Стартовая иллюстрация | Чистый plate загрузочного референса | Нет | Фоновый цвет/нейтральный fallback |
| Графика первого экрана | Выпущенный home.room и актуальные визуальные варианты членов семьи | Ограниченная подготовка; каждый ресурс имеет fallback | Дом доступен с заглушками |
| Последующие разделы | Магазин, невыбранные наряды, остальные питомцы и сцены | Нет | Локальный fallback раздела и повтор |

Пути берутся из проверенного asset release/resolver. Отсутствующий variant не заменяется произвольной старой графикой. Не предварительно загружать весь каталог и все возможные наряды. Стартовый art plate требует отдельной записи в реестре/manifest при фактической будущей доставке; этот документ такой доставки не делает.

Правила индикатора:

1. Пока неизвестен объём работы — indeterminate. Для native `<progress>` нет `value`; для кастомного `role="progressbar"` нет `aria-valuenow`.
2. Не двигать заполнение по таймеру и не держать выдуманные 95–99% во время ответа сервера. Подпись этапа полезнее неподтверждённого числа.
3. Численный прогресс разрешён только для фиксированного реально выполняемого набора. Предпочтительна подпись «Подготовлено ресурсов: X из Y». Для неоднородных файлов можно использовать заранее известные веса из размеров release-файлов: `sum(weights of decoded ready files) / sum(weights of all files in this batch)`.
4. Такая величина описывает готовность взвешенного набора, не полученные в реальном времени байты и не оставшееся время. Знаменатель фиксируется перед показом. Открытие следующего раздела создаёт отдельную загрузку и не уменьшает старую полосу.
5. Не прибавлять условные доли за авторизацию, запуск JavaScript или задержку. Если требуется показать именно переданные байты, реализация должна получать реальные loaded/total и учитывать неизвестный total; без этого процент байтов не заявляется.
6. Не считать ошибку изображения успешным скачиванием для достижения 100%. Выбор fallback завершает подготовку интерфейса отдельным результатом и позволяет убрать полосу без ложного сообщения «все изображения загружены».

Семантика неизвестной длительности и подписей описана в [HTML progress](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/progress). [Phaser Loader](https://docs.phaser.io/phaser/concepts/loader) отдельно показывает события progress, filecomplete и loaderror; его процент также относится к собственной очереди ресурсов, а не к авторизации приложения.

## 7. Загрузка и декодирование изображения

Для стартового plate и подготовки первого экрана контракт ресурса имеет результаты `ready`, `missing`, `failed`, `timed-out`, `cancelled`.

- Размеры/пропорции резервируются до загрузки, чтобы не сдвигать статус и кнопку.
- Ресурс для цельного раскрытия становится `ready` после успешной загрузки и `HTMLImageElement.decode()`. При отсутствии метода используется проверенный load/error fallback.
- Для стартового декоративного plate начальный deadline — 8 секунд, затем продолжается работа с фоном. Эта настройка не продлевает обязательное ожидание API. Если семья готова раньше, plate её не задерживает.
- Повтор запроса изображения сбрасывает ошибку только этого ресурса. Неуспешный Promise не должен навсегда отравлять кэш новой попытки.
- Одинаковые URL одной версии можно объединять в одном активном запросе. Очистка общего запроса одним потребителем не должна ломать другого; если нет корректного учёта потребителей, ограничить дедупликацию одной boot-попыткой.
- Cleanup снимает обработчики и таймеры, отменяет fetch там, где он используется, и не применяет результат старой попытки. Нельзя обещать отмену `decode()` тем же сигналом: проверка актуальности нужна и после его завершения.

`decode()` возвращает готовность декодированного изображения и может завершиться ошибкой при сетевом сбое, изменении `src` или повреждённых данных. [MDN HTMLImageElement.decode](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode).

## 8. Референс и арт-контракт

Первый художественный референс задаёт предпочтительную композицию: семейный дом, вывеска Family Life, группа персонажей и питомцев, тёплая игровая атмосфера. Это направление следует сохранить при подготовке арта.

Будущий runtime plate — чистая иллюстрация без запечённой полосы, статуса загрузки, подсказок и псевдокнопок. Полоса и текст рисуются средствами DOM. Вывеска может остаться художественным элементом, если рядом есть доступное текстовое название и соблюдён утверждённый вариант бренда.

Плоское исходное изображение с визуально заполненной полосой не является готовым интерактивным экраном: оно сообщает одно фиксированное состояние, не позволяет корректно менять текст и адаптировать контроль к высоте WebView. Не маскировать проблему второй полосой поверх первой.

При арт-подготовке требуется зона для живого статуса и действий, не занятая важными лицами/деталями. Композиция проверяется на 375 и 390 px, а также на коротком viewport. Выбор crop/contain определяется видимостью важных элементов, а не растягиванием изображения с искажением пропорций. Статус размещается по доступной области экрана, а не привязывается к пикселю большого референса.

Такой plate может быть цельной заставкой. Он не становится автоматически интерактивным семейным домом: динамические персонажи, питомцы и предметы сцен требуют отдельного контракта слоёв.

## 9. Telegram и размеры экрана

- `Telegram.WebApp.ready()` вызывается после готовности необходимых элементов оболочки, независимо от успешности авторизации. Он не означает, что семейные данные уже получены.
- `expand()` рассматривается отдельно от готовности. Нельзя считать его завершённым изменением высоты сразу после вызова.
- Для нижнего статуса учитывать стабильную высоту Telegram и события изменения viewport. Уважать device safe-area и Telegram content-safe-area; не складывать пересекающиеся отступы вслепую. Вне Telegram использовать CSS viewport и `env(safe-area-inset-*)` fallback.
- Отсутствующий SDK/пустой initData при Telegram-входе дают понятную инструкцию открыть приложение через Telegram. Нельзя подменять их local-identity или фиктивной успешной сессией.
- Нативная заставка Telegram до страницы настраивается отдельно в BotFather. Наша HTML/React-оболочка не заменяет этот этап.

Поведение `ready`, `viewportStableHeight`, safe-area, SDK и нативной заставки определено в [официальной документации Telegram Mini Apps](https://core.telegram.org/bots/webapps). Реальная проверка iOS/Android WebView обязательна; desktop-эмуляция ширины не доказывает её прохождение.

## 10. Доступность, движение и offline

- Название и статус доступны текстом. Декоративный plate имеет пустой `alt`; содержательная иллюстрация получает короткую подпись без повторения всех соседних текстов.
- Смена этапов объявляется через стабильный `role="status"`/polite live region. Не объявлять каждый кадр или каждый процент. Область статуса не должна находиться внутри другого региона, чьё `aria-busy` подавляет нужное объявление до завершения загрузки.
- Индикатор имеет доступную подпись. Загружаемый регион обозначается `aria-busy`, затем атрибут снимается. Ошибка доступна как сообщение; повтор доступен клавиатурой и имеет видимый focus.
- Кнопки не меньше 44 × 44 CSS px. Текст не является частью bitmap; он должен переноситься при увеличении масштаба и размера шрифта. Цветовая пара текста/фона проверяется на WCAG AA.
- Необязательные пульсации, параллакс и перемещение камеры выключаются при `prefers-reduced-motion: reduce`. Смысл статуса сохраняется без анимации. Уже существующее правило `.v3-app` нужно распространить на отдельную HTML-оболочку, если она вне этого контейнера. [MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).
- `navigator.onLine` используется как дополнительная подсказка. Кнопка повторного запроса не блокируется только из-за его значения. [MDN onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine).
- Загрузчик не вводит offline-начисления и offline-авторизацию. Кэширование кода и публичного арта не равнозначно доступности семейной сессии. На первом открытии без полученного HTML показать оболочку технически невозможно; offline-service-worker этим документом не предлагается.

## 11. Разделение кода

Первый кандидат — отделить маленький bootstrap и оболочку от полного `LiveApp`. Hero/Family/World можно загружать через `React.lazy` после измерения сборки и сценариев перехода. Локальные индикаторы разделов не должны возвращать пользователя на полноэкранную начальную заставку при каждом переходе.

Для отклонённого lazy-import требуется Error Boundary с восстановлением. `Suspense` в React 18 не отслеживает существующие запросы из Effect автоматически; API-состояния остаются явными. Не использовать новые API из документации React более поздней версии без отдельной миграции. [React lazy](https://react.dev/reference/react/lazy), [React Suspense](https://react.dev/reference/react/Suspense).

Vite поддерживает динамические импорты и загрузку их CSS; оптимизации проверяются на используемой версии Vite и собранных артефактах. Наличие `lazy()` само по себе не доказывает уменьшение стартовой цепочки. [Vite build optimizations](https://vite.dev/guide/features.html#build-optimizations).

## 12. Матрица проверки

Проверки выполняются на production-сборке и локальном синтетическом API; запуск реального бота не подразумевается. Там, где требуется Telegram WebView, результат фиксируется отдельно после доступности такой среды.

| Сценарий | Критерий прохождения |
|---|---|
| Холодный кэш, медленная сеть и CPU | Видна HTML-оболочка до основного приложения; нет ложного процента и пустого промежуточного кадра |
| Горячий кэш | Вход/дом открывается без принудительной задержки; изображение не вызывает сдвиг статуса |
| `/meta` завис или вернул ошибку | Ограниченное ожидание, правильный текст, повтор; нет локальной инструкции при неизвестном режиме |
| Bootstrap завис, сеть оборвалась, JSON повреждён | Ошибка чтения; нет заявления о возможном сохранении действия |
| Сессия отсутствует/истекла | Открывается вход; boundary-отказ не выдаётся за успешную проверку отсутствия сессии |
| Plate 404, corrupt, зависший | Фон/fallback; работа API и доступ к форме/дому продолжаются |
| Пустой release | Нет фиктивных image-запросов и процентной стадии |
| Часть слоёв первого экрана отсутствует | Предсказуемый fallback без ложного объявления полной загрузки |
| Основной JS недоступен | HTML-ошибка и способ перезагрузки; нет вечного пустого root |
| Lazy chunk недоступен после перехода | Ошибка соответствующего раздела; нет бесконечного spinner/reload |
| JavaScript отключён | Видна инструкция `noscript` |
| Повтор, затем поздний ответ прежнего запроса | Старое поколение не изменяет результат новой попытки |
| StrictMode, unmount/remount | Cleanup работает; старый запрос не обновляет новый экран; команды не дублируются |
| Ранее сохранённый pending POST | Тело и idempotency key сохранены; загрузчик не отправляет новый экземпляр |
| Offline → online и ложный onLine | Понятная подсказка, доступный повтор; статус сети не подменяет ответ API |
| 375/390 px, короткий viewport, увеличение текста | Нет горизонтального overflow; статус/повтор не обрезаны и доступны без наложений |
| Reduced motion, клавиатура, screen reader | Статус понятен без движения; корректные подписи, порядок фокуса и редкие объявления |
| Telegram iOS/Android, раскрытие/сворачивание | Shell раскрывается через ready; нижняя зона вне перекрытий, нет скачущей привязки |
| Telegram SDK недоступен/задержан, initData пуст | Понятный исход вместо зависания или подмены режима |
| Уход в фон и возвращение во время старта | Нет применения устаревшей попытки; ожидание и ошибки соответствуют результату сети |

## 13. Критерии готовности реализации

Реализация считается готовой к отдельной приёмке, когда выполнены все условия:

1. Закрыты обе HTML-точки входа и ошибки до React; показана непрерывность перехода оболочка → вход/дом/ошибка.
2. Прогресс связан с реальной операцией; при неизвестном объёме отсутствует численный процент. Пустой release корректно пропускается.
3. Отказы API, отсутствие сессии, ошибка кода и отказ декоративного арта различимы. Доступен проверенный повтор без нарушения существующих команд и ревизий.
4. При доставке нового plate есть утверждённый чистый экспорт, запись asset manifest, подходящие размеры и успешный asset-check. Сам референс с запечённой полосой не считается этим экспортом.
5. Пройдены `npm run lint`, `npm run v3:typecheck`, релевантные `npm run v3:test` и `npm run v3:build`. Тесты проверяют состояния/ошибки/cleanup на швах, а не совпадение строк JSX.
6. Матрица имеет фактические результаты и доказательства: скриншоты 375/390, filmstrip старта и отказа, сетевые наблюдения. Непройденный реальный Telegram отмечен как ограничение, а не PASS.
7. Изменение описано как локальный V3-результат. Этот Markdown-файл без реализации не закрывает ни один пункт приёмки.
