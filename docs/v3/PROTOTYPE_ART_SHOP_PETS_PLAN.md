# V3 — персонажи, магазин и уголок питомца

Дата: 2026-09-11. Подготовка следующих блоков [плана завершения прототипа](PROTOTYPE_COMPLETION_PLAN.md). Документ основан на текущем коде V3 и принятом деревянном оформлении Figma. Это план реализации и приёмки: новые изображения не изготовлены, Figma, runtime, БД и экономика в ходе этой подготовки не изменялись.

Рекомендуемый порядок: **пилот взрослого и ребёнка со сменой одной одежды → магазин/гардероб → бесплатный уголок с тремя темами → сквозная проверка**. Каркасы магазина и питомцев можно собирать параллельно с арт-пилотом из существующих мастеров. Массовая генерация начинается только после проверки совместимости пилота.

## 2. Ограниченный художественный пилот A01

### 2.1. Состав и границы

Сделать **одного взрослого и одного ребёнка**, каждого в двух состояниях: бесплатная базовая одежда и существующая «Одежда путешественника». Сохранить лицо, цвет кожи, волосы, позу, камеру, рост и освещение одного героя при переодевании. Ребёнок имеет собственные пропорции, а не является уменьшенной копией взрослого.

Художественное направление — мягкий детальный cartoon/chibi, читаемый на телефоне, с тёплым светом и спокойными материалами, совместимыми с деревянным UI. Существующие [герой со спутником](../../work/figma-v3/art/hero-companion.png) и [семейный дом](../../work/figma-v3/art/family-home.png) — ориентиры стиля. Это цельные композиции: вырезание героя из них само по себе не создаёт совместимых носимых слоёв.

Одна статичная нейтральная стоячая поза, одна фиксированная камера, простые волосы без сложного прохождения за одеждой. Бесплатная база — полноценная закрытая повседневная одежда, которая возвращается после снятия покупки. В пилот не входят анимация, дополнительные лица/причёски, головные уборы, полная библиотека костюмов, сборка четырёх уникальных членов семьи и новый ассортимент.

| Entry | Slot / variant / state | Что поставляется |
|---|---|---|
| A01-1 | `hero.adult` / `default` / `neutral` | Бесплатная взрослая база |
| A01-2 | `hero.adult` / `outfit:v3.outfit.traveler` / `neutral` | Совместимый носимый вариант путешественника для взрослого |
| A01-3 | `hero.child` / `default` / `neutral` | Бесплатная детская база |
| A01-4 | `hero.child` / `outfit:v3.outfit.traveler` / `neutral` | Совместимый носимый вариант путешественника для ребёнка |
| A01-5 | `item.outfit` / `v3.outfit.traveler` / `base` | Одно квадратное товарное превью того же костюма |

Итого пять логических ресурсов; один ресурс может содержать несколько PNG. Отдельные портреты в этот набор не включать: текущий `GameHero` кадрирует ту же сборку. Превью предмета не заменяет одежду на герое.

### 2.2. Кандидат профиля и способ сборки

Предлагаемые имена профилей — `adult.front.v1` и `child.front.v1`. Предложение для первого экспорта: логический canvas **256×320**, `pixelScale: 2`, PNG **512×640 RGBA**. Это та же пропорция 4:5, которую принимает текущий validator; 64×80 в реестре — кандидат, а не предел разрешения. Квадратное товарное превью проверять отдельно, например 256×256 logical при scale 2. Размеры, камера и точки привязки становятся принятыми только по результату пилота.

Для минимального A01 рекомендуется проверяемая замена одной части сборки:

1. База содержит `contact_shadow`, `body_underlayer`, `face`, `hair_main`. В `body_underlayer` находится силуэт тела с бесплатной одеждой; отдельные лицо и волосы сохраняют узнаваемость. Голова, руки и открытая кожа при смене одежды сохраняют исходную геометрию.
2. Вариант путешественника заменяет **тот же** `body_underlayer` совместимым изображением тела в костюме. Он использует общий canvas и идентичные координаты открытой кожи. Остальные три слоя остаются базовыми.
3. Снятие вещи убирает outfit variant и возвращает базовый `body_underlayer`. Тени не удваиваются, лицо/волосы не перерисовываются случайно, старая одежда не выглядывает.

Это ограниченная модульная сборка с заменой одетого тела. Она не доказывает возможность произвольного смешивания торса, брюк, обуви и шляп. Настоящую одежду поверх неизменяемого тела можно предпочесть, если пилот покажет чистое перекрытие бесплатной базы без масок и удаления слоёв. Не объявлять этот вариант рабочим до проверки.

При рекомендованном разбиении A01 получается восемь базовых PNG, два заменяющих PNG и одно превью — **11 PNG**. Не создавать пустые файлы для остальных ролей реестра. Разбиение можно уточнить после проверки силуэта; изменение фиксируется в профиле, а не маскируется несовпадением слоёв.

В brief профиля зафиксировать canvas, масштаб, камеру, линию пола, границы силуэта, фокус портрета и будущую точку хвата. Предлагаемый контакт с полом `(0.5, 0.95)` уже есть в реестре; его наличие в метаданных не означает автоматического размещения в сцене. Утвердить допустимые роли и обязательную базу; для каждого носимого варианта указать, какие роли он заменяет. Все слои полноразмерные, без индивидуального tight crop.

### 2.3. Что действительно умеет текущий renderer

| Механизм | Текущее поведение | Решение для пилота |
|---|---|---|
| Разрешение героя | `default` + точные `outfit:<id>` + `hand:<id>`, состояние всегда `neutral` | Не изготовлять `celebration`, пока нет соответствующего пути UI |
| Совместимость | Сравнивает строку profile, logical dimensions и scale | Разные взрослый/детский профили; носимые варианты совпадают со своей базой |
| Наложение | Последний слой с тем же role заменяет предыдущий; затем роли сортируются по реестру | Держать явную таблицу замен; не полагаться на имена файлов или порядок загрузки |
| Маски и исключения | Нет hide/erase/mask и реестра rig-профилей | Не проектировать одежду, которой требуется скрыть непредусмотренный базовый слой |
| Проверка manifest | Проверяет формат profile, но не существование утверждённого профиля и не обязательный слой тела | Перед runtime-приёмкой добавить или отдельно выполнить проверку whitelist профилей и обязательной базы; валидная строка ещё не доказывает совместимость |
| Загрузка | Все части скрыты до загрузки всех PNG; ошибка одной части показывает общий fallback | Проверить одну ошибку слоя, незагруженный вариант и повтор открытия без изменения владения/выбора |
| Отсутствующая одежда | Вся сборка становится `not_supplied`; renderer не подменяет покупку другой одеждой | Визуальный fallback объясняет недоступность изображения; применённая вещь и кошелёк сохраняются |
| Фактическая оболочка | `v3-game-art` имеет собственные размеры/фон; часть контекстного CSS адресована только placeholder `v3-asset-slot` | Сначала выровнять геометрию loading/ready/failed в каждом контексте |
| Масштабирование | В `live.css` для всех PNG задано `image-rendering: pixelated` | Для принятого мягкого арта проверить обычное сглаживание; не утверждать pixel-art ограничением V3 |
| Портрет | CSS scale 1.65, origin 50% 15%; `portrait_focus` не применяется | Проверить кадрирование двух пилотных лиц и перенести фокус в управляемый контракт при необходимости |

Источники: [registry.ts](../../src/v3/assets/registry.ts), [resolver.ts](../../src/v3/assets/resolver.ts), [GameAsset.tsx](../../src/v3/assets/GameAsset.tsx), [live.css](../../src/v3/live/live.css), [архитектурный аудит](ASSET_ARCHITECTURE_AUDIT.md). Полный порядок ролей: `contact_shadow → aura_back → hair_back → outfit_back → body_underlayer → legs → feet → torso → held_back → face → hair_main → headwear → hair_front → hands_held_front → accessory_front → aura_front`. Наличие роли в списке не обязывает пилот поставлять её.

### 2.4. Приёмка A01 и следующий маленький набор A02

Сначала собрать контрольный лист: взрослый/ребёнок × база/путешественник на нейтральном, светлом и тёмном фоне; рядом разобранные слои. Проверить альфу и отсутствие ореола, скачка лица, ступней и роста, швов кожи, просветов старой одежды, лишней тени и обрезанных волос. Наложение до/после должно сохранять лицо и контур открытой кожи; простая визуальная похожесть двух независимо созданных героев недостаточна.

Затем проверить каждого героя крупно в «Облике» и примерке, в квадратном портрете, в карточках дома/семьи и приключения при ширине экрана 375 и 390 px. Приёмка включает последовательность база → примерка → отмена → куплено, но не применено → применено → снято. Нужны реальные скриншоты этих размеров и слоёв; сравнение только исходников на 512×640 недостаточно.

Следующий набор A02 — **существующий** `v3.item.adventure-kit`: два носимых hand variant для взрослых/детей и одно квадратное `item.weapon` preview, всего три логических ресурса. У предмета проверить заднюю/переднюю части, хват, свободную руку после снятия и совместимость с базой и путешественником. Одного квадратного превью недостаточно. Если корректный хват потребует новой позы или скрытия руки, сначала уточнить профиль и renderer; не выдавать вклеенный поверх ладони предмет за принятый слой. A02 обязателен перед финальной художественной приёмкой всего текущего гардероба, но не увеличивает A01.

Артефакты: brief и принятый профиль в `art/family-life-v3/briefs`, происхождение/референсы в `sources`, кандидаты в `exports`, контактные листы и скриншоты в `review`. Только выбранные runtime PNG — в разрешённом V3 asset root, с точными entries/hash и строками общего манифеста по [ASSET_DELIVERY.md](ASSET_DELIVERY.md). Сейчас эти поставки отсутствуют.

`v3:assets:check` проверяет заголовок PNG, размер, hash и отсутствие лишних runtime-файлов; это не проверка альфы, декодирования или контактов. Для runtime QA использовать локальный V3 сервер, который обслуживает нужный root. Обычная Vite-сборка с `publicDir: false` не поставляет будущие PNG автоматически. Изготовление Figma-пилота и подключение PNG в работающий клиент — два отдельных результата приёмки.

### 3.2. Минимальные экраны и состояния

Продолжать существующий раздел «Герой»: **Облик / Питомцы / Вещи / История**. «Мой облик» — небольшой гардероб двух имеющихся предметов, отдельная большая система фильтров и коллекций для двух позиций не нужна. Экран «Вещи» показывает три товара ребёнку и дополнительно семейную лампу взрослому. Реальные награды остаются отдельным семейным процессом.

| Состояние | Видимый смысл | Минимальное действие |
|---|---|---|
| Витрина | Название, точная цена, личное/семейное владение, доступные монеты | «Посмотреть предмет» |
| Карточка одежды/руки | Превью и короткое описание косметического эффекта | «Примерить»; возврат из примерки сохраняет прежний облик |
| Условия покупки | Цена, чей кошелёк, кому останется вещь, сколько доступно | «Купить за 60/100/180/240 монет» после получения условий |
| Недостаточно монет | Точная недостающая сумма, доступные средства с учётом резерва | Недоступная покупка и понятный возврат к делам; без кредитов и пополнений |
| Куплено, не применено | «Предмет получен»; облик ещё прежний | Для носимой вещи — «Применить к герою» |
| Применено | Состояние видно и в гардеробе, и на герое | «Снять предмет» возвращает базу/пустую руку |
| Уже в коллекции | Повторная покупка отсутствует | Открыть имеющуюся вещь; для лампы показать семейного владельца |
| Отправка / неопределённый ответ | Действие обрабатывается; повторное нажатие ограничено | Сохранить контекст предмета и восстановить актуальное состояние |
| Условия устарели | Старое подтверждение больше не действует | «Обновить условия»; новая покупка только с актуальной ценой |
| Изображение недоступно | Название и факт владения остаются читаемыми | Основной процесс не теряет выбранную вещь |

Примерка временно меняет один визуальный слот, сохраняя другой. Покупка не применяет вещь автоматически. Применение сохраняет ID владения; путь PNG никогда не становится игровой собственностью. В кошельке различать «Всего», «В резерве», «Доступно». В прототипе допустим заранее записанный пример: всего 80, резерв 30, доступно 50, на костюм за 60 не хватает 10. Это состояние демонстрации, а не новая денежная операция.

Лампа после покупки уже появляется в домашнем списке «Вещи нашего дома». Отдельного действия «Поставить», пространственного места или совместимости с уголком питомца сейчас нет. Поэтому в текущем блоке показывать семейное владение и предмет в домашнем списке; изображение лампы в сцене требует отдельной композиции дома, а не выдуманной команды применения.

Источник взаимодействий: [ItemDetails и Wallet](../../src/v3/live/Hero.tsx), [QuotePurchase/PurchaseItem/SelectAppearance](../../src/v3-server/game/collection.ts), [семейные вещи дома](../../src/v3/live/App.tsx), [создание реальных наград](../../src/v3/live/Rewards.tsx).

## 4. Бесплатный уголок и выбор оформления

### 4.1. Сохраняемый путь питомца

1. До первого принятого дела — понятное условие бесплатного выбора. После принятия — котёнок **или** щенок, результат известен до подтверждения. Повтор входа не даёт второе право.
2. Получение стартового яйца или покупка лисёнка создаёт питомца с 0 XP. Получатель XP и спутник автоматически не выбираются. После получения показать явное действие «Развивать этого питомца».
3. Опыт получает один выбранный питомец, закреплённый при открытии нового дела. Уже открытые дела сохраняют прежнего получателя либо отсутствие получателя. Карточка другого питомца — просмотр, а не переключение.
4. При **50 XP** доступно «Помочь вылупиться бесплатно». Это ручное действие. До него вид остаётся яйцом, даже если аналитическая проекция XP уже достигла следующей стадии.
5. Вылупление создаёт бесплатный «Уютный уголок» с темой `meadow`. При **122 суммарных XP** питомец подрастает автоматически после вылупления; можно накопить этот XP ещё в яйце и сразу вылупить подросшего питомца. Отдельной цены роста нет.
6. «Взять с собой» и «Оставить отдыхать в уголке» управляют спутником независимо от получателя XP. Спутник уже показывается у семейных карточек; для собственного «Облика» требуется добавить его отдельную визуальную сборку.

Пороги — снимок [balance.ts](../../src/v3/model/balance.ts). Награда питомцу за лёгкое/обычное/сложное/большое принятое дело — 1/2/4/8 XP. Точные состояния определяют сохранённые `hatched` / `grown`, а не только число XP. Основания: [коллекция](../../src/v3-server/game/collection.ts), [закрепление условий дела](../../src/v3-server/game/tasks.ts), [MemberVisual](../../src/v3/live/MemberVisual.tsx).

### 4.2. Что рисовать и что разрешать выбрать

Первая художественная проверка уголка — один котёнок и три **бесплатных оформления того же места**:

| Theme | Название UI | Рекомендуемая художественная трактовка |
|---|---|---|
| `meadow` | Луговое | Зелёные акценты, мягкая подстилка, тёплое дерево |
| `sky` | Небесное | Голубые акценты и спокойный свет при тех же местах и масштабе |
| `sand` | Песочное | Песочные/терракотовые акценты при той же геометрии |

Это направление изображений, не три новых товара. Если в оформлении нарисованы подушка, коврик или миска, они являются неотделимыми частями бесплатной темы. Они не получают цены, отдельного владения или кнопки «Установить».

В Figma собрать уголок из независимых слоёв: фон/базовое место → питомец → возможный передний план. Самого питомца не запекать в комнату: замена спутника и стадия роста используют отдельный asset. Текущий клиент выводит `pet.corner` и `pet.companion` раздельно и не имеет композиции с точкой питомца. Для такой же сцены в runtime нужна небольшая явная раскладка с общей линией пола, масштабом и порядком перекрытия. Проверка Figma не считается реализацией этой раскладки.

Точные варианты уголка: `pet.corner`, `<species>:<theme>`, state `base`. Для первого котёнка это три entry `v3.pet.cat:meadow`, `v3.pet.cat:sky`, `v3.pet.cat:sand`. Если фон подходит всем видам, девять сочетаний трёх видов/тем могут ссылаться на те же три комплекта PNG с одинаковыми hash. Не генерировать одинаковые комнаты девять раз; совместимость каждого вида всё равно проверить. Все исходные размеры реестра, включая 320×240 уголка и 48×48 питомца, остаются кандидатами; сохраняется требуемая пропорция 4:3 и 1:1 соответственно.

Отдельно согласовать variants яйца: магазин передаёт `v3.egg.fox`, детали питомца — `v3.pet.fox`, стартовый выбор — `v3.pet.cat` / `v3.pet.dog`, общий блок до выбора — `default`. Можно дать разным entries один и тот же PNG там, где он действительно одинаков. Нельзя поставить один вариант и считать все четыре места покрытыми. Известный результат показывается отдельным названием/превью, а не случайным сюрпризом.

### 4.3. Минимальный UX уголка и граница декора

Карточка вылупившегося питомца содержит его вид, XP/стадию, независимые действия развития и спутника, затем «Бесплатный уголок». Настройки — имя до 60 символов, три темы с превью и одна кнопка «Сохранить уголок». Выбор темы в редакторе показывает локальную примерку; сохранение явно завершает изменение. Закрытие без сохранения и повторное открытие возвращают сохранённое имя/тему. Пустое имя после удаления пробелов не сохраняется. Уголок доступен без Family Level и не списывает монеты.

В текущем завершении прототипа «выбор декора» реализуется как выбор этих трёх бесплатных оформлений. **Предметный декор — следующий отдельный контракт**, если он понадобится: допустимые предметы и места, совместимость видов/тем, личное или семейное владение, получение, применение/снятие, сохранение раскладки и однократная покупка. До такого решения не добавлять платные подушки, новую валюту, виртуальные цены, магазин декора или использование семейной лампы у питомца. Продуктовый контракт допускает будущий совместимый постоянный декор, но каталог и команды его сейчас не описывают.

Модель текущего уголка — только `{name, theme}`: [shared game.ts](../../src/v3-shared/game.ts), [SavePetCorner validation](../../src/v3-server/game/commands.ts), [PetDetails](../../src/v3/live/Hero.tsx). В этой подготовке расширение модели не предлагается как уже выполненная работа.

## 5. Готовые сценарии для приёмки

Для Figma подготовить связанные состояния и зафиксировать начальные условия. Для runtime повторить те же пути на синтетических данных и проверять сохранение/повторы. Статический переход Figma показывает предполагаемый результат, но не доказывает списание, авторизацию или идемпотентность.

| ID | Начальные условия и действия | Проверяемый результат |
|---|---|---|
| ART-01 | Взрослый и ребёнок: база → путешественник → база; крупный вид и портрет | Одна идентичность, без скачка геометрии и швов; детские пропорции самостоятельны |
| ART-02 | Те же облики в доме, семье, приключении, примерке на 375/390 | Одинаковая внешность, читаемое лицо, нет обрезания; loading/ready/failed сохраняют место |
| ART-03 | Не поставлен outfit; несовместимый профиль; ошибка одного PNG | Понятный fallback всей сборки, сохранённый предмет/выбор; чужая одежда не подставляется |
| SHOP-01 | Костюм не куплен, доступно ≥60: примерить, закрыть, открыть | Кошелёк и применённый облик не изменились |
| SHOP-02 | Получить условия, купить за 60, применить, снять | Одно приобретение и списание; до применения вид прежний; после снятия бесплатная база |
| SHOP-03 | Всего 80, резерв 30, доступно 50; открыть костюм за 60 | Показан недостаток 10; резерв не расходуется; покупка недоступна |
| SHOP-04 | Повтор отправки покупки / истёкший quote / уже приобретено | Нет двойного списания и дубля; устаревшие условия обновляются явно |
| SHOP-05 | Надет костюм; купить и применить набор за 100; поочерёдно снять слоты | Рука и одежда сохраняются независимо; сочетания проверены A02 |
| SHOP-06 | Взрослый покупает лампу за 240; другой взрослый/ребёнок открывает семью | Одно семейное владение видно дома; платит первый взрослый; ребёнок не покупает, дубликата нет |
| PET-01 | До/после первого принятого дела выбрать котёнка; повторить выбор и попытаться выбрать щенка | До принятия нельзя; после один бесплатный питомец; XP target ещё не назначен |
| PET-02 | Открыть дело без питомца; выбрать XP target; открыть новое дело; принять оба | Старое сохраняет прежние условия, новое даёт 1/2/4/8 XP выбранному питомцу |
| PET-03 | Яйцо на 49/50 XP; выполнить бесплатное вылупление; довести до 122 | Ниже 50 действия нет; на 50 ручное вылупление и бесплатный уголок; рост без оплаты |
| PET-04 | Яйцо накопило 122 до вылупления; затем вылупить | До команды остаётся яйцом, после — подросший питомец; нет повторного подарка |
| PET-05 | Развивается один питомец, с собой выбран другой; посмотреть третьего | Просмотр не меняет XP target/спутника; снятие спутника не отключает развитие |
| PET-06 | Вылупившийся котёнок: изменить имя/каждую тему, отменить, затем сохранить и открыть заново | Отмена сохраняет прежнее; сохранение возвращает выбранное; баланс прежний, место бесплатное |
| PET-07 | Собственный «Облик», семейная карточка и уголок после выбора спутника | Согласованы вид и стадия; герой и питомец отдельные сборки; отсутствие арт-файла не отменяет выбор |
| UX-01 | Все новые экраны при 375 и 390 px, длинные имя/название, открытая нижняя панель | Основные действия ≥44 px, текст не перекрывается, понятен возврат, цена и владелец читаются |

Для текущего кода уже существуют проверки части покупок, экипировки, стартового выбора, XP и вылупления в [game-unit.test.ts](../../tests/v3-server/game-unit.test.ts). В этом аудите они не запускались; ссылка на тест не заменяет новый прогон после реализации. После изменений runtime выполнить требуемую типовую проверку, профильные тесты затронутых команд/renderer и браузерный сценарий. Для одного этого документа тесты runtime не требуются.

## 6. Конкретные следующие поручения и зависимости

| Порядок | Поручение | Готовый результат | Зависимость |
|---|---|---|---|
| 1 | Зафиксировать brief A01; изготовить пару баз и одну смену одежды | Пять логических ресурсов-кандидатов, контрольный лист слоёв, варианты до/после | Принятое стилевое направление; размеры/профили ещё кандидатные |
| Параллельно | Собрать сценарии магазина из деревянных мастеров | Витрина ребёнка/взрослого, примерка, условия, недостаток, владение, применение/снятие, устаревшие условия | Точный каталог этого документа; арт можно временно обозначить слотами |
| Параллельно | Собрать сценарии питомца и три темы уголка | Выбор яйца → XP → вылупление → бесплатное место → имя/тема → отдельный спутник | Экран принятого дела из блока 11; отдельного декор-контракта не требуется |
| 2 | Проверить A01 в Figma на 375/390 и принять профиль | Evidence пяти ресурсов, одинаковые лица и геометрия в контекстах | A01; результат не означает runtime-готовность |
| 3 | Выполнить A02 и закончить художественную сборку магазина | Носимый набор взрослый/ребёнок + превью, проверенные комбинации | Принятые профили A01; без новых цен |
| 4 | При поручении подключения исправить выявленные ограничения изображения | Общая оболочка состояний, масштабирование мягкого арта, проверка профилей/базы, портрет; локально загруженный пилот | A01/A02 и отдельная проверка runtime |
| 5 | Подключить композицию спутника и уголка, затем пройти сквозные сценарии | Независимый герой/питомец, сохранение темы, подтверждённые 375/390 скриншоты и результаты команд | Принятый уголок; явная раскладка сцены; блоки входа и дел |

Общие Figma-индекс, handoff, память и asset manifest обновляет основной агент после подтверждённых изменений. Не отмечать этот план как завершённый магазин/питомцы или поставленный арт: сейчас завершена только проверка исходников и подготовка ограниченных следующих блоков.
