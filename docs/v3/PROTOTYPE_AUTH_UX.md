## Сценарии и правила продукта

| Ситуация | Путь | Результат |
|---|---|---|
| Первый взрослый | Welcome → создать семью → сохранить код восстановления | Профиль Марины, в семье пока только Марина |
| Приглашённый взрослый | Приглашение Олега → собственный PIN → сохранить свой код | Личный взрослый профиль Олега |
| Ребёнок со своим Telegram | Приглашение Лизы → собственный PIN → сохранить свой код | Личный детский профиль Лизы |
| Ребёнок на общем устройстве | Взрослый добавляет Мишу → открывает детский профиль | Детские дела и накопления; возврат к взрослому через его PIN |
| Действующая сессия | Короткая загрузка → сохранённый профиль | Взрослая сессия возвращает Марину; детский режим возвращает Мишу без PIN |
| Завершённая сессия / потерян PIN | PIN либо код восстановления + новый PIN → сохранить новый код | Возврат в соответствующий личный профиль |

Telegram identity определяет аккаунт, а семейное приглашение — участника и его роль. Получатель приглашения не выбирает себе взрослые права на экране входа. В V3 взрослые также играют: у них собственные дела, герой и накопления, плюс управление семьёй.

В семье после создания не появляются готовые участники. Кнопка добавления взрослого включает Олега в список, после чего его приглашение открывается из карточки. Добавление ребёнка включает Мишу; взрослый может открыть его управляемый профиль. Отдельный демонстрационный сценарий с уже заполненной семьёй показывает приглашения Олега и Лизы.

PIN содержит 6–12 цифр. Он требуется при входе после завершения сессии и при возвращении из детского режима к взрослому. Действующая сессия сохраняет текущий режим, в том числе управляемого ребёнка. Кнопка «Назад» на PIN возвращает к ребёнку, если PIN был открыт из детского режима.

Восстановление требует исходный Telegram-аккаунт и одноразовый код: новый PIN, новый код восстановления, отзыв прежних сессий. Экран потери Telegram объясняет необходимость вернуть исходный аккаунт и не обещает перенос профиля в другой аккаунт.

Приглашение одноразовое, действует 7 дней; повторная выдача заменяет прежнее. Общая ошибка приглашения не раскрывает, какой профиль или аккаунт существует. Ошибка PIN объясняет действующее правило: после пяти неверных попыток вход приостанавливается на 15 минут.

Эти ограничения сверены с локальным кодом `src/v3-server/auth/service.ts`, `src/v3-server/auth/crypto.ts`, `src/v3-server/transport/http.ts`, `src/v3/live/Login.tsx` и `src/v3/live/App.tsx`. Прототип фиксирует UX-контракт; он не меняет реализацию этих правил.

## Как устроена демонстрация

На стартовом экране девять сценариев, которые задают демонстрационный контекст. Один общий экран входа по приглашению обслуживает Олега и Лизу; общий экран сохранения кода ведёт в нужный профиль. Экран повторного входа использует задержку 0,7 секунды. Все переходы остаются на странице 10.

На экранах Олега, Лизы и управляемого ребёнка есть отдельная кнопка «К сценариям прототипа». Это выход из демонстрации, а не действие смены прав. Рабочие действия возврата из детского режима, включая кнопку «Профили» в шапке, по-прежнему ведут через PIN.

Семейные имена и значения полей заранее заданы для показа сценария. `DEMO-INVITE-NOT-VALID`, `DEMO-RECOVERY-NOT-VALID` и маски PIN не являются настоящими учётными данными. Кнопка копирования показывает подтверждение, но не пишет в системный буфер обмена. Кнопки ошибок открывают заданные состояния: прототип не валидирует ввод, не отсчитывает попытки PIN, не потребляет приглашения и не отзывает реальные сессии.

Новая изолированная коллекция `Family Life / Auth demo` содержит семь переменных:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| next-screen | Конечный профиль после входа | family |
| profile-name | Имя владельца приглашения / кода | Марина |
| pin-back | Контекст возврата с PIN | welcome |
| managed-name | Имя управляемого ребёнка | Миша |
| oleg-present | Видимость Олега в семье | false |
| liza-present | Видимость Лизы в семье / профилях | false |
| misha-present | Видимость Миши в семье / профилях | false |

Коллекция и все переменные скрыты от публикации. Для строк задан TEXT_CONTENT; для булевых переменных явно задан ALL_SCOPES, поскольку доступный Figma API не принимает отдельный VISIBILITY или пустой scope для этого типа. Существующие коллекции и значения тем не изменялись. Временно включённые для снимков участники возвращены к значениям по умолчанию и отдельно проверены чтением.

Условия переходов проверены после сохранения в Figma. Для четырёх вариантов конечного профиля используются четыре независимых двоичных CONDITIONAL с пустым else. В этом коннекторе один CONDITIONAL с более чем двумя блоками сохранялся неполностью, а вложенный CONDITIONAL отклонялся. Итоговая форма прошла отдельное чтение и проверку поведения.
