# Дела каждый день — UX прототип

Дата: 2026-09-11. Рабочий дизайн на странице 11. Существующие правила V3 сохраняются; Figma показывает конкретные сценарии и заполненные примеры, не исполняет серверные команды.

## Основные решения

- Ребёнок: Сегодня / Ожидают / История. В карточке дела две независимые области действия по 48 px: «Условия» и «Готово». По кнопке «Готово» нет лишнего подтверждения, после отправки повторная отправка недоступна.
- Взрослый: Мои / Проверить / Управление. Очередь результатов отделена от создания дел и расписаний. Собственное выполнение принимается сразу; детское — только после решения взрослого. Проверяющий не получает награду за чужое дело.
- Проверка открывает конкретные условия и ожидаемую награду; возврат требует понятное пояснение. Поля в Figma показаны заполненными, свободный ввод проверяется на следующем интерактивном browser-пилоте, а не заявляется работающим в макете.
- Начисление показывается только в принятом результате. История открывает ту же квитанцию; переход назад не создаёт новый результат.
- При неизвестном результате отправки повтор относится к тому же запросу; в UI нет кнопки создать новую отправку. Подтверждённая отправка ведёт в ожидание взрослого.
- Совместное дело показывает свою часть и остальные части отдельно. Награда за свою часть после проверки не ждёт завершения всех участников.
- Пауза влияет на будущие повторы. Уже открытые работы, отправленные результаты и полученные награды сохраняются. Возобновление не создаёт долги за паузу.

## Границы демонстрации

Демо-старт явно помечен как выбор сцен. Переход между взрослой и детской точками запуска не изображает получение чужих прав. Вход реализует отдельная страница 10. Основные предметные вкладки за пределами «Дел» будут подключены в общей интеграции; их отсутствие действий не объявляется законченным игровым маршрутом.

## Приёмка

Кликабельные «Условия» и «Готово» не перекрывают друг друга. На 375 px текст и кнопки помещаются, длинный контент прокручивается. После отправки нет повторной кнопки начисления. После принятия результат исчезает из очереди взрослого. Возврат содержит пояснение. Собственное дело взрослого завершается без второй проверки. Ссылки остаются в своей странице. Свободный ввод, реальная сеть и межпользовательская синхронизация Figma этим прототипом не проверяются.


## Фактическая проверка

50 фреймов,235 переходов,718 текстовых узлов,7 переменных. Нативная проверка: нет несовпадений реакций, ошибок геометрии и областей нажатия меньше44px. Осмотрены четыре финальных PNG375px: список, создание, проверка совместной части, история.

Независимая симуляция сохранённых Figma-реакций:10/10 сценариев,74 цепочки PASS. Покрыты оба порядка очереди, принятие/возврат, создание с паузой/возобновлением, собственные дела и возврат/повторная отправка совместной части. Это структурная проверка, не браузер.

Браузер PASS: создание заполненного примера; отправка книг; ожидание сохраняется после возврата; взрослый принимает; результат появляется в истории ребёнка. Дополнительно пройден совместный маршрут: отправка→продолжить Мариной→принять часть→продолжить Лизой→статус «Принято»→история→квитанция8монет/15опыта без повторной кнопки начисления. Совместный возврат проверен симуляцией, отдельно в браузере не повторялся.

Доказательства: `work/figma-v3/task-flow/{flow-final.json,qa-final.json,routing-final.js,independent-qa.results.json,independent-qa.actions.json}`. Новые примеры сбрасывают демо; «Продолжить» сохраняет состояние. Общая нижняя навигация ведёт к демонстрационному выбору сцен, а не создаёт единый мир между страницами.
