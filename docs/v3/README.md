# Family Life V3

Изолированный третий вариант: сохраняемый бесплатный игровой цикл готов к этапу графики. Родители и дети играют; взрослый сам подтверждает своё дело, детский результат проверяет взрослый. Числа v0.1 — рабочая конфигурация для проверки темпа, а не обещание окончательного баланса.

## Открыть локально

Из корня worktree `work/telegram-preview/family-life-v3`:

```bash
npm run v3:local
```

Открыть [локальную игру](http://127.0.0.1:3003/family-life-v3.html). Нужен Docker Desktop и закреплённый образ PostgreSQL из `scripts/v3/verify-foundation.ts`. Runtime создаёт собственную синтетическую БД и сохраняет её между запусками. Project `.env` не читается. На первом входе выбрать «Начать», имя и PIN; сохранить выданный код восстановления отдельно.

Опционально для **пустого** локального контура: `npm run v3:local:seed`. Он создаёт синтетические профили Алексей/Саша и четыре дела; тестовый PIN основного устройства `123456`. Использовать один раз при подготовке демонстрации. Это не способ сброса семьи и не production-учётная запись. В текущем QA-контуре семья уже создана и игровой прогресс сохранён.

`Ctrl+C` закрывает HTTP; БД остаётся. `npm run v3:local:status` проверяет принадлежащий этому контуру контейнер. `npm run v3:local:stop` останавливает его с сохранением данных; следующий `v3:local` поднимет его снова. `work/v3-local/state.json` содержит собственный сгенерированный пароль и имеет права 0600; файл и восстановление игнорируются Git. Не выводить их в логи, не удалять для «перезапуска» и не подменять настройками реальной БД. При оставшемся после аварии `create.lock` сначала проверить отсутствие другого запуска.

## Реализовано

- Разовые/ежедневные/недельные дела, личное назначение, ротация и совместные части. Снимок наград и получателей до работы, возврат с причиной и явная повторная отправка.
- Единственное начисление, неизменяемый денежный журнал, личные монеты/XP, исправление и восстановление без долга и отъёма вещей.
- Покупка по серверной цене, владение, отдельные примерка и применение; стартовый котёнок или щенок, опыт выбранного питомца, вылупление, рост, спутник и бесплатный уголок.
- Детские семейные обещания: резерв → одобрение → фактическая выдача со списанием; отказы, отмены и их история.
- Одна выбранная накопительная цель; добровольное приключение с фиксированным составом и уроном от принятых дел; постоянные однократные трофеи.
- PIN, общий телефон, отдельное приглашённое устройство, пауза игрока, сохранение истории, одноразовое восстановление, отзыв сессий. Неизвестный результат записи повторяется с тем же телом и ключом.

Подробности и доказательства: [итог до графики](PRE_ASSET_RESULT.md), [архитектура runtime](RUNTIME_DESIGN.md), [выполненный пакет](PRE_ASSET_IMPLEMENTATION.md).

## Проверки

```bash
npm run lint
npm run v3:typecheck
npm run v3:server:typecheck
npm run v3:test
npm run v3:server:test:pg
npm run v3:build
npm run v3:server:build
npm run v3:assets:check
```

Полный PG runner создаёт временный собственный контейнер, проверяет миграции/rollback/конкурентный доступ и удаляет только его. `v3:server:test` без runner запускает unit и явно пропускает opt-in PG; не считать этот пропуск проверкой БД. `v3:audit` анализирует исходные GDD, `v3:simulate` — предложенный баланс, `v3:tgrep` — отдельный инструмент поиска.

`v3:build` выпускает только клиентские артефакты; `v3:dev`/`v3:preview` на 3002 без API не заменяют `v3:local`. Старый прототип этапа 2 сохранён в исходниках, но больше не является главным entry.

Для будущего Telegram-запуска подготовлен `family-life-v3-telegram.html` с официальным SDK и серверный HMAC verifier. Настоящий бот, HTTPS-host, deployment configuration, реальные семейные данные и WebView-проверка в эту локальную работу не входят. Main, Folio и текущее меню бота не менялись. Сезоны и платежи остаются этапами 6–7 [плана](STAGED_PLAN.md).
