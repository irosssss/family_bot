# V3 — сохраняемый runtime до графики

2026-09-09. Область: отдельная ветка V3, PostgreSQL 18.6 в собственной синтетической БД. Исходный Foundation 3.1 сохранён; новые миграции 0002/0003 дополняют его. Старые migrations не переписаны.

## Граница записи

UI `src/v3/live` → единственный transport → `/v3/api/commands` → raw closed DTO → текущий opaque VerifiedActor → family/actor lock → capability и ресурс → game engine → claims + ledger + document CAS + receipt → commit. Перед повторным возвратом receipt полномочия и принадлежность acting member проверяются заново. ID чужой семьи не превращает объект в разрешённый.

Каждая семья сериализует свои команды одним family row lock. `game_documents.body` содержит агрегат JSONB с definitions/occurrences/parts/attempts/settlements, progress, purchases/pets, goals/orders/corrections/adventures. Это сознательное решение для ограниченного семейного runtime: проще проверить атомарность всего бесплатного цикла. История и объём агрегата растут, чтение/аудит всего документа не рассчитаны на неограниченную многолетнюю нагрузку. Перед production нужны измерения размера/латентности, retention/архив и, при необходимости, разбиение агрегата; сейчас не заявляется готовая масштабируемая production-служба.

Деньги представлены canonical decimal strings, расчёты BigInt; signed ledger и unsigned quantity проверяются до записи. Непрерывная sequence, уникальные cause keys и composite family/player FK — в PostgreSQL. Ledger/claims/receipts не обновляются. Permanent semantic claims отделены от transport receipts: удаление временной квитанции не позволяет начислить одну долю снова. `auditWorld` проверяет сохранение сумм, резервов, ownership и одно активное приключение/цель. Ошибка после debit/ownership откатывает всю транзакцию.

В ответе — свежая projection текущего участника: свой кошелёк/ledger/покупки/питомцы, доступные задачи и детская проверка по grants. Публичный облик — только item IDs выбранной одежды/предмета и вид/стадия спутника; личные покупки, баланс и текст результата другого взрослого не выдаются. Семейные вещи видны всем членам семьи.

## Календарь и начисление

IANA zone, полночь с учётом DST. Материализуется текущий день без исторического backfill. Once/daily/weekly, individual/shared/rotation. Общая работа имеет точные части и бюджет, равный их сумме; нельзя частично открыть бюджет с отсутствующим исполнителем. Роль, сложность, награда, pet target, цель и adventure сохраняются при открытии.

Поздняя отправка по умолчанию 14 дней, настройка 1…90 фиксируется на occurrence. Performed date не будущая и не раньше фактического открытия. Pending review не истекает. Новая timezone применяется после конца текущего периода без перекрытия или повторного открытия уже пройденной даты. Изменение definition действует на будущие работы.

Adult trusted-self сразу создаёт settlement; child submit не начисляет ничего. Accept ребёнка начисляет единственному владельцу доли; проверяющий не получает награду. Return требует причины, новая попытка — явного predecessor `after_return`. Повтор старой отправки возвращает её прежний результат. Отмена не стирает принятые части и не закрывает незавершённую проверку молча.

## Траты, питомцы, общий прогресс

Цены берутся из общего каталога через зарегистрированную серверную policy и revision/hash. Quote на 5 минут фиксирует цену/получателя/предмет; purchase атомарен и permanent ownership не дублируется. Примерка локальна, применение — отдельная проверенная команда. Семейную вещь взрослый покупает за свои монеты с семейным ownership.

После первого принятого дела появляется одно бесплатное право на котёнка либо щенка. XP получает заранее выбранный питомец, новый выбор не меняет старую работу. Вылупление бесплатно от 50 XP; первый рост — 122 XP всего. Companion и получатель XP независимы. Название и тема уголка сохраняются; Milestone роста сохраняется после коррекции XP.

Real offers доступны указанным детям. Quote/request создаёт резерв available; approve сохраняет его. Delivery списывает один раз, UI требует отметки фактического выполнения. Отклонение/разрешённая отмена освобождает резерв без второго денежного прихода. После одобрения ребёнок просит отмену, decline требует явного продолжения; pending cancellation блокирует delivery. Взрослый может отменить с причиной; решения хранятся отдельной историей.

Цель фиксирует состав/нормы/срок расчёта и принимает только привязанный вклад без expiry. Overflow не переносится в следующую цель. Adventure фиксирует roster и target = число участников × норма 13 × plannedDays. Урон приходит из принятых работ; пауза меняет новые привязки, уже открытые работы сохраняют прежние условия. Победа и цель дают по одному постоянному трофею. Повторный просмотр/тап не награждает.

Correction сначала выдаёт серверный preview на 5 минут. Gold: applied=min(original,available), остаток waived без долга. XP/вклад/опыт питомца/урон компенсируются ledger entries. Владение, резерв и milestone не отбираются. Restore возвращает только реально applied и только один раз.

## Вход и устройство

`createV3HttpApp` принимает trusted database/origin/mode/verifier. Local mode разрешает loopback и только явные синтетические устройства; Telegram mode требует HTTPS и `telegramIdentityVerifier(botToken)`. Verifier проверяет HMAC WebAppData, duplicate/decode/JSON boundaries, signed auth_date (300 секунд, future skew 30), bot-scoped subject. Модуль не читает env. Доставку настоящего bot token и prod database adapter нужно отдельно сконфигурировать при выпуске; подстановка local verifier в production недопустима.

`family-life-v3-telegram.html` загружает официальный SDK до main; клиент передаёт только raw initData, сервер его проверяет. `ready/expand` вызываются для Telegram mode. Обычный локальный entry не загружает SDK. Настоящий Telegram WebView, iOS/Android и меню бота ещё не проверялись/не менялись.

PIN 6…12 цифр хранится как scrypt hash с salt. После пяти неверных попыток — пауза 15 минут с сохранением счётчика. Восстановление требует свежую identity proof и одноразовый код, меняет PIN/код и отзывает старые сессии. Непривязанное устройство создаёт семью только при явном enroll; обычный login не создаёт пользователя из-за опечатки.

Сессия — случайный 256-bit token, в БД hash, HttpOnly SameSite=Strict cookie `/v3/api`, Secure при HTTPS, TTL 7 дней. Adult→managed child отзывает старый контекст; возврат требует PIN домашнего взрослого. Приглашённый own child не получает возврат к взрослому. Приглашение 7 дней, роль берётся из member, старое заменяется новым, consume один раз. Для replay код приглашения хранится также в защищённой actor-scoped квитанции: не утверждать, что вообще все секреты существуют только в hash. API не логирует credentials/личный текст.

Host/Origin точные, cross-site denied, мутации требуют JSON + Origin + `X-V3-Request: 1`; raw body до 64 KiB, без CORS. Auth rate limit ограничен в памяти процесса плюс постоянный per-identity PIN lock. Reverse proxy, общий rate limit нескольких узлов и secure deployment headers относятся к конфигурации выпуска.

## Клиент и неизвестный ответ

Команда сохраняет точное тело/ключ в scoped `sessionStorage` до отправки; cookie/PIN туда не пишутся. Пока результат неизвестен, новые записи блокируются, доступен повтор того же запроса. Ошибка 5xx/обрыв/timeout/невалидный JSON считается неизвестным результатом; timeout покрывает тело ответа. Подтверждённый retry обновляет projection и закрывает прежнюю форму, чтобы повторное нажатие не создало новую сущность.

Pending привязан к member; другой профиль не может воспроизвести его. Session re-auth сохраняет неизвестный запрос до возврата в правильный профиль. Revision/epoch не позволяют старому GET затереть более новое состояние или результат смены профиля. Focus/visibility/30 секунд обновляют read model. Browser reload и рестарт HTTP сохраняют данные PostgreSQL.

SessionStorage — вкладка текущего браузера, не долговременная очередь команд между устройствами; серверная semantic uniqueness остаётся отдельной защитой. Ротация auth cookie после полностью потерянного ответа может потребовать повторного входа, который не повторяет игровое начисление.
