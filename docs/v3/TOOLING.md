# Инструменты разработки V3

## tgrep: закреплённый локальный бинарник

Проверено по официальному релизу 2026-09-09: последний стабильный выпуск — **v1.0.5**, опубликован 2026-09-08. Это дополнительный инструмент поиска для разработчика. Установка и запуск не входят в запуск игры. [Релиз v1.0.5](https://github.com/microsoft/tgrep/releases/tag/v1.0.5)

Из корня V3 checkout:

```bash
npm run v3:tgrep:install
npm run --silent v3:tgrep -- --version
```

Установщик выбирает macOS x86_64 или arm64, проверяет закреплённый SHA-256 и кладёт бинарник в игнорируемый `work/v3-tools/tgrep/1.0.5/tgrep`. Wrapper запускает этот бинарник и передаёт аргументы; корень поиска задаётся в каждом вызове. Бинарник и индексы не коммитятся.

Официальные архивы и SHA-256: [assets v1.0.5](https://github.com/microsoft/tgrep/releases/expanded_assets/v1.0.5).

## Разовый и повторный поиск

Для разового поиска и проверки собственных правок первым выбором остаётся `rg`:

```bash
rg -n 'BALANCE_POLICY_V01' src/v3
```

Для повторных запросов можно явно построить индекс **только `src/v3`**:

```bash
npm run --silent v3:tgrep -- index src/v3 --index-path work/v3-tools/tgrep/indexes/src-v3
npm run --silent v3:tgrep -- -n -F --index-path work/v3-tools/tgrep/indexes/src-v3 -- 'BALANCE_POLICY_V01' src/v3
npm run --silent v3:tgrep -- --files --index-path work/v3-tools/tgrep/indexes/src-v3 src/v3
```

Для `docs/v3`, `scripts/v3` или `tests/v3` при необходимости создаётся отдельный индекс с соответствующим корнем и отдельным каталогом `docs-v3`, `scripts-v3` или `tests-v3`. Индекс всего checkout для этого сценария не нужен. Флаги поиска ставятся перед `--`; после него идут шаблон и пути. `-F` ищет буквальную строку. [Руководство для агентов v1.0.5](https://github.com/microsoft/tgrep/blob/v1.0.5/AGENTS.md#searching)

Индекс не обновляется самим поиском. Сразу после правки читать актуальные файлы можно так:

```bash
npm run --silent v3:tgrep -- --no-index -n -F -- 'BALANCE_POLICY_V01' src/v3
npm run --silent v3:tgrep -- --no-index --files src/v3
```

## Необязательный сервер на время работы

Запускается отдельной явной командой в терминале; автоматического старта нет:

```bash
npm run --silent v3:tgrep -- serve src/v3 --index-path work/v3-tools/tgrep/indexes/src-v3
```

Статус из второго терминала:

```bash
npm run --silent v3:tgrep -- status src/v3 --index-path work/v3-tools/tgrep/indexes/src-v3
```

Остановка — **Ctrl+C** в терминале сервера; подкоманды `stop` у tgrep нет. В v1.0.5 сервер слушает `127.0.0.1` на случайном порту; `serve.json` хранит PID и порт, обработчик Ctrl+C удаляет этот файл. Локальные RPC не имеют отдельной аутентификации и возвращают фрагменты исходных файлов выбранного дерева. API-ключ для tgrep не требуется. [Исходник сервера v1.0.5](https://github.com/microsoft/tgrep/blob/v1.0.5/tgrep-cli/src/serve.rs), [команды CLI](https://github.com/microsoft/tgrep/blob/v1.0.5/tgrep-cli/src/main.rs)

## Границы результата поиска

- Холодный `serve` до завершения первой индексации возвращает пустой результат. Возобновляемый неполный индекс может отвечать частично. `Indexing: complete` подтверждает завершение первоначальной сборки, но не синхронизацию с последней правкой. События watcher обрабатываются асинхронно; для проверки отсутствия кода после изменений использовать `rg` или `--no-index`.
- При остановленном сервере локальный индекс остаётся снимком. Перед дальнейшим индексным поиском его нужно пересобрать. Пересборка командой `index` не обновляет уже работающий сервер. [Актуальность индекса](https://github.com/microsoft/tgrep/blob/v1.0.5/AGENTS.md#freshness)
- По умолчанию скрытые и игнорируемые файлы пропускаются, действуют проверки бинарных файлов и лимит **64 MiB**. Поэтому даже `--no-index` не означает поиск абсолютно всех байтов. `.tgrepignore` автоматически не читается. `--exclude` доступен только для `index`/`serve`; одинаковые ограничения индексации должны применяться к обоим. [Флаги и ограничения v1.0.5](https://github.com/microsoft/tgrep/blob/v1.0.5/README.md#file-size-limits)
- `--index-path` передаётся также поиску и `status`. `--ignore-file`, `--follow` и `--one-file-system` действуют только при полном сканировании; для них требуется `--no-index`. Не добавлять расширяющие область флаги `--hidden`, `--no-ignore` или `-u` по умолчанию. [Согласование параметров](https://github.com/microsoft/tgrep/blob/v1.0.5/AGENTS.md#keep-index-serve-and-search-flags-aligned)
- Код завершения `0` означает совпадение, `1` — отсутствие совпадений в выбранной области, `2` — ошибку. Сохранять stderr: сообщение о fallback или незавершённой работе нельзя превращать в доказательство отсутствия кода. [Коды завершения](https://github.com/microsoft/tgrep/blob/v1.0.5/README.md#exit-codes)

Игровой код V3 не импортирует tgrep. Проверка поиском не заменяет lint, тесты и браузерный QA.

## Проверка подключения — 2026-09-09

На этом Mac установлен x86_64 релиз 1.0.5; SHA-256 совпал, повторный запуск локального установщика прошёл. `rg`, полный проход tgrep и индексный поиск `BALANCE_POLICY_V01` дали одинаковые 22 строки. Отрицательный запрос вернул код 1. Индекс содержит 18 файлов `src/v3`.

Серверный smoke: `Indexing: complete`, watcher active, поиск через loopback нашёл 4 файла и помечен `via server`. После проверки процесс остановлен Ctrl+C, `serve.json` удалён. Сервер не оставлен в фоне; повторный запуск только явной командой выше. В sandbox открытие сокета было недоступно, проверка выполнена с разрешённым локальным сетевым доступом.

`node --check scripts/v3/tgrep.mjs` и `npm run lint` прошли. Доказательства — локальный игнорируемый `work/v3-tools/tgrep/smoke.json`; бинарник/архив/индекс находятся там же. Это smoke интеграции, а не доказательство ускорения маленького V3-каталога.
