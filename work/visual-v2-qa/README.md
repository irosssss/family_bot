## Найденный и повторно проверенный дефект

`battle-375.png`: `.demo-world-v2 .demo-arena-party span` из adventure-v2.css применял фон/padding к корневомуspan Character, создавая тёмные прямоугольники за героями. Автор Adventure добавил отдельный `.demo-world-party-name` только для подписи.

После обычной перезагрузки страницы: `battle-375-corrected.png`; два name labels, оба `.demo-character` имеют computed background rgba(0,0,0,0), padding0px, missing0. Лишние прямоугольники исчезли. Старый файл оставлен только как before-evidence, не как текущая версия.

Последующая проверка координатора выявила отдельный дефект самого арта: белая непрозрачная область внутри дуги starter/rare лука остаётся и после CSS-исправления. Четыре imagegen-кандидата отклонены из-за отсутствия настоящего alpha и смещения силуэта; runtime не заменён. Этот остаток не считается закрытым данным браузерным проходом; подробности в `../visual-v2-bow-fix/README.md`.

## Follow-up: keyboard/focus и console карточки босса

2026-09-05, свежая штатная CUA tab4. Tab3 автоматически закрылась после предыдущего turn; выбран тот же browser1, создана новая вкладка без перезапуска сервера. Использовались документированные `PlaywrightLocator.press`, `Tab.pressKey`, read-only DOM и `Tab.dev.logs`.

Карточка текущего босса открыта клавишей Enter:

1. Начальный фокус — контейнер `[role=dialog]`, внутри открытого окна.
2. Tab → «Закрыть»; Tab → «Вернуться»; Tab → «Закрыть» (цикл замкнулся).
3. Shift+Tab → «Вернуться»; Shift+Tab → «Закрыть». На каждом шаге activeElement оставался внутри диалога.
4. Escape → диалог удалён (count0), фокус возвращён именно на исходную первую `button.demo-world-boss-card` («Прокрастинация»), а не на body или другой элемент.

Документированный `qaTab.dev.logs({levels:['warn','error'],limit:30})` вернул одну ошибку текущей вкладки: `[vite] failed to connect to websocket (Error: WebSocket closed without opened.).` Источник `http://localhost:3000/@vite/client`, timestamp2026-09-04T23:27:44.098Z. Это HMR WebSocket; интерфейс/HTTP и проверка клавиатуры продолжали работать. Других warn/error в возвращённом журнале текущей вкладки не было. Этот факт не является полным аудитом прежних вкладок или всех экранов.

Никаких игровых действий/сохранений в follow-up не выполнялось. Отдельная доработка прозрачности луков, выполняемая автором ассетов, этим тестом не оценивалась.
